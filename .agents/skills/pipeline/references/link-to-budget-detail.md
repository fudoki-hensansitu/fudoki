# 資料の施策を予算書の内訳（事業）に紐付ける

自治体ページに出す施策（予算案のプレス発表の1頁1施策など）に分野を付けるときは、施策を予算書の内訳の1行へ紐付け、その行の目の COFOG を使う。紐付け自体（内訳の `detail_id`）もデータに残す。分野だけでなく紐付けを持つと、あとで構造化したときに事業から施策・評価・公約を引ける。

## 手順

1. **名前と額で直接当たるものを先に確定する。** 正規化（NFKC、空白・括弧・記号・末尾の【課名】を除く）した名前が一致するもの、または部分一致かつ予算額が円まで一致するもの。
2. **残りは候補を12件出す。** 施策名と内訳名を `Intl.Segmenter('ja', { granularity: 'word' })` で単語に分け、どの行にも付く語（事業・経費・推進・支援・運営・整備・管理など）、助詞、1文字の平仮名を外す。単語の Dice 係数（2×共通語数÷両方の語数の合計）で、同じ自治体・年度・当初予算の `fiscal_expenditure_detail`（`breakdown='事業'`、全深さ）から上位12件を取る。
3. **TypeSafe の Jev に選ばせる。** `POST https://api.typesafe.ai/v1/systemone`、`model: jev-latest`、`choice` の質問1つ。state は施策の見出し・事業名・予算額・要点。criteria は候補ごとに「予算書の内訳『名前』（款・目）」と、`none`「この施策を含む内訳は上のどれでもない」。
4. **確信度 0.6 以上なら採用する。** その行の `detail_id` と目の COFOG を持つ。0.6 未満と `none` は紐付け無しにして、分野は「その他」に入れる。名前からの推測で分野を決めない（根拠が予算書の行に無いものは分けない）。

紐付けは取り込みのときに一度作ってデータとして置く。画面を開くたびに Jev を呼ばない。予算案のプレス発表の施策は `bun run --cwd pipeline evaluation:link-press`（`pipeline/ingestion/evaluation/link_press.py`）がこの手順で紐付け、seed `pipeline/dbt/seeds/evaluation/press_item_link.csv` に足す。seed に行がある施策は聞き直さない。

## なぜこの形か（品川 R8/R7、名前と額で直接当たらなかった51頁での比較）

| 方法 | 正しく決まった数（R8/R7） | 弱点 |
| --- | --- | --- |
| 文字 bigram の Dice | 4/16 | 言い換えに弱い。額の加点は無関係な同額の行も持ち上げる |
| e5 ベクトル（0.90 以上） | 3/12 | 短文どうしは点が 0.83〜0.94 に詰まり、境目が曖昧 |
| 単語の Dice（Intl.Segmenter） | 6/20 | 予算書に施策名の行が無い年度（R8）で取りこぼす |
| 候補12件 → Jev（0.6 以上） | 13/22 | 0.6 以上は全部正解。外れは低い確信度で出る |

- 款別予算の資料などを間に挟むと拾える件数は増えるが、資料が1つ増えるだけ手間なので挟まない（2026-11-07 yuito）。
- 全行を Jev に見せる案は、`choice` の選択肢が255個までなので目しか選べず、似た目の取り違えが高い確信度で出た（里親→子ども育成費 0.96 など）。事業への紐付けも残らない。
- Sudachi の正規化表記（`normalized_form`）は「紙おむつ」を「紙御襁褓」にするなど表記を変えるので使わない。文中の書き方のまま比べる。
- 候補を単語の Dice だけで出しても、Jev が 0.6 以上で選んだ正解はすべて上位12件に入っていた。

## 料金・鍵

- Jev は入力 $0.042 / 100万トークン、出力は無料。候補方式は1件約1,000トークン。
- 鍵は `TYPESAFE_API_KEY`（クラウド環境に登録済み）。API の書き方は dotfiles の `typesafe-ai` skill と https://docs.typesafe.ai/llms.txt を見る。
