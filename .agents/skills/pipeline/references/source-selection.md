# A. source_selection — 取り込む1資料を確定する

原典を確認し、対象に必要な情報を持つ1資料を選定する。原典をアップロードしたら完了する。

## 続きから調査するときの優先順

- 最初に自治体の選定ファイルを年度・資料区分・選定／保存状態・会計と向きで集計し、公式掲載一覧との差分を調査対象にする。台帳の全候補や補正号を順番に読み直さない。年度の選定件数だけで全会計の確認済みとは判断せず、企業会計などの別冊・別掲載先も照合する。
- 保存済みで範囲を確認した資料は、差し替え・不足の手掛かりがなければ再取得・再検査しない。同じ年度の別会計や必要な分冊が欠けている場合は、該当箇所だけ追加確認する。会計の構成は年度で変わりうるため、別年度との違いだけで不足とは判断しない。
- 確認した予算書・決算書の範囲が要件を満たし、新たな不足の手掛かりがなければ、同じ対象の概要や別形式を全部取得して不採用理由を作らない。追加候補は、既存の選定で補えない会計・事業・版などがある場合にその箇所だけ確認する。
- 歳出が最優先なら、当初予算・決算の歳出を会計別に選定して保存することを先に終える。歳入の境界確認や補正号の整理を先行しない。同じ原典に歳入が載っていても、未確認の歳入範囲を確認済みとして宣言しない。複数自治体を扱うときは、指定された年度範囲の最新分から進め、自治体ごとの結果を保存して監督側へ返す。次の自治体は短い作業指示と確認済みの事実だけを引き継ぎ、前の自治体の大量の本文・画像を読み直さない。
- 複数自治体で当初予算・決算を最優先と指定された場合は、全体の担当待ち一覧でもその順序を保つ。優先対象の選定・保存と不足の記録が終わった担当を、補正の多数の候補確認だけで占有し続けない。未選定の補正候補は年度・号数・公式URL・取得済み原典と確認結果・残作業を短く引き継ぐ。優先対象の未着手分がなく、残る担当に必要な実行枠が確保されているなら、空いた枠で優先対象を終えた自治体の既知補正候補を進められる。同じ自治体の担当を重ねず、選定した資料の保存は担当を区切る前に終える。
- 一部の会計だけ最新年度の原典が公開されている場合も、要件を満たす確認済み原典はその年度で選定・保存し、未確認・未掲載の会計は不足として記録する。他の会計が未掲載という理由で、取得できる歳出明細まで未選定にしない（主な会計の一般会計が未公表のときは次項）。「最新分」は会計ごとに判断し、一般会計が2025年度・企業会計が2024年度まで公開されているなら、その2024年度の企業会計も最新分として選定する。会計ごとの最新掲載年度が違う場合は、その差を理由に残す。
- その年度・資料区分の主な会計（一般会計）が**未公表**なら、公営企業会計などの一部の資料だけで選定しない。`selected_candidate_id: null`・`archive: null` とし、理由の先頭に「未公表（確認した頁・日時）」を書く。理由にだけ未公表と書いて選定済みにすると、機械からは完了に見え、取り込みの検査で「一般会計の scope が無い」と誤読され、公表後の選び直しの対象にも入らない。null にした対象は「公表され次第選ぶ」列に入る。確認済みの一部の資料は候補に残し、保存済みの R2 の object は消さない。対象は公表前に限る。公表済みで取得できない、款・項のみで不採用、団体が公開せず都の調査資料などで部分選定した、会計別の号数で特別会計だけの補正号は「未公表」と書かず、下の部分選定の規則で扱う。取り込み済みの対象は管理 JSON を直すまで暫定で選定を残し、理由に「一般会計は未公表。暫定で選定し取り込み済み。公表後に全会計で選び直す」と書く。
  例: 福生市の2025年度決算は下水道事業会計の決算書だけが公表され、決算一覧（`finances/kessan/index.html`）に一般会計が無く最新は令和6年度だった。下水道だけを選定せず、null・理由「未公表（決算一覧、2026-10-13確認）」とした。
- 一部事業の資料も、事業名と対象年度の予算額・実際の支出額が同じ明細で対応するなら、その範囲を選定し、他の歳出の不足を記録できる。「概要」という題名や全歳出を網羅しないことだけで除外しない。ただし財源の充当額、複数年の総事業費、款・項だけの総額を事業の予算額・決算額に読み替えない。
- 補正資料は事業名・歳出科目と補正額（増減額）が対応する部分も選定できる。補正前・補正額・補正後の3額がそろうことを必須にしない。補正差額を補正後の予算額と読み替えず、原典の金額列名・単位と、基準額や他会計の不足を理由に残す。
- 債務負担行為の限度額や繰越明許費の繰越枠は、当年度の歳出補正額とは区別する。これらだけを変更する号は、款別総括に補正額0が載っていても事業別の歳出補正明細として選定しない。独立した調書頁は歳出のscopeから除き、補正明細と同じ物理頁に載る場合は対象の列と非加算の関係を理由に記録する。
- 一般会計を含まない補正でも、実施順から架空の号数を付けない。原典の会計別号数を根拠に対象へ対応付け、同じキーに別の実施日の冊をまとめる場合は会計・実施日・号数を区別して記録する。対象を組み直すときは確認済み原典を失わず、分冊と保存キーの整合も再検査する。
- 原典が万円などで丸めた額を示していても、その金額が対象年度・事業の予算額や補正額と確認できるなら、表示単位・丸めの注記を保持して部分選定できる。円単位の精度や款項目コードがないことだけで除外せず、正確な円額へ復元したり推定したりしない。金額の意味が不明なら未確認として残す。
- 会計名が原典に無い部分資料は、範囲に「会計未記載」と原典の表題を記し、会計名を推定しない。固定資産の当年度増加額や企業債残高も、支出額と確認できない限り歳出範囲へ加えない。
- 当初予算への修正資料は、対象年度と当初予算の候補との関係を確認する。補正号数がないことだけで対象不明の候補にしない。同じ公式掲載先の説明と修正箇所から、修正の成立・撤回等の扱いと既存冊への反映を確かめる。成立した修正が既存冊に未反映なら必要な修正冊も同じ選定対象へ含め、原案額・修正額・差額と再掲部分の扱いを記録する。扱いが未確認なら版の不足を残し、原案の印刷額を無断で訂正しない。
- 同じ年度の複数資料を併せて選定するときは、主要事業の概要と事務事業評価などの間で同一事業が重複する場合がある。併用で補う範囲を区別し、少数の代表明細で名称・所管・年度・金額列を照合する。確認できた重複は資料・物理頁・単位・差額と二重集計を避ける扱いを理由に記し、未確認の残りまで突合済みとしない。頁単位で除けない重複のために全事業の抽出へ進まない。
- 合計の一致は補助検査であり、金額列の意味・年度・会計や補正号数の対応をそれだけで確定しない。不一致は差額と未確認の原因を記録し、端数や転記と推定して一致扱いにしない。
- ユーザーが優先する資料区分の選定・保存と不足の記録を先に区切る。補正を「見つかれば選定」と指定された場合は、同じ公式掲載先で見つかった候補を扱い、見つからなければ確認したURL・年度範囲を残して止める。概要資料が多数並ぶ場合は、掲載説明と判断に必要な実物から明細の有無を確かめてから取得対象を決め、全号のダウンロードを先行しない。一部の実物確認を全号の本文確認済みとは記録しない。既知の404やURL推測の連続試行は、新たな掲載リンクなどの手掛かりが得られた場合に再開する。
- 監督付きの作業では、最初の掲載一覧と既存記録の照合後に、追加確認する対象・残る不足・時間のかかる操作を報告する。別の資料へ進む前や一括取得の開始前に、orchestration の未読指示を確認し、優先順の変更を反映する。長引くときは失敗した取得や探索を繰り返す前に監督側へ相談し、選定できた対象は保存まで進める。
- 同じ自治体でも本文・画像が会話に積み上がって作業が長引く場合は、確認済みのURL・取得先・年度・会計・金額列の意味・単位・物理頁範囲と残る不足を担当メモにまとめ、会話を要約して続ける。取得済み原典とその確認結果を再利用し、一覧探索や全冊確認からやり直さない。
- 担当やharnessを交代するときは、監督側が取得済み原典の場所・台帳へ反映した判断・保存状態・残作業を短く渡す。引継ぎ先は台帳と担当メモから始める。起動・停止・release等の制御記録には原典の確認結果が無いため、資料確認の経緯を探す目的で読み続けない。旧会話の表示末尾だけで経緯が分からない場合も、既存判断を全冊の再確認で置き換えず、具体的な不足を監督側へ照会する。
- 作業時間は開始・完了の実時計の差で求める。監督付きならdispatchの開始と完了記録を照合し、体感や完了見込みを実測の所要時間として報告しない。 報告書の完了時刻は`date -u +%Y-%m-%dT%H:%M:%SZ`等の実行結果を使い、TUIの経過表示や予定時刻で埋めない。
- 並行調査は自治体ごとに編集担当を一人に固定し、一時資料も自治体別の場所へ置く。型・記録形式はschemaと担当自治体の既存記録から確認し、雛形探しのために他自治体の台帳を読み比べない。ダウンロード・描画の出力先は担当ディレクトリの絶対パスで指定する。`cd ... && command &` のような背景実行で親の作業ディレクトリまで変わったと考えず、repo rootや他担当の一時領域へ書かない。共有の進捗一覧は監督側が直列で更新する。複数の補助プロセスが同じ一覧を更新する場合は、読み取りから書き戻しまでをロックし、原子的なファイル置換だけで更新の取りこぼしを防げるとは考えない。

## 選定の手順

1. [schema.ts](../../../../pipeline/source_selection/schema.ts) を読み、指定された自治体・年度・資料区分のレコードを取り出す。
2. 公式HPまたは公式オープンデータの対象年度の掲載情報から資料を選ぶ。その範囲で選べるなら探索を広げない。該当資料がない場合だけ別の掲載先を探し、探索した範囲と残る不足を記録する。候補未発見や取得失敗だけで公開資料なしとは判断しない。リンク切れ資料の代替を web アーカイブに求めるときは、国立国会図書館のウェブアーカイブに館内限定の資料があり、外部から取得できるとは限らないことを踏まえる。
   調査対象の指定は、その資料の公開・存在や選定可能性を保証しない。選定できるはずだという推測から同じ一覧や検索を繰り返さず、具体的な候補と実物の不足を確認して探索を区切る。確認済みの範囲を理由に残した未選定も、この工程の結果として扱う。
   公式ページと原典URLが同じアクセスエラーになる場合は、既存の取得手段・ブラウザ等で必要な切り分けをしたら取得不能の根拠を残す。別ホスト・プロキシ・アーカイブサービスを順番に試し続けない。古い掲載一覧の保存版は候補発見の手掛かりであり、現時点の最新年度・未掲載・議会認定を確定する根拠にはしない。実物未取得のPDFを文字PDF等と仮定して登録せず、分類を記録できない候補URLは未選定理由に保持する。公開資料なしの判断は掲載一覧の最新年度・監査意見など複数の根拠で行い、推測で置いたURLの404を根拠にしない。対象年度が未公表なら最新の公表年度を対象にし、未公表の根拠を理由に残す。法定の決算書が無ければ、同じ粒度の明細を持つ別の刊行物も候補にする。
   公式原典の保存版PDFを取得済みなら、現行URLの404と実物の不在を区別する。既知の保存版掲載リンクと取得URL・保存日時・SHAが対応し、実物で対象年度・会計・金額と範囲を確認できる場合は、その取得可能な保存版を候補として扱える。元の自治体公式URLと保存版を使った理由を残し、取得URLは実際に取得したURLを記録する。保存版を元URLから現時点で取得できたものとして記録しない。
   現行URLの404は**改名**（現行の掲載一覧に別名の同内容ファイルがある。府中市 132063 は現行の `...administrative_evaluation.pdf` が旧URLの全28ファイルと sha256 一致）と**廃止**（現行の一覧に該当年が無い。千代田区 131016・狛江市 132195・多摩市 132241 の2020〜2021年度）に分かれる。curl の404だけで取得不能と確定せず、現行一覧に該当年度のファイルがあるかを先に見る。自治体の自前404ページは本文が `text/html` なので、応答の中身でも見分けられる。
   Wayback Machine は `.../web/<ts>id_/<url>` の形が原本のバイト列を返すため、取得物の sha256 検証に使える。ただし `id_` 無しの URL は書き換えが入り、保存が約1MiBで切れることや `Temporarily Offline` もあるので配信先としては不安定。**R2 に保存したコピーを正とし、Wayback の取得URLは出典として reason に残す。**
3. 対象を年度・資料区分ごとにまとめ、掲載情報で候補を絞ってから実物を確認する。掲載一覧は年度・資料区分で絞り、必要なリンク名とURLだけ取り出す。HTMLやカタログの全件を端末へ出さない。同じURLの確認結果を共有し、候補全件を先行取得しない。CSVが単独で要件を満たせばPDFの追加取得は不要。掲載説明だけで不足が明確な補助・総括資料も取得しない。内容が分からない競合は該当箇所を確認する。取得していない資料の内容・版を断定しない。
4. CSVは掲載一覧・ファイル名・会計列から収録されている会計を確認する。会計別ファイルがあれば掲載一覧を照合し、既知の会計だけで確認を終えない。文字コードを確認して`csv.DictReader`等で列名と値を対応付ける。日本語CSVではUTF-8／UTF-8 BOMとCP932を確認し、デコード失敗を無視しない。款・項・目名がコードや仮の値だけになっていないか、必要な金額と単位を確認する。目・細目を取り違えず、行数はヘッダを除いて数える。
5. PDFは下記の方法で目次から全会計と分冊を把握し、必要な表・取り込み範囲を確認する。目・事業・節が別々に存在することと、同じ明細で対応することを区別する。必要な条件と先頭・末尾を確認したら止め、OCRや全明細の抽出に進まない。
6. 条件を満たす候補から1資料を選び、理由を記録する。同じ内容・版ならCSV、文字PDF、画像PDFの順を基本にする。同じ対象範囲を単独の資料で覆えるなら、分冊や会計・歳入・歳出別ファイルの組み合わせより優先する。選べなければ不足と探索済みの範囲を残す。分冊は目次・掲載一覧にある会計を覆う必要な冊を一つの候補にまとめる。会計別冊も含め、各冊の会計・歳入／歳出の取り込み範囲を確認する。明細を確認できない会計があれば、その会計名と不足を理由に残す。理由は「対象外」「明細なし」といった分類だけで書かず、確認した表構成・列名・金額の段階・頁を具体的に残す。理由に記した重複や対象外の頁は取り込み範囲にも反映させる。CSVとPDFの突合が必要な場合は、単独資料で代替できない理由をユーザーへ伝える。
7. 選定後は代表候補だけ残す。選び直しや分冊の変更時は、理由に記した資料構成・対象範囲も現在の選定と一致させる。未選定の対象も、重複・対象不一致・本文で必要情報の不足を確認した候補を除き、不足は理由に残す。既存の対象にない会計という理由だけで候補を除かない。選定情報を更新し、下記のコマンドで検査・保存する。対象未確定の候補も自治体の選定ファイル内で管理し、確認できたら選定対象へ移す。会計名は原典の表記を保持し、一般会計への置き換えや既知の会計だけへの絞り込みをしない。

## オープンデータの入口

[東京都オープンデータカタログ](https://catalog.data.metro.tokyo.lg.jp/)で対象自治体・年度の財政資料を確認する。公式HPから案内される自治体独自の掲載先も使う。APIを使う場合は、このカタログの`/api/3/action/package_search`に`q`を渡す。紹介ポータルのURLにAPIパスを付けたり、未確認の組織IDや空の`fq`を指定したりしない。

検索は自治体名と資料区分で絞り、`success`・総件数・取得件数を確認する。結果の一部だけを見て候補なしとは判断しない。

自治体公式のリンク集・索引は誤記や対象外のリンクを含むことがある。団体の掲載先は団体マスタ（`packages/jurisdictions/jurisdictions.json`）の名称と照合して採用する。

東京都の市町村公営企業決算状況調査など、複数団体を載せる公式冊子は、資料名や総括表だけで明細なしと判断しない。目次から費用構成・資本的収支の科目内訳を少数頁で確認する。対象団体列だけを選定し、事業種別と計の重複、他団体・総計・収入・繰越等の行を対象外として理由に残す。費用科目の内訳を自治体の款項目の全明細と同一視せず、原典の粒度と不足を記録する。同じ冊子を並列担当で確認するときは取得済みファイルと判明した表・物理頁を読み取り専用で共有し、年度・団体列・表境界を各担当が実物で確認する。単位は表内の表示と冊子の凡例、税は該当する定義・注記を根拠にし、法適用・法非適用や本文・表など定義の適用範囲を確認して他区分へ拡張しない。数値規模から推定しない。

## PDFの確認方法

まず既存のPoppler CLIを使う。依存ライブラリを追加しながら抽出方法を試し続けない。

```bash
pdfinfo FILE
pdftotext -f N -l N -layout FILE -
pdffonts FILE
pdfimages -list FILE
```

本文を探す前に目次を読み、載っている会計名をすべて記録する。一般会計・定番の特別会計だけで終えず、独自の特別会計や事業会計も原典の名称で拾う。企業会計の費用明細や資本的支出明細も、原典の科目・事業名と金額が同じ明細で対応するかを確認する。款・項・目という見出しの有無や会計様式だけで除外しない。資本的支出明細が独立していない冊子では、事業報告書の工事・事業明細も少数頁で確認する。「附属書類」という位置付けだけで除外せず、当年度の実際支出との対応で判断し、工事費・契約額・固定資産増加額を支出済額と推定しない。会計ごとの資料がそろっていても、資本的支出が款・項集計だけなら明細不足を記録する。費用・決算額・支出額を同じ意味へ置き換えず、原典の金額列名・単位・税の扱いを理由に保持する。全体の目次が別冊なら先に確認し、会計と各分冊・頁範囲を対応付ける。同じファイルに複数会計や歳入・歳出が載る場合は、ファイルを重複取得せず、それぞれの範囲を確認する。

目次を見つけるために全頁の文字抽出を先行しない。表紙直後や同種の既存資料で分かる位置から必要頁だけを確認する。画像化は最初から表の名称・列見出し・頁番号を読める解像度にし、低解像度で読めず同じ頁を描き直す往復を避ける。

同じ自治体の既存資料で目次の位置が分かる場合は、その頁を探索の起点にする。年度が違う資料の頁番号や境界はそのまま流用しない。分冊なら同じ資料群の「表紙・目次」別冊も確認する。目次の印字頁と対象PDFの物理頁を対応付け、表紙・欠頁・空白頁によるずれを先頭と末尾で確認する。目次が会計の範囲だけを示す場合は、その区間内で歳入／歳出の順序を確かめ、中間の1頁ずつで区間を半分に絞り、最後に境界前後を確認する。
scopeにはPDFの物理頁を使う。印字頁のずれが冊子内で変わっても、全冊のオフセットを復元する必要はない。描画ファイル名と指定した物理頁を対応付け、必要な境界の表題・金額側を単頁で確認する。小さな合成画像のラベルや印字頁の解釈が曖昧なら、合成・切り抜き・低解像度での描き直しを繰り返さず、その物理頁を読める解像度で直接表示する。

文字抽出結果が必要な複数頁にまたがる場合は、原典ごとに一度抽出して改頁で物理頁に対応付け、必要な見出しと境界だけを参照する。取得済みの文字抽出結果を再利用し、全頁を個別の外部コマンドで順に抽出し直さない。

目次と文字抽出の頁対応が食い違い、表題の抽出漏れや空白頁で境界を決められない場合は、疑わしい少数頁を描画して表示上の表題・最後の明細・金額側を確認する。同じ頁について可能性を並べたり、頁ずれの推測を繰り返したりしない。確定した会計・金額列・単位・物理範囲は担当メモへ残し、次は未確定の境界だけを扱う。給与費明細書や実質収支調書の全頁を分類する必要はない。

一括版と分割版が同じ内容なら、必要な範囲を確認・保存しやすい方を選ぶ。分割版は境界で同じ頁・明細を重ねて収録していることがあるため、対象範囲から重複を除く。頁単位の範囲で他の必要明細と同居し、重複だけを除けない場合は、その分冊・頁と重複の存在を理由に残し、後工程で別明細として二重計上させない。重複の突合が長引く場合は一括版への選び直しも検討する。給与費明細書・調書等が続く冊は、歳出の事項別明細の終端と区別して範囲を記録する。企業会計の冊子も、費用・資本的支出の明細と、キャッシュ・フロー計算書・貸借対照表・注記等を区別し、財務諸表区間全体を歳出明細の範囲にしない。目次から分かる所在と、実際の科目名・金額列の確認を区別する。

文字が読めれば画像化しない。文字化け・空の場合は必要頁を表示して確認する。 ToUnicode未対応の文字や数字を独自に復号する手法の開発を、この選定工程で始めない。必要な名称・金額列・境界の少数頁を描画し、確認した範囲から選定・保存を進める。PDFを直接表示できるツールがあればそれを使い、画像入力が必要なツールでは実際に見る頁だけ描画する。全冊や近隣の数頁をまとめて描画せず、取得・描画済みの資料を再利用する。 表示した画像が指定ファイル・頁と一致しない場合は、読取結果を実物確認の根拠にしない。新しい色・ラベル・nonce付き画像や画像合成ツールを作って読み直し続けず、原典のSHA、物理頁、描画ファイルの絶対path、未確認の表題・金額列・境界を担当メモに残して監督側へ渡す。監督側が独立確認して返した根拠は同じ資料の再検査をせず利用し、その他の確定済み対象は保存まで進める。 画像確認が止まった冊がある場合も、確認済みの冊だけで要件を満たすなら対象を部分選定して保存し、未確認冊は選定したfilesに混ぜない。未確認冊のために担当全体を待機させず、取得済み原典と不足の頁を追加確認の担当へ引き継ぐ。

```bash
pdftoppm -cropbox -f N -l N -r 120 -png FILE PREFIX
```

見開きに名称と金額が分かれる表は、同じ明細に対応する左右両頁を対で確認し、両方の物理頁を取り込み範囲に含める。左頁が予算現額・節内訳、右頁が支出済額等という配置もある。金額の意味は両頁の列見出しから読み、「計」や節の合計との一致だけで支出済額・予算現額のどちらとも決めない。目別の支出済額がないと判断する前に、対応する右頁の金額列まで確認する。それでも支出済額の列を持たず予算現額だけの決算明細書もある。文字抽出できないPDFには輪郭線描画もあるため、画像スキャンと断定しない。文字として読めない範囲は画像を読む手順で確認する。

物理頁の文字抽出や描画が同一でも、頁の重複とは限らない。見開き全体の文字層・MediaBoxを共有し、CropBoxと回転で左右を別頁として表示するPDFがある。`pdfinfo -f N -l M -box FILE`で確認し、表示範囲の検査には`pdftoppm -cropbox`を使う。既定のMediaBox描画が一致することだけで重複を除いたり、最終明細の金額側の頁を範囲外にしたりしない。

単位は金額列ごとに確認する。表全体が「円」でも、当初予算額・補正予算額の列だけ「千円」とする例がある。例外の見出しがかかる列を確かめ、款・項・目の行全体や、支出済額まで同じ単位と扱わない。単位や金額の意味を近隣年度の規模から類推しない。

評価資料（`evaluation_selections`）の対象年度は、資料の題でなく、評価シートに印字された事業費・決算額・決算見込額などの年度列で決める。「令和N年度事務事業評価」は評価した年度（= 令和(N-1)年度の決算）を指すので、題や掲載一覧の文言で判定すると1年ずれる（2026-10-14 に西東京市 132292 で実測）。複数年度の列があるときは評価の対象になる年度の列を特定し、その額が決算見込（推計）でもその列を採る（最新の確定決算へ寄せない）。選んだ列の見出しと値、決算見込などの注記を `reason` に写す。

pdf_type は取り込み範囲の各頁の読取方法で判断し、表紙・目次や一部の頁の体裁で断定しない。schema の `scan` は画像として読む必要があることを表し、原典の作成方式が画像スキャンであることを意味しない。選定範囲に ToUnicode 欠損の文字化けや輪郭線描画があり画像を読む必要があれば、画像 XObject がなくても `scan` とし、読めない頁を reason に記録する。画像スキャンという作成方式を確認する場合は `pdfimages -list` を起点に画像の寸法と頁面積に対する覆域を見て、迷う場合は対象頁を描画して確かめる。ロゴや図表の画像だけで原典全体を画像スキャンと断定しない。

## 検査・保存

確認日時は`datetime.now(timezone.utc).isoformat()`等で実時計から取得する。台帳はJSONとして読み、対象のオブジェクトを更新する。文字列置換で隣の対象を巻き込まない。一時ファイルを書いてから置換し、並行作業中も途中のJSONを読ませない。編集前後を`json.loads`で比較して、意図した対象以外を変えていないことを確認する。台帳全体を端末へ出さない。

```bash
mise x -- bun pipeline/source_selection/check.ts
mise x -- bun pipeline/source_selection/archive.ts
mise x -- bun pipeline/source_selection/archive.ts --write --jurisdiction 132047
mise x -- bun pipeline/source_selection/archive.ts --evaluation --write --jurisdiction 131172   # evaluation_selections だけを evaluation-settlement の key へ
```

評価資料の索引は、保存後に `bun run --cwd pipeline evaluation:index`（計画の表示）→ `--write`（sandbox の外）で AI Search へ頁ごとに登録し、`bun run --cwd pipeline serving:evaluation-catalog` で Worker の一覧を書き直す。item の key は `<原典のsha256>_p<物理頁4桁>.pdf`。`cf ai-search items upload` は key を `--file` の basename にするので `/` では区切れない。metadata の number（`page`）は文字列の数字で送る（number のままだと `invalid_metadata_format`）。`items list` は 1 回 50 件まで。選定の sha256 や pages を変えたら、`--write` を回すまで catalog から外れる（指紋が合わない）。取り込みは1時間に数百頁なので、数千頁を足すときは `--timeout-minutes` を数百分にして background で回す（期限切れや `items list` の `fetch failed` で止まっても、同じ計画の再実行は登録済みを飛ばす）。`running` のまま数十分進まない item は再実行でも登録し直されないので、その key だけ同じ metadata で `items upload` し直す。

コマンドの終了コードを直接確認する。出力を grep や tail へパイプすると終了コードはパイプ末尾のものになるため、検査・保存コマンドはパイプに通さず実行する。通過後は変更や未解決の問題がなければ繰り返さない。必要な実物確認・範囲の記録・保存を終えたら、報告で担当を区切る。補足のためだけに全頁の回転・用紙サイズ・対象外の調書を分類し始めない。選定内容に具体的な矛盾が見つかった場合は、その箇所の修正と必要な再検査に絞る。

並行作業中、他自治体の更新途中のスキーマ不備で全体検査が失敗したら、他担当のファイルを修正したり、待機と全体検査を繰り返したりしない。自分の台帳だけを担当一時ディレクトリへコピーし、`checkSelections(directory)` をそのディレクトリで実行して同じ構造・保存計画検査を通す（`check.ts` の関数はディレクトリを受け取るがCLIは引数を受け取らない）。担当結果と他自治体の失敗を区別して報告し、全担当の更新後に監督側が全体検査を行う。selectionを追加するときは、スキーマで必須の`archive: null`も含めてから原子的に置き換える。

`checkSelections`は非同期なので`await`する。返却値は検査済みの団体集計の配列で、失敗時は例外が出る。Promiseを文字列化した`{}`や未定義の`result.ok`を検査結果とせず、コマンド本体の終了コードを確認する。repo rootから担当コピーを検査する最小の例:

```bash
mise x -- bun -e 'import {checkSelections} from "./pipeline/source_selection/check.ts"; console.log(JSON.stringify(await checkSelections(process.argv[1])))' /absolute/path/to/own-check-dir
```
