# B. ingestion

渡されたCSV/PDFから、印字された値・単位・粒度を保持した取り込みParquetを作る。抽出の説明は歳出を対象とする。管理・保存CLIは歳入と歳出を方向別に扱い、既存の歳入表も移行できる。取り込み方法は **CSV・text PDF・scan PDF** の形式に応じて選ぶ。PDF内でも頁・領域ごとに文字層の利用可否を判断する。

この文書は書き直した取り込み方針であり、現行の抽出器や登録方式を前提にしない。セル検出・欠落領域の自動再実行を含め、ここに書いたフロー全体が実装済みという意味ではない。

## 入力・出力と共通原則

- 入力はAの選定・保存記録と、保存済み出典に対応するローカルCSV/PDF、対象範囲と未確認事項。入力の型は [source_selection/schema.ts](../../../../pipeline/source_selection/schema.ts) を正本とする。出典の取得・探索、これらの情報の判定・管理は上流の責務とし、Bでは受け取った情報との対応を保持する。出典のバイト列は変えず、SHA-256で対応を確認する。
- 出典の文字列、金額の桁区切り・符号・単位を保持する。カンマ除去、数値型への変換、円への換算、名称の統一は後段で行う。
- 取り込みはraw層であり、対象の管理情報を財政データ列として追加しない。自治体コード・西暦年度・資料区分・歳入／歳出の共通コード・共通の粒度区分は管理情報・宣言から後段で付与する。出典に印字された年度・会計・方向は原文として保持し、固定値や推定で補わない。出典ID・頁・セル参照は出典との対応情報として保持する。
- PDFの見開き・折り返し・出典で確認できる所属や階層を復元することは取り込みで行う。共通科目への変換、事業×節への集約や配賦、単位換算と区別する。後段での利用のために、出典にない関係や共通形式を取り込み表へ混ぜない。
- PDFの取り込み表は、出典に印字された項目を1行とするノードの表と、印字された金額を1行とする金額の表の組で出す。CSVの出典は原文の行と1対1の表のまま取り込み、ノードの形への変換は後段で行う（[ADR 0020](../../../../docs/adr/0020-ingestion-outputs-node-tables.md)）。列の定義は [dbt モデルの設計](../../../../docs/prd/fiscal-dbt-models/dd.md#取り込みの出力-ノードの表と金額の表)、保存と管理JSONは [保存設計](../../../../docs/prd/ingestion-storage/dd.md) を正本とする。
- 見出しは原文を保持する。項目が印字された欄の見出しをノードの軸、段の見出しの印字を段の見出し、金額が印字された欄の見出しを上位から「／」で連結した文字列として必ず持つ（金額だけの欄に見出しがなければ、印字された説明などの欄の見出し）。見出しを確かめられない金額は保存しない。読み取れなかった金額と所属を確認できない項目は行を作らず、件数を管理JSONの `tables[]` に持つ。こちらで単位や共通分類の名称を付け足さない。単位は金額の行ごとに出典の単位の原文を持つ。会計名と出典由来の注記は表の単位の事実として管理JSONの `tables[]` に置き、行へ反復しない。ノードと金額は、それぞれ印字された物理頁と、印字範囲を囲む矩形の座標を持つ。座標は表示頁（CropBox・回転を反映した後）の左上を原点とするPDFのpoint単位に揃え、OCRの座標は元の頁の座標へ戻して入れる。座標は出典で探し直すために持ち、親子の判定の根拠にはしない。未確認の値を推定で補わず、段の名前・金額の段階への対応、集計方法・換算倍率・共通分類は後段へ残す。
- 出典で確認できる所属・階層は取り込みで組み立て、ノードの親として出力する。末端の行に祖先の名称・金額を反復する横持ちの表にしない。款・項・目のノードは同じ会計の各表に含め、各表を款を根とする木にする。目に属する独立した説明・節の一覧・財源内訳は、それぞれ別の軸の枝にし、一つの枝に混ぜない。所属を確認できない項目は親を推定せず、検査結果に未確認として残す。節への対応が未確認の説明を、特定の節の内訳と解釈しない。ヘッダーや全単語・座標まで反復する `context_json` を作らない。
- 空文字、NULL、印字された0、読み取れなかった値を区別する。OCRの観測がないことを、出典が空欄である根拠にしない。
- 取り込み表は型を明示して直接Parquetに保存する。同じ表のCSVは併出・中継せず、閲覧にもParquetを読む。出典CSVは別にそのまま保持する。
- 出典の行・頁・位置との対応を表または観測表に残す。PDFの物理頁番号と印刷頁番号は分ける。出典に印字された行番号と、抽出時に生成した観測IDを区別する。生成IDは観測・検査内の参照に使い、rawの出典値として扱わない。表ID・単位・欄の意味は出典で確認できた範囲で記録する。
- 指定されたローカル出力先にParquetを生成し、既存の表を上書きしない。変換結果に出典ID・表ID、ファイルのパス・SHA-256・サイズ・行数、抽出コード・layout設定への参照を対応付ける。独立した `provenance.json` は作らない。変換モジュール単体はR2や管理JSONを更新せず、管理側のCLIが取得・保存を行う。保存構造と移行は [保存設計](../../../../docs/prd/ingestion-storage/dd.md) を参照する。
- Bの終点は取り込みParquetと再抽出に必要なコード・書式設定、変換時の未確認事項。出典の選定（source_selection）、対象別JSONの管理、dbt、分類、採用はこの変換処理の責務に含めない。

## Aの保存済み出典を受け取る

1. Aから対象の選定情報と保存記録を受け取る。未選定・未保存・対象未確定の候補では開始しない。選定台帳全体をcontextへ出さず、対象だけを取り出す。
2. 呼び出し側が保存記録の出典をローカルへ用意する。Bは公式URLから再取得せず、取得済みファイルのSHA-256を保存記録と照合する。不一致は出典の差し替えとして停止し、現在の台帳へ勝手に合わせない。
3. 対象JSONと出典SHAからローカルパスへの対応を `ingestion:convert` へ渡す。実行入口が現在の選定・保存記録とscopeを検査し、出典のSHAを照合する。分冊は別出典として保持し、会計名・非連続の物理頁範囲・text/scanの指定を受け渡す。TypeScript側から個別に受け渡す場合は `pipeline/ingestion/selection.ts` の `prepareIngestion()` を使う。
4. PDFは渡された歳出の頁範囲だけを処理する。範囲内の文字層の状態に応じて抽出方法を切り替え、年度・会計を再判定しない。CSVは書式別コードで出典の会計・方向の列に対応させる。`convert_csv()` 自体は行を絞らないため、複数会計・歳入／歳出を含むCSVは出典の全行を保持し、対象行の対応を別に明示する。対応できなければ未確認として停止し、列の値から会計を推測しない。
5. 一つの表は出典ファイル一つから作り、分冊を一つの表へ結合しない。分冊をまたいで続く款・項・目は、各分冊の表に同じノードを置き、後段で一つにまとめる。出典の頁番号は分冊ごとに1から数え、通し頁を出典頁として記録しない。別会計・独立した表では階層の文脈をリセットする。

`prepareIngestion()` 単体はローカル出典の対応検査までを行う。R2からの復元と表の保存・登録は管理側のCLIを使う。PDFの自動書式選択や、取り込み表の検査・dbtへの採用をこの関数に任せない。

## contextへ返す量を限定した実行手順

1. 出典ID・対象頁／表・書式設定・出力先を指定する。既存の書式設定とコードを再利用し、新しい書式だけ必要な代表頁を確認して設定を作る。
2. 読み取り・表の組み立て・変換・検査はコードで実行する。OCR観測・bbox・Poppler XML・取り込み明細・詳しい検査結果はファイルに保存し、全量をツール出力へ流さない。長い標準出力・標準エラーもファイルへ保存する。
3. 通常は成否、出典ID・表ID、処理頁数・行数、異常の種類と件数、出力情報・詳細ファイルの参照先だけを短く返す。`ConversionResult` を返すときも、明細やOCR観測を併せて表示しない。要約の件数は全対象からコードで計算する。
4. 異常や確認の必要がある場合だけ、頁・表・列・行／観測IDで絞って取得する。最初の明細表示は10件以内を目安にし、必要な範囲へ段階的に広げる。全量の保持と、contextへの表示量を分ける。目視確認は対象頁・領域に限定する。
5. 修正はコード・書式設定へ反映し、影響した範囲を再実行する。同じ全量データをcontextへ読み直さず、要約と対象範囲の確認を繰り返す。全量表示の明示的な依頼がある場合は、その指定に従う。

## CSV

1. 文字コード、区切り文字、引用符、ヘッダー、列数、複数行セルを確認する。文字化けや列数不一致を黙って読み飛ばさない。
2. 出典のデータ行と1対1の表を作る。値は文字列として取り込み、先頭の0・空欄・桁区切り・単位を失う型推論を避ける。重複行・合計行・説明行を勝手に削除しない。
3. ヘッダー付きCSVは共通の `convert_csv()` で変換する。変換後に出典を読み直し、列名・順序・型、全セル値、行順、空欄、重複行、物理行範囲をParquetと照合し、不一致なら保存せず停止する。候補dirの `<表ID>.checks.json` の成否・出典SHA・表SHA・行数を確認し、通れば取り込み完了とする。出典自体の合計一致や財政上の正しさは合否条件にしない。ヘッダーなし・前置き付きは書式別コードを使い、共通検査に合格済みとは扱わない。
4. CSVはノードの表にしない。款・項・目・節が別の列に並び、取り込みで復元する木がないため、原文の表のまま渡す。ノードの形への変換は dbt の intermediate で行う。

## text PDF

1. 対象頁を表示し、文字層から必要な本文を取得できるか確認する。頁番号だけが文字で本文が画像なら、本文はscan PDFとして扱う。
2. **Popplerの `pdftotext -bbox-layout` で単語と座標を取得する。** 通常の入口は単語単位とし、文字単位への再分割を標準処理にしない。単語は抽出器の区切りであり、日本語の意味上の単語とは限らない。
3. 文字層があるのに文字化けする場合は、文字対応表・フォントの復元を検討する。復元できない領域だけOCRへ回す。アウトライン化された文字もOCRの対象になる。
4. 生の単語・座標を保持し、次の「PDFの表の組み立て」でノードと金額へまとめる。

座標は原点、単位、CropBox・回転の扱いを記録する。異なる抽出手段を混ぜるときは、同じ表示頁の座標系へ変換してから対応付ける。

## scan PDF

### 文字・位置を取得する

1. OCRは **共通入口** `pipeline/ingestion/lib/scan_ocr.py` を通して行う。既定は **PaddleOCR PP-OCRv6 small（ONNX Runtime、CPU）**。新しい依頼は `engine: "paddle"` と書く。Apple Visionは `backend="vision"` で選び、既存の冊は観測IDと訂正の宣言が結び付くので `engine: "vision"` のまま残す（[ADR 0032](../../../../docs/adr/0032-paddle-onnx-for-new-scan-acquisitions.md)）。Visionは単独の0などを読み落とすことがある。現行の取得（`acquire`）は、OCRの箱にも罫線にも覆われない墨を同じエンジンで読み直し、残りを行の文脈ごとVLMで読んで観測に固定する（下記「文字観測がないセルを再読する」の現行実装）。OCRは変換器の外で取得し、固定した観測を変換器へ渡す（[ADR 0019](../../../../docs/adr/0019-freeze-scan-ocr-observations.md)）。依頼は管理JSONの `ocr_inputs` に書き、`ingestion:ocr` が観測を取得してSHAを書き込む。観測は `convert --remote` で表と一緒にR2へ保存される。出典別の抽出器にエンジン呼び出し・画像描画・座標復元を複製しない。入口と設定の詳細は [モジュールの説明](../../../../pipeline/ingestion/lib/scan_ocr.md) を参照する。
2. 対象の物理頁・領域を指定し、300dpiを初期条件にする。表示上のCropBox・回転を反映して描画し、切り出し後の座標を元の頁へ戻す。
3. Paddleは **PP-OCRv6 small（ONNX Runtime）、検出長辺1280px、原解像度で文字認識** を初期条件にし、既定は縦2分割（重なり60px）・分割片ごとの検出上限1920・pypdfium2の300dpi（[ADR 0032](../../../../docs/adr/0032-paddle-onnx-for-new-scan-acquisitions.md)）で、変えるときだけ依頼の `config` に書く。この条件だけで全セルの文字保持を保証しない。観測のないセルは下記の欠落セル再読へ、検出済み名称の誤読は意味照合による補正へ進む。必要な見出し帯・セルの再読領域は出典別に宣言し、原画の切り出しで読む。前後のnative出力・採用した観測・座標、版・固定モデルSHA・描画条件・読み取り領域を保持する。Apple Visionは **accurate、revision 3、日本語・英語** を初期条件にし、OSの版・build、revision、言語補正も記録する。Appleの内部重みは固定できるとは扱わない。
4. Apple Visionの `usesLanguageCorrection` をonにする場合は、コードと別管理の `ocr_vocabulary.json` を `customWords` に渡す。辞書は正しい名称の候補であり、認識成功や単独の0の検出を保証しない。Paddleの原文をこの辞書で自動置換しない。
5. 出典の列・表領域を確認して切り出し、文字列・観測枠・単語／数値の部分枠を取得する。頁全体のOCRだけで、すべてのセルを検出できたとは判断しない。
6. OCRの `raw_text`、候補のconfidence、観測ID、読み取り領域、元の頁での座標を保持する。枠が取れない文字も捨てず、座標なしとして残す。親候補から引き継いだconfidenceを文字単位の精度と解釈しない。

OCRモジュールは文字と位置を返す。**表の列・セル・階層の検出は別の処理**で行い、OCR出力をそのまま完成した表とは扱わない。表や階層を生成するVLMはこのフローの標準経路にしない。

### 文字観測がないセルを再読する

単独の0などが初回OCRで観測されない場合は、次の順で再読する。

1. **OCRとは独立にセルの範囲を決める。** 罫線・表の列配置・行境界から金額セルを特定する。罫線がない表は書式宣言や出典確認を使い、不確かなセル範囲は未確認として残す。正解の数値を見て再読対象を選ばない。
2. 初回は表・列の領域で読む。セルと観測枠を対応付け、文字観測がないセルを再読候補として記録する。未検出候補には本当に空欄のセルも含まれる。
3. **欠落セルだけ、内側を小さく切り出して同じOCRモジュールへ渡す。** 罫線を避ける余白を設定し、初回の正常な観測は保持する。全セルをセル単位のOCRに置き換えない。
4. 得られた文字と枠を元の頁へ戻し、同じセルの再読観測として追加する。初回と再読の対応・設定・結果を残し、重なった観測を重複加算しない。
5. まだ読めない場合は、切り出し範囲・白い余白・拡大率を変える有限の再試行を行う。条件と回数の上限を先に定める。
6. 上限後も観測がないセルは未検出のまま残し、出典確認へ渡す。**空欄を0で埋める、合計に合う数字を推測する、`customWords`で0を強制する処理は行わない。**

### 検出済み名称は意味を照合してから再読する

名称の字形誤読や中点の差を見つけても、すぐcrop再読へ回さない。観測のないセルや数値の誤読は、名称補正とは分けて扱う。

1. **確認済みの共通訂正辞書を先に照合する。** 既知の科目・法定節の名称、欄の役割、節番号、所属の文脈から候補を絞る。「徵収費→徴収費」「負担金·補助及び交付金→負担金・補助及び交付金」のような、確認した誤読パターンは適用条件とともに共通辞書へ蓄積し、条件が合う別PDFでも再利用する。認識エンジン・モデル版による違いも適用条件に含める。出典・セルを限定する個別訂正は、その出典だけの例外に使う。
2. 辞書にない場合は、既知名称とOCRの混同パターンを意味的に照合する。候補が一意に決まり、観測済み文字の字形差で説明できる名称は、crop再読を省いて補正候補を作れる。新しい科目名・説明文を生成したり、名称から金額・単位・所属を補ったりしない。
3. 候補が複数ある、辞書の適用条件が合わない、誤読か出典の表記か区別できない場合だけ、該当領域をcropして再読する。解決しなければ未確認として出典画像の確認へ渡す。
4. **意味の一致だけで出典の字形まで確認済みとしない。** 旧字・異体字・句読点の一括置換で出典を標準語形へ揃えない。出典に「高齡者」と印字されていれば「齡」を保持する。補正箇所は出典字形と適用条件を確認し、誤った補正は撤回する。
5. nativeの元文字・観測ID・頁・座標を上書きせず、補正前後、適用したルールと辞書の版またはSHA、理由と確認範囲を残す。訂正辞書は認識器へ渡す語彙辞書とは区別する。

共通の後処理は [ocr_names.py](../../../../pipeline/ingestion/lib/ocr_names.py)、確認済みの名称パターンは [節名称辞書](../../../../pipeline/ingestion/lib/fiscal_setsu_name_corrections.json) と [科目名辞書](../../../../pipeline/ingestion/lib/fiscal_subject_name_corrections.json) を使う。番号を含む欄は呼び出し側で番号を分離し、名称全体だけを渡す。原文の空白・折り返しを保つ場合は `correct_name_preserving_layout` を使い、文字数が変わる規則の `layout_policy` も記録する。

金額の誤読も同じ宣言の形で直す。`id`・観測した金額・正しい金額・`reason` に頁と観測IDを足した `AmountRule` を `AmountDictionary` に置き、`correct_amount` で生の観測を上書きせずに補正前後・rule ID・辞書SHA・位置を返す。同じ誤読文字列が別のセルにあっても頁と観測IDが合う規則だけを適用し、宣言した観測文字列が実際の観測と食い違えばエラーにする。名称の規則は文字を、金額の規則は正しい金額が数字だけであることを検査し（観測した側はOCRの誤読をそのまま書くので英字を含んでよい）、種類の混ざった辞書キーを拒否する。金額の訂正は木の検査で正しさを確かめ、誤った宣言は合計と合わず検査を通らない。合計の差から値を逆算して埋めない。

これは名称補正の手順であり、共通辞書の自動適用が全抽出器に実装済みという意味ではない。

### 前処理と再試行の判断

- `minimumTextHeight` は指定値と実際の値を記録する。初回から0なら、さらに下げて改善する余地はない。大きく設定すると小さい文字を落とす可能性がある。
- 罫線除去は標準処理にしない。試す場合は元画像を保持し、文字の欠損・未検出・数値の不一致を比較する。
- 全頁の高解像度化・全セルの再読より、欠落領域だけの再読を先に試す。描画・OCR・再試行それぞれの時間を測り、再読対象が多い場合は列・セルの設定を見直す。
- 画像や設定を変えるときは、変更済みの条件にだけ再実行を限定する。キャッシュのキーには出典SHA、頁・領域、描画条件、OCR設定・版、辞書のハッシュを含める。

## PDFの表の組み立て（text / scan共通）

単語・OCR観測から行・列・階層を組み立てる処理は、Pythonコードと書式別の宣言にする。共通処理には `pipeline/ingestion/lib/pdf_table.py` を使い、列境界・見出し・見開きなど書式の違いを宣言で指定する。[共通モジュールの使い方](../../../../docs/pdf-table-module.md)を参照し、新しい書式では出典を確認してコード・宣言を作り、対象頁で検査してから同じ書式へ適用する。

layoutは年度・会計ではなく書式ごとに管理する。年度・会計が違っても列配置・見出し判定・階層表現が同じなら再利用し、設定値の違いで対応できる場合は同じ処理へ設定を渡す。書式の規則が変わる場合は別のlayoutにする。一つのPDF内でも頁・表ごとに書式が違えばlayoutを切り替える。年度・会計は上流から受け取り、layoutから推定しない。別会計・独立した表へ移るときは階層の文脈をリセットする。文書ごとの組版の設定（`<方向>.layout.json`）の形・6項目・指紋への含有は [組版設定](../../../../docs/prd/generic-node-builder/layout-settings.md) を参照する。

LLMを使う場合は、このコード・宣言の作成と修正を支援させる。取り込み実行時に、各PDFの行・金額・階層を毎回LLMへ生成させない。

1. **見開きが1つの表なら、左右の単語・観測を共通座標系へ合わせてから行にまとめる。** 頁ごとに作った行番号で結合しない。折り返しの違いで左右の行数が一致しないため、表の基準線・列を使って対応させ、元の頁・座標も保持する。
2. 出典で列の役割を確認し、名称・金額・節・説明欄を区別する。ヘッダーも出典の文字・位置から構築し、複数段・結合範囲・単位と本文列への対応を保持・検査する。列名とx境界を手動指定しただけでは、この対応を確認したことにしない。固定したx境界だけで長い名称や桁の多い金額を切り捨てない。罫線、配置、文字の並びを合わせて判断する。
3. 款・項・目の見出しを取り、その文脈を同じ会計・表の明細へ継承する。継続頁の再掲見出しで文脈を消さず、見出しの変更・表や会計の終了で更新する。
4. 事業・説明の階層は、字下げ・番号・罫線・金額の配置を出典で確認して復元する。階層数や名称の意味を自治体共通の固定ルールにしない。名称の左端や金額の右端だけで一意に決めない。
5. 名称の折り返しは位置と文脈を確認して結合し、説明文・積算根拠を名称に混ぜない。折り返しが終わってから名称を確定する。原文も保持し、名称に含まれる数字を通し番号だと推測して削除しない。
6. **法定節一覧と事業・説明欄は、内部の構築・検査で独立して扱う。** 印字行番号・y座標を使って節と説明を結合しない。見開きの共通座標は文字の配置のために使い、意味上の関係の根拠にはしない。説明内に確認済みの節見出しがある場合は、事業・節・細目の親子関係と同じ目の節一覧への対応を保持する。対応が未確認なら、確認済みの目への所属と説明内の経路までを保持する。保存する取り込み表では、説明内の各段の項目をノードにし、親子で階層を表す。出典で名称・金額が一つの欄に印字されていても、JSON・配列・STRUCT列に格納しない。法定節一覧は説明とは別の軸の枝にし、境界で継続中の項目は検査用の観測として保持する。説明内の段を節と名付ける解釈は後段の宣言で行い、出典の見出し・値に混ぜない。対象ページだけでは末端を確定できない項目は検査結果に未完了として示す。抽出元の欄や範囲の終了状態など、抽出・検査の状態を出典の値として追加しない。欄はノードの軸、終了状態は観測と検査結果へ残す。説明の項目金額と法定節総額を区別し、同じ高さの行や名前だけから配賦された内訳を作らない。
7. 内訳がない目も残す。集計値と内訳は区別して保持し、同じ金額を二重に加算しない。不明な階層や対応は推測で埋めず、出典で確認できる粒度を出す。

法定節一覧と説明欄を別に構築することは、説明欄内に節の区分がないという意味ではない。説明が「事業→節→細目」を印字している場合は、その節見出しと細目への所属を保持する。目の全範囲と継続頁を確認し、説明内の節別金額を目×節へ集約して法定節一覧と照合する。名称だけ・同じ高さの行だけでは対応を確定せず、出典内の節名称・区分の対応、階層、対象範囲、節別金額の一致を合わせて確認する。財源内訳は別の分解であり、出典に事業・細目ごとの配分がなければ結合して配分額を作らない。今回の局所確認と適用範囲は [共通モジュールの説明](../../../../docs/pdf-table-module.md) を参照する。

組み立てたノードと金額は型を固定し、`pipeline/ingestion/lib/conversion.py` の `write_conversion()` に渡す。内部で `parquet.py` による保存を行い、ローカルの出力情報を返す。表IDに対応する戻り値は、ノードの表と金額の表のパスと、表の会計名・notesにする。移行前の横持ちの表を出す既存の変換器は、パスとmetadataの戻り値を使える。既存PDFの全表は、横持ちの表とmetadataからノードの表と金額の表を作る `node_tables.migrate_rows()` で移行する。複数段をまとめた `column_contexts` は名称列の接頭辞で分ける。段の位置があれば親と位置で、なければ同じ親の下で連続するその段までの値の組で識別する。離れて再登場する同名の兄弟をまとめない。根の軸の見出しは「科目」に固定しない。節の一覧は独立した枝にし、続く説明の軸は直前の説明に結ぶ。説明のない科目は同じ会計で生成した明細表から補う。備考欄の流用・充用・不用額等は、共通の注記辞書で種類を解き、原文と金額・単位・印字位置を「注記」軸に保持する。金額の見出しは「注記金額」で、段階を付けず、木の合計と支出済額の選択から外す。「予備費」の語だけでは注記にしない。「事業へ支出」は既存の備考セルで親科目名が「予備費」と完全一致する場合だけ充用にする。月額は既存の月額セル、回数単価は同じ括弧内の円付き金額に限定する。議決番号・年号の数字は、注記の語が同じ欄にあっても金額にしない。折返しは同じ備考欄だけで継承する。未割当の観測も保存して受け渡す。PDFの読み取り・表の組み立て・Parquetの保存を別の処理として扱い、書き出し時に金額や階層を推論しない。

「最小の構築」の対象が少数ページなら、ページ数を限定して本来の取り込み構造を作る。ヘッダー、名称の折り返し、階層、独立した表の分離を省いた印字行グリッドを、取り込み完了と扱わない。範囲末尾で続く階層は継続中として保持し、閉じた範囲の検算と区別する。見開きtext PDFの実装例は [statement/text_spread.py](../../../../pipeline/ingestion/fiscal/layouts/statement/text_spread.py)、今回の適用範囲は [共通モジュールの説明](../../../../docs/pdf-table-module.md) を参照する。

## PDFの金額検査

PDFは出典の内部で重複して印字された数字どうしの一致で確かめる。保存した候補Parquetを読み戻し、階層ごとに「直下の内訳の合計＝出典に印字された親の金額」を照合する。構築コードの自己申告や、構築コード内の再計算との一致だけで合格にしない。

| 集計する内訳 | 比較する出典の金額 |
| --- | --- |
| 説明欄の末端明細（確認済みの所属で目・節ごとに集計） | 同じ目の法定節一覧の節額 |
| 同じ目に属する節額 | 目の金額 |
| 同じ項に属する目の金額 | 項の金額 |
| 同じ款に属する項の金額 | 款の金額 |

- 同じ会計・金額段階・金額列・単位の中で、名称ではなく所属経路で比較する。反復した親の金額は親ごとに一度だけ数え、`SUM(DISTINCT 金額)` は使わない。小計と内訳、独立した分解（法定節一覧と説明欄・財源内訳）を足し合わせない。
- 結果は一致／不一致に加え、継続頁・未読・所属未確認は「保留」、比較する印字合計や完全な内訳がない場合は「検算不可」とし理由を残す。欠けた金額を0で補わない。
- 合計一致では名称の欠損や同額の取り違えを検出できない。名称・未読セル・欠落・二重収録は、合計が合わない箇所と補正した箇所を中心に出典で確認する。OCRの未検出・誤読・表への対応未確認は分けて報告する。
- 不一致・保留・検算不可を一覧にして原因（欠落・二重収録・誤読・誤所属・範囲不足・出典の不整合）を切り分け、下の手順で修正して影響範囲と上位階層を再検査する。同じ問題が2回程度の修正で解消しない場合は、階層・粒度・継続頁・単位と検査側の集計キーの前提を出典で見直す。合計を合わせるための推定・配賦やParquetの直接書き換えはしない。
- 金額セルを科目番号・積算根拠と区別し、年度・会計・単位・金額段階・当年／前年の列を出典の見出しと照合する。補正は基準額・増減額・補正後額を区別し、未収録の変更を0にしない。
- 共通の検査は `bun run --cwd pipeline ingestion:verify --manifest <JSON>`（候補は `--candidate <候補dir>`）。text PDF は `tree_checks.py` の `check_tree`（子と同じ軸の子孫が金額を1つも印字しない親は比べない。表の作り手で検査を変えない）が同じ軸の親子合計を全段で検査し、`coverage_checks.py` の `check_digit_coverage` が印字された数字の網羅（金額の行・項目の表示・共通の非金額に分類できない金額帯の数字は保存前に停止、帯の外は報告）を検査し、保存処理も両方の検査を通過条件にする（網羅は scan PDF が対象外）。単位の確かめ（款の和＝印字の歳出合計と、一般会計の桁。`ingestion/fiscal/unit_checks.py`）は scan も含む全 PDF 表の通過条件で、印字の合計が置けない表・保存済みの表は桁だけ、分冊は報告だけを出す（[ADR 0028](../../../../docs/adr/0028-unit-check-in-the-save-gate.md)）。明示された計の0も同じ科目・金額列の合計と照合する。科目の再掲は採用済みの祖先経路・印字列で照合し、既存の数量セルの矩形は「数量表」の範囲として検査に渡す。判定は [tree_checks.py](../../../../pipeline/ingestion/lib/tree_checks.py)・[coverage_checks.py](../../../../pipeline/ingestion/lib/coverage_checks.py) を正本とする。詳細は `.build/ingestion-verify/` へ出力され、標準出力は表ごとの件数だけになる。保存済みの表は語の対象範囲を持たないため、網羅の再検査は候補の scope 付きのみ。
- ノードの表・金額の表は未読・所属未確認・構造の不整合・合計不一致があれば保存前に停止する。`ingestion:verify` は不一致で終了コード1となる。表をまたぐ照合（説明内の節と法定節一覧の対応）・独立した分解（財源内訳）の検査は共通の木の検査の対象外であり、必要になればdbt側の共通の検査として作り直す（個別の宣言は置かない）。支出額の集計に使わない補助表を外すときは、`expected_tables`・`tables` から外す。R2の実体は別の操作で削除する。

## 誤りが見つかったときの修正

1. 出典と観測を確認し、文字の未検出・誤読、セルや階層への誤割当、出典自体の空欄を区別する。合計の不一致だけで欠落セルや訂正値を決めない。
2. 検出済み名称の誤読は [意味照合による補正](#検出済み名称は意味を照合してから再読する) を先に行い、一意に決まらない箇所を再読する。未検出や数値の誤読は対象領域の読み取り条件を見直して再読する。誤割当は書式別の列境界・行結合・見出し判定を修正する。共通化できる処理はモジュールへ置き、Parquet書き出しへ出典別の例外を追加しない。
3. 再読・ルール修正で解消しない値は未解決として残す。出典を確認した個別訂正が必要な場合は、出典SHA・物理頁・セル枠・取得済みの観測IDで対象を限定し、訂正値と理由を宣言で別管理する。元の文字・観測なしの状態を上書きせず、印字が確認できない値を推測しない。
4. 修正対象の表を組み立て直し、新しい候補Parquetへ保存する。採用済み入力は上書きしない。影響する範囲で保存・読み戻しと合計検査を再実行し、同じ書式の他の表への影響も確認する。

## 共通の規則を足すとき

`ingestion/lib/`・`ingestion/generic/` の規則を足す・広げるときは、既存の全表を変更の前後で数え、出力が1行も変わらないことを確かめてから採る。変わった表があれば、規則を設定（`repairs` などの allowlist）へ閉じるか、款・項の文脈に限定する（`消費者行政` を共通の語にしたところ世田谷・青ヶ島の既存の目が変わり、産業経済費の商工費に限定した）。採否は不一致の総数で決めない — 修正で不一致が入れ替わるだけ（頁単位の増減が0）なら実質の改善ではない（昭島は 21→20 の入れ替わりで不採用）。

## PDFの再抽出（再現性の確認）

抽出器を変更・移設したときや、出典だけから作り直せると主張するときは、次の範囲を確認する。

1. SHAを確認した出典PDF、抽出コード、必要な書式設定・訂正宣言を使う。候補Parquetを再抽出の入力にしない。
2. 別の出力先・キャッシュで実行し、元の私有フォルダ・旧key・旧pathに依存しないか確認する。作業領域から採用済み入力へのdir symlinkを張らない。読み取り用symlink経由の相対writeが入力を変更し得る。
3. 位置付き観測やOCR結果を入力にする場合は、その保存物からの再構築と、出典PDFから取り直した再実行を分ける。凍結観測からの再生を出典からの再抽出として報告しない。
4. 再生成表と候補の列型・全値・NULL・重複数・出典位置を照合する。SHA一致と表の内容一致は区別する。実行環境やOCRによりバイト列の一致を保証できない場合は、その条件を明記する。
5. 入力・設定・対象範囲・結果はローカルの検査記録に残し、必要なコードと宣言は本体から辿れるようにする。

同じ文書の一部の頁だけを変換した結果は、全体の変換と一致しないことがある。帯・段・見出しの種類は text の頁から学ぶため、OCR の頁だけを変換すると学習が欠ける（調布2024 の p413 は頁だけの組み立てで見出しが化け、全体の変換では正しく読めた）。合否は全体の変換で判断する。

同じ候補を再現できても、同じ誤りを再現することがある。[PDFの金額検査](#pdfの金額検査) の代わりにしない。旧Parquetをコピーするだけの処理は再抽出器ではない。再抽出の共通CLIや、全PDFに必須とする合否条件はまだない。

## 変換結果の受け渡し

`ConversionContext` で、出典ID・表ID、抽出コード・layout設定への参照を渡す。Aからの入力では `prepareIngestion()` の選定参照と、使用した全出典の保存参照を渡す。変換が複数の出典を受け取る場合は、表ごとにどの出典から作ったかを対応させる。型は [conversion.py](../../../../pipeline/ingestion/lib/conversion.py) を参照する。`convert_csv()` と `write_conversion()` は、これらの参照とParquetのローカルパス・SHA-256・サイズ・行数を `ConversionResult` として返す。`dataclasses.asdict()` でJSONにできる辞書へ変換できる。

年度・会計等を推定・定義せず、受け取った対象・scopeと変換結果を表IDで対応させて管理側へ渡す。変換器は `convert(inputs, destination, options)` と同じフォルダの `options.schema.json` を定義し、表IDとローカルParquetの対応を返す。変換器からGitの管理JSONやR2を更新しない。型と制約は [管理schema](../../../../pipeline/ingestion/fiscal/manifest.schema.json) と [実行時検査](../../../../pipeline/ingestion/fiscal/manifest.py) を正本とする。

## 管理JSONを確認して変換する

1. `pipeline/ingestion/fiscal/jurisdictions/<自治体>/<年度>/<資料区分>/<方向>.json` に入力SHA、変換コード・設定、期待する表を定義する。形式・会計・ページ範囲はselectionから解決する。複数出典・複数変換・複数表は同じ対象のJSONへまとめる。
2. `pipeline/` から `bun run ingestion:check --manifest <対象JSON>` を実行する。型・正規配置・選定との対応・表IDの所有者が不正なら修正してから進む。
3. 出典のSHAからローカルパスへの対応JSONを渡す。出典の復元が必要なら `bun run ingestion:originals --manifest <対象JSON> --output <入力パスJSON> --remote` を使う。
4. `bun run ingestion:convert --manifest <対象JSON> --inputs <入力パスJSON> --output <新しい候補dir>` を実行する。件数とファイルパスだけをcontextへ返し、表・OCR・検査の詳細はファイルへ保存する。
5. CSVは自動保持検査の結果を確認して保存へ進む。PDFは候補Parquetと未確認事項を出典照合へ渡す。R2へ保存する場合は次の手順へ進む。

## 現在版の保存・差し替え

1. 管理側から現在の選定・scope・設定を受け取り、入力条件を確定する。同じ対象の出典更新・変換・保存・後段処理は順番に実行し、並行更新しない。出典はAの保存先を使用し、Bで別の出典領域へ複製しない。
2. 必要な全表をローカルで生成・検査する。異常の詳細はファイルに保存し、件数と対象だけを返す。
3. 新しい候補dirを指定し、`ingestion:convert` に `--remote` を付ける。入力条件が変わっていないことを確認し、管理側の保存処理が対象の方向の領域へ全表を上書き保存する。scan PDFのOCR観測（`ocr_inputs`）も表より先に同じ領域の `ocr/` へ保存される。
4. 期待する表と処理済み・未処理範囲を確認し、全アップロード成功後に管理側が表の管理情報を更新する。局所再処理では、変更しない表の参照も保持する。未処理・欠落や未確認の0行を、表の廃止として扱わない。失敗時は後段へ進まず、同じ入力条件で必要な全表を再保存する。
5. PDFの新形式では保存後に自動で掃除しない。2表の保存と管理JSONの採用を確認してから、移行した横持ちの表を別の操作で削除する。対象かつ指定した方向のingestion領域だけを一覧取得し、削除直前にも現在の参照を確認する。旧形式の掃除に失敗したら `bun run ingestion:cleanup --manifest <対象JSON>` を実行する。別年度・別補正号・別方向を削除しない。
取り込みは表と管理情報の保存・差し替えまでで完了する。保存済みの管理情報とParquetの読み込み、入力条件・SHA・サイズの照合はdbt側の入力準備で行う。保存途中の表を読み始めない。

## 保存済みの自治体へ会計を足す

保存済みの表（一般会計など）と未保存の新しい変換は、同じ管理 JSON に共存できない（`Saved manifest must contain every expected table`）。会計を足すときは、管理 JSON を直接編集せず、現在の管理 JSON に変換を1つだけ追加し `tables` を空にした計画の JSON を作って `ingestion:convert --manifest <対象JSON> --inputs <入力パスJSON> --output <新しい候補dir> --extend-plan <計画JSON>` に渡す。既存の変換・表は変えずに保持され、新しい表だけを変換して関門を当てる。`--remote` を付けると保存して管理 JSON に登録する（付けなければ候補だけ）。1回に足せる変換は1つなので、複数の会計は順に回す（登録のたびに管理 JSON が変わるので、計画は毎回その時点の管理 JSON から作る）。`generic/` を直した後の保存済みの表は、先に `ingestion:refresh --remote` で指紋を合わせる。

## 指紋が古くなったとき

scan の測定用管理 JSON は `docs/prd/generic-node-builder/scan/plans/` に `tables=[]`・`ocr_inputs` 付きで保持する。`ingestion:cleanup` はこの参照も照合してOCRを保護する。採用した変換は正規manifestへ移し、plansから外す。取得は `scan/acquire.py --plan … --inputs-dir … --remote` で逐次固定・保存し、`request.vlm_fallback:false` はVisionの欠落再読までを行い、残りを金額検査後の有限のVLM再読へ渡す。

`ingestion:check` が `Stale saved table` で止まるのは、表を作ったコード・設定・出典・scopeのどれかが変わったという合図であり、表の中身が変わった証拠ではない。次の順で、中身で決める（[ADR 0027](../../../../docs/adr/0027-refresh-fingerprints-by-table-content.md)）。

指紋は変換の宣言（`conversions[].options`）と書式の設定（`.layout.json`）も含む。印字の食い違いの注記のように表の中身を変えない記録は `.layout.json` に足さず、`jurisdictions/<自治体>/README.md` や [書式の設定](../../../../docs/prd/generic-node-builder/layout-settings.md) に書く — 宣言に1行足すだけでその対象の全表が stale になる。

1. `bun run ingestion:refresh --remote` を `pipeline/` から実行する（対象を絞るなら `--manifest <対象JSON>`、書き換えずに見るだけなら `--dry-run`）。レビュー指摘への修正はまとめてから回す — 変換コードを1行直すたびに回すと、全表の再変換に40〜50分かかる（2026-10-22 実測で6回超）。`--remote` を省くと、指紋の変わった表を R2 から取り直さないので、古い `.cache/objects` との不一致で `restore` が止まる。指紋が古い管理JSONだけが対象で、出典と保存済みの表をR2から読み（書かない）、変換をローカルでやり直して、表ごとに列・型・行の順序・値と、管理JSONへ書く表のメタデータを比べる。保存前の関門（木の検査・網羅の検査）も当て直す。
2. 全表が「same」の管理JSONは、`input_fingerprint` だけを書き換える。保存済みのParquetとその `sha256`・サイズは変えない。結果は `.build/ingestion-refresh/report.json`（管理JSON・表ごとの `same`／`different`／`blocked`と、増えた・消えた・変わった行の数と例）に残り、標準出力には件数と対象だけを返す。
3. 「different」か「blocked」の管理JSONは書き換えない。`different` は本当の変更なので、件数と差分を確かめ、許可を取って `ingestion:convert --remote` で保存し直す。`blocked` は今の検査で止まるので、変換コードか宣言を直す。
4. 共有のコード（`ingestion/lib/`・`ingestion/generic/`・書式別の共通処理）を直す PR は、手順1を回して更新した管理JSONを含める。PRの差分が、どの表の中身が変わったかを示す。
5. 表を作らず合否だけを決める検査のコードは、表を作るコードと別の `*_checks.py` に置く。このモジュールは指紋の対象外で、変更しても表は古くならない（表を書く関数・呼び出しがあれば `manifest.dependencies` が停止する）。そのため検査を厳しくした PR は、`bun run ingestion:verify --remote` を保存済みの全表に当てて通ることを確かめる。落ちる表は変換コードか宣言を直して保存し直す。

`--dry-run` は R2 と管理 JSON を書かないが、やり直した表が使う Jev の答え（`<方向>.digit-recheck.jsonl`、Git 管理）は更新され得る。`convert` が答えを書き戻す副作用で、同じ答えの集合なら差分は出ない。dry-run の後に `git status` を見て、指紋以外の差分は答えの変化として別に判断する。

保存キー・管理情報の置き場は [設計書](../../../../docs/prd/ingestion-storage/dd.md) を参照する。局所再処理は `--conversion <ID>` を使う。説明のない科目の補完が必要なら、同じ会計の明細表を生成するconversionも選ぶ。変更しない表が現在の条件と一致していることを確認する。

金額の位置は金額列自身の `<金額列>_物理頁`（または `_出典物理頁`）と座標列から取る。text PDF の変換器は、金額の表の各行が印字の頁・座標を持つよう、金額の語の box を共通の `amount_position_fields()`（中央区は出典座標の `origin_position()`）で金額列ごとの位置列に載せる。行の位置が金額自身の位置であると変換器が確認済みなら、context の `amount_position_prefix` で位置列の接頭辞を宣言できる。金額自身の頁がない横持ちの表は、移行で金額の `physical_page`・座標をNULLにする。名称の頁や座標を流用しない。

印字された数字の網羅は `coverage_checks.check_digit_coverage()` の共通検査で確かめる（text PDF のみ）。変換器は処理した頁・領域の文字層の語（頁・表示座標・原文）を `<表ID>.coverage.json` に出し、保存処理が木の検査と並べて当てる。金額の行の box に入る語はその金額の一部、ノードの box に入り符号・名称に読める語は項目の表示、頁番号・年月日・％・番号＋文字・頁脚番号・統制合計行は自治体共通の非金額、金額帯に入る残りは止める取りこぼし、帯の外の残りは件数と例の報告に残す。明示された計の0も同じ科目・金額列の合計と照合する。科目の再掲は採用済みの祖先経路・印字列で照合し、既存の数量セルの矩形は「数量表」の範囲として検査に渡す。判定は [coverage_checks.py](../../../../pipeline/ingestion/lib/coverage_checks.py) を正本とする。

備考欄の金額が注記として採用されないときは、自治体の変換器より先に `annotations.py` の共通の原因を疑う（[ADR 0024](../../../../docs/adr/0024-monetary-annotations-without-phase.md) の追記）: 末尾に `円` が付く金額セル、節の行の接頭辞のない「備考」列、見開きの右頁の行割当と備考の先頭行・折返し、予備費が充用した款を列挙する備考。備考へ原文のまま保持した経費内訳は、変換器が `annotations.remark_prose_lines()` で辞書の語が現れる前の行だけを `経費内訳` の非採用の範囲として宣言する（保持した語だけで、採用した金額・ノードの語は含めない）。金額が次の頁へ折り返す内訳は、金額の物理頁を金額の語の頁で持つ。

Jev の聞き直し（`ingestion/lib/digit_recheck.py`）は網羅の検査の後段で、止める方向だけに使う。聞く数字は2種類だけ — 弱い規則（注記・書式の非金額の形、頁脚・番号・数量・年月日）で非金額とした数字と、金額帯の外で説明がつかず報告に残った数字。採用した金額・ノードの番号と名前（科目コードと段の印字 `1項`・`（目）2` を含む）、議決番号の形（令和7年第7号）、合計、宣言した非採用の範囲で説明がつく数字は聞かない。帯の中で止まっている数字も聞くが、その確率は原因の手がかりとして添えるだけで通す判断には使わない。問いは「この数字は表の項目の金額として取り込むべき値か」（モデルは `jev-1.13.0` 固定、しきい値0.7）で、同じ行の語を左から並べて対象を【】で示した文・列の見出し・上下の行だけを渡す。座標と、規則が通した理由は渡さない（理由を渡すと本物の金額を見逃しやすくなった）。0.7 以上は `jev_blocked` として止め、原因の規則を `rule` に残す。答えは `<方向>.digit-recheck.jsonl`（Git）に、入力の fingerprint（文の内容・問いの文・基準・モデル・しきい値のどれが変わっても別の問いになる）と確率だけを保存し、convert・verify のやり直しでは API を呼ばずに再現する。答えが無く `TYPESAFE_API_KEY` も無いときは飛ばさずに止める。convert は答えを書き戻し、再実行した表では使った答えだけを残す（失敗した実行でも聞いた答えは残る）。止まった数字は人が出典の頁で本物か聞き方の誤検出かを分け、本物は変換器か非採用の宣言を、誤検出は共通の規則（科目コードの印字など）を直す。Jev の答えで止まっている数字を通す設定は置かない。数字を含まない文字（名前・見出し）の網羅は対象外。

網羅の照合は出典PDFごとに行う。同じ出典の同じ物理頁を読む表は、同じ変換でも別の変換でも、採用した全表のノード・金額の印字位置を集めて照らす。木の検査は各表に個別に当てる。処理する語の範囲と金額欄の境界は表ごとの sidecar に残し、金額欄のある書式では既存の欄境界を使う。自由な位置に印字される説明の金額で欄境界がない場合は、金額行の範囲を使った帯であることを `bands_from` に明示する。

読んだが採用しない表・ブロックは、変換器の既存の読み分け（観測用の総括・節一覧・本文・経費内訳など）から実行時に語の頁・矩形を出す。人が定めるのは表の種類と採用しない理由だけで、検査から外す頁・x・yを手書きしない。種類の語彙は `node_tables.EXCLUSION_KINDS` に集約し、未知の種類・空の理由・不正な範囲は停止する。新しい非採用の判断は共通処理から自動で増やさない。非採用の範囲と重なる採用金額・項目の表示を先に照合し、非採用の件数と種類別内訳も検査結果に残す。

名称の中でも桁区切りや円の付いた金額の表記は、名称として網羅済みにしない。枠に重なる数字の断片がはみ出す場合は、同じ印字の断片をつないだ数字が採用金額と完全に一致する場合だけ照合済みにする。隣接するだけの数字は網羅済みにしない。分割された議決番号・年度や、数値のすぐ上の％の単位は、印字の位置と共通の非金額の書式が一致する場合に限って照合する。未網羅の数字は引き続き金額帯で保存を止め、帯の外では件数と例を報告する。

ラベルのない合計行は、同じ採用表で同じ親・軸・段に属する金額が同じ見出し・単位ごとに持つ和と照合する。全ての子の印字より後の行で、0以外の和が2列以上で一致するときだけ、その行の一致した列を網羅済みにする。1列だけの一致、0だけの一致、不一致の列は停止したままにする。独立した表の木を混ぜて合計を推測しない。

自由配置の金額で `bands_from=rows` を使う表は、列ごと落ちた金額を網羅の検査では検出できない。この場合も説明の軸の親子の和を木の検査で確認し、表ごとに帯の生成方法を報告する。

合計の和は、同じ親の全ての子、または同じ親の同じ頁の子で確かめる。2列以上で確かめた合計の直後に折り返された0以外の金額も、同じ和と一致する場合だけ網羅済みにする。「計」「合計」「小計」の印字が金額の左にある場合は、同じ親の採用金額の和と一致する0以外の列を照合する。0だけの一致で合計と認定しない。
