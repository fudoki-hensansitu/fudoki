# B. ingestion

選定・保存済みの出典から取り込みの表を作り、検査して管理 JSON に記録するまで（R2 には merge 後の CI が置く）。表の形は [dbt モデルの設計](../../../../docs/prd/fiscal-dbt-models/dd.md#取り込みの出力-ノードの表と金額の表)、保存と管理 JSON は [保存設計](../../../../docs/prd/ingestion-storage/dd.md)、型は [管理 schema](../../../../pipeline/ingestion/fiscal/manifest.schema.json) が正本。

## 原則

- 取り込みは raw。文字列・金額の表記・単位・見出しは出典のまま持つ。換算・名称の統一・分類・段の名前・金額の段階は後段で行う。
- PDF は印字された項目のノードの表と、印字された金額の金額の表の組にする。CSV は原文の行と1対1の表にする（[ADR 0020](../../../../docs/adr/0020-ingestion-outputs-node-tables.md)）。
- 出典で確かめられる所属・階層は取り込みで組み立て、ノードの親にする。独立した分解（節の一覧・事業の説明・財源内訳）は別の軸の枝にし、混ぜない。
- 推定しない。読めない金額・所属を確かめられない項目は行にせず、件数を管理 JSON に残す。空欄・0・読めない値を区別し、0 で埋めない。
- 1つの表は1つの出典ファイルから作る。分冊を結合しない。
- 変換器は R2 と管理 JSON を書かない。保存と登録は管理側の CLI が行う。
- 大きな出力（OCR の観測・語・検査の詳細）はファイルに置き、context には件数と参照先だけを返す。

## 形式ごとの読み方

- **CSV**: 共通の変換で取り込み、出典を読み直して全セルが一致することを確かめる。
- **text PDF**: Poppler の語と座標から読む。Poppler は `mise.toml` で版を固定する（版で読める語が変わる）。版を上げたら全表を読み直して比べる。
- **scan PDF**: OCR は共通の入口で変換の外で取り、観測を固定する（[ADR 0019](../../../../docs/adr/0019-freeze-scan-ocr-observations.md)、[ADR 0032](../../../../docs/adr/0032-paddle-onnx-for-new-scan-acquisitions.md)）。読めなかったセルは範囲を絞って読み直す。名称の誤読は確かめた辞書で直し、出典の字形は保つ。合計から値を逆算しない。

## 読み方の宣言

- PDF の読み方は管理 JSON の workflow に宣言する。書式ごとに作り（年度・会計ごとではない）、同じ書式の年度・会計に写す。自治体別の変換コードは増やさない（[PDF workflow の設計](../../../../docs/prd/pdf-workflow-patterns/dd.md)）。
- 1つの書式のための判定は opt-in の quirk にし、使う表だけが選ぶ（[ADR 0043](../../../../docs/adr/0043-format-quirks-are-opt-in.md)）。共通コードを直すのは、全表に効くべき直しのときだけ。共通の規則を足す・広げるときは、既存の全表で出力が変わらないことを確かめる。
- LLM は宣言とコードを作るのに使い、実行時に表を作らせない。

## 検査（保存の関門）

- 木の検査: 同じ軸で、印字された親の金額＝子の和を全段で確かめる。
- 数字の網羅（text PDF）: 印字された数字が、採用した金額・項目か、宣言した非採用の範囲で説明できることを確かめる。
- 単位の確かめ: 款の和と印字の歳出合計、一般会計の桁（[ADR 0028](../../../../docs/adr/0028-unit-check-in-the-save-gate.md)）。
- Jev の聞き直しは止める方向だけに使う。
- 通らない表は保存しない。合計を合わせるための推定・配賦・Parquet の直接の書き換えはしない。2回ほど直して解けなければ、階層・単位・範囲の前提を出典で見直す。
- 誤りは、読めていない・誤読・誤った所属・出典の空欄を分けて直す。出典を確かめた個別の訂正は、位置を限った宣言にする。

## 保存と指紋

- `ingestion:convert` は検査が通った表を管理 JSON に記録する（R2 には書かない）。R2 に置くのは merge 後の CI の `ingestion:store` だけで、記録と変換し直した表が一致したものを置く（[ADR 0045](../../../../docs/adr/0045-ingestion-tables-uploaded-by-ci.md)）。スレッドが R2 に書くのは OCR 結果（`ingestion:ocr --save`）だけ。保存済みの対象に会計を足すときは、既存の表を変えずに1変換ずつ足す。
- 指紋が古いのは、表を作るコード・設定・出典が変わった合図で、中身が変わった証拠ではない。`ingestion:refresh` で作り直して中身を比べ、同じなら指紋だけを書き換える。違えば convert で記録し直す（[ADR 0027](../../../../docs/adr/0027-refresh-fingerprints-by-table-content.md)）。refresh は PR ごとに回さず、全部 merge した後に1回回す。
- 合否だけを決める検査のコード（`*_checks.py`）は指紋の外にある。検査を厳しくしたら、保存済みの全表に当て直して通ることを確かめる。
