# B. ingestion

渡されたCSV/PDFから、印字された値・単位・粒度を保持した取り込みParquetを作る。抽出の説明は歳出を対象とする。管理・保存CLIは歳入と歳出を方向別に扱い、既存の歳入表も移行できる。取り込み方法は **CSV・text PDF・scan PDF** の形式に応じて選ぶ。PDF内でも頁・領域ごとに文字層の利用可否を判断する。

この文書は書き直した取り込み方針であり、現行の抽出器や登録方式を前提にしない。セル検出・欠落領域の自動再実行を含め、ここに書いたフロー全体が実装済みという意味ではない。

## 入力・出力と共通原則

- 入力はAの選定・保存記録と、保存済み原典に対応するローカルCSV/PDF、対象範囲と未確認事項。入力の型は [source_selection/schema.ts](../../../../pipeline/source_selection/schema.ts) を正本とする。原典の取得・探索、これらの情報の判定・管理は上流の責務とし、Bでは受け取った情報との対応を保持する。原典のバイト列は変えず、SHA-256で対応を確認する。
- 原典の文字列、金額の桁区切り・符号・単位を保持する。カンマ除去、数値型への変換、円への換算、名称の統一は後段で行う。
- 取り込みはraw層であり、対象の管理情報を財政データ列として追加しない。団体コード・西暦年度・資料区分・歳入／歳出の共通コード・共通の粒度区分は管理情報・宣言から後段で付与する。原典に印字された年度・会計・方向は原文として保持し、固定値や推定で補わない。原典ID・頁・セル参照は原典との対応情報として保持する。
- PDFの見開き・折り返し・原典で確認できる所属や階層を復元することは取り込みで行う。共通科目への変換、事業×節への集約や配賦、単位換算と区別する。後段での利用のために、原典にない関係や共通形式を取り込み表へ混ぜない。
- PDFの取り込み表は、原典に印字された項目を1行とするノードの表と、印字された金額を1行とする金額の表の組で出す。CSVの原典は原文の行と1対1の表のまま取り込み、ノードの形への変換は後段で行う（[ADR 0020](../../../../docs/adr/0020-ingestion-outputs-node-tables.md)）。列の定義は [dbt モデルの設計](../../../../docs/prd/fiscal-dbt-models/design-doc.md#取り込みの出力-ノードの表と金額の表)、保存と管理JSONは [保存設計](../../../../docs/prd/ingestion-storage/design-doc.md) を正本とする。
- 見出しは原文を保持する。項目が印字された欄の見出しをノードの軸、段の見出しの印字を段の見出し、金額が印字された欄の見出しを上位から「／」で連結した文字列として必ず持つ（金額だけの欄に見出しがなければ、印字された説明などの欄の見出し）。見出しを確かめられない金額は保存しない。読み取れなかった金額と所属を確認できない項目は行を作らず、件数を管理JSONの `tables[]` に持つ。こちらで単位や共通分類の名称を付け足さない。単位は金額の行ごとに原典の単位の原文を持つ。会計名と原典由来の注記は表の単位の事実として管理JSONの `tables[]` に置き、行へ反復しない。ノードと金額は、それぞれ印字された物理頁と、印字範囲を囲む矩形の座標を持つ。座標は表示頁（CropBox・回転を反映した後）の左上を原点とするPDFのpoint単位に揃え、OCRの座標は元の頁の座標へ戻して入れる。座標は原典で探し直すために持ち、親子の判定の根拠にはしない。未確認の値を推定で補わず、段の名前・金額の段階への対応、集計方法・換算倍率・共通分類は後段へ残す。
- 原典で確認できる所属・階層は取り込みで組み立て、ノードの親として出力する。末端の行に祖先の名称・金額を反復する横持ちの表にしない。款・項・目のノードは同じ会計の各表に含め、各表を款を根とする木にする。目に属する独立した説明・節の一覧・財源内訳は、それぞれ別の軸の枝にし、一つの枝に混ぜない。所属を確認できない項目は親を推定せず、検査結果に未確認として残す。節への対応が未確認の説明を、特定の節の内訳と解釈しない。ヘッダーや全単語・座標まで反復する `context_json` を作らない。
- 空文字、NULL、印字された0、読み取れなかった値を区別する。OCRの観測がないことを、原典が空欄である根拠にしない。
- 取り込み表は型を明示して直接Parquetに保存する。同じ表のCSVは併出・中継せず、閲覧にもParquetを読む。原典CSVは別にそのまま保持する。
- 原典の行・頁・位置との対応を表または観測表に残す。PDFの物理頁番号と印刷頁番号は分ける。原典に印字された行番号と、抽出時に生成した観測IDを区別する。生成IDは観測・検査内の参照に使い、rawの原典値として扱わない。表ID・単位・欄の意味は原典で確認できた範囲で記録する。
- 指定されたローカル出力先にParquetを生成し、既存の表を上書きしない。変換結果に原典ID・表ID、ファイルのパス・SHA-256・サイズ・行数、抽出コード・layout設定への参照を対応付ける。独立した `provenance.json` は作らない。変換モジュール単体はR2や管理JSONを更新せず、管理側のCLIが取得・保存を行う。保存構造と移行は [保存設計](../../../../docs/prd/ingestion-storage/design-doc.md) を参照する。
- Bの終点は取り込みParquetと再抽出に必要なコード・書式設定、変換時の未確認事項。原典情報の一覧・`sources.toml`・固定入力一覧の管理、dbt、分類、採用はこの変換処理の責務に含めない。

## Aの保存済み原典を受け取る

1. Aから対象の選定情報と保存記録を受け取る。未選定・未保存・対象未確定の候補では開始しない。選定台帳全体をcontextへ出さず、対象だけを取り出す。
2. 呼び出し側が保存記録の原典をローカルへ用意する。Bは公式URLから再取得せず、取得済みファイルのSHA-256を保存記録と照合する。不一致は原典の差し替えとして停止し、現在の台帳へ勝手に合わせない。
3. 対象JSONと原典SHAからローカルパスへの対応を `ingestion:convert` へ渡す。実行入口が現在の選定・保存記録とscopeを検査し、原典のSHAを照合する。分冊は別原典として保持し、会計名・非連続の物理頁範囲・text/scanの指定を受け渡す。TypeScript側から個別に受け渡す場合は `pipeline/ingestion/selection.ts` の `prepareIngestion()` を使う。
4. PDFは渡された歳出の頁範囲だけを処理する。範囲内の文字層の状態に応じて抽出方法を切り替え、年度・会計を再判定しない。CSVは書式別コードで原典の会計・方向の列に対応させる。`convert_csv()` 自体は行を絞らないため、複数会計・歳入／歳出を含むCSVは原典の全行を保持し、対象行の対応を別に明示する。対応できなければ未確認として停止し、列の値から会計を推測しない。
5. 一つの表は原典ファイル一つから作り、分冊を一つの表へ結合しない。分冊をまたいで続く款・項・目は、各分冊の表に同じノードを置き、後段で一つにまとめる。原典の頁番号は分冊ごとに1から数え、通し頁を原典頁として記録しない。別会計・独立した表では階層の文脈をリセットする。

`prepareIngestion()` 単体はローカル原典の対応検査までを行う。R2からの復元と表の保存・登録は管理側のCLIを使う。PDFの自動書式選択や、取り込み表の検査・dbtへの採用をこの関数に任せない。

## contextへ返す量を限定した実行手順

1. 原典ID・対象頁／表・書式設定・出力先を指定する。既存の書式設定とコードを再利用し、新しい書式だけ必要な代表頁を確認して設定を作る。
2. 読み取り・表の組み立て・変換・検査はコードで実行する。OCR観測・bbox・Poppler XML・取り込み明細・詳しい検査結果はファイルに保存し、全量をツール出力へ流さない。長い標準出力・標準エラーもファイルへ保存する。
3. 通常は成否、原典ID・表ID、処理頁数・行数、異常の種類と件数、出力情報・詳細ファイルの参照先だけを短く返す。`ConversionResult` を返すときも、明細やOCR観測を併せて表示しない。要約の件数は全対象からコードで計算する。
4. 異常や確認の必要がある場合だけ、頁・表・列・行／観測IDで絞って取得する。最初の明細表示は10件以内を目安にし、必要な範囲へ段階的に広げる。全量の保持と、contextへの表示量を分ける。目視確認は対象頁・領域に限定する。
5. 修正はコード・書式設定へ反映し、影響した範囲を再実行する。同じ全量データをcontextへ読み直さず、要約と対象範囲の確認を繰り返す。全量表示の明示的な依頼がある場合は、その指定に従う。

## CSV

1. 文字コード、区切り文字、引用符、ヘッダー、列数、複数行セルを確認する。文字化けや列数不一致を黙って読み飛ばさない。
2. 原典のデータ行と1対1の表を作る。値は文字列として取り込み、先頭の0・空欄・桁区切り・単位を失う型推論を避ける。重複行・合計行・説明行を勝手に削除しない。
3. ヘッダー付きCSVは共通の `convert_csv()` で変換する。変換後に原典を読み直し、列名・順序・型、全セル値、行順、空欄、重複行、物理行範囲をParquetと照合し、不一致なら保存せず停止する。候補dirの `<表ID>.checks.json` の成否・原典SHA・表SHA・行数を確認し、通れば取り込み完了とする。原典自体の合計一致や財政上の正しさは合否条件にしない。ヘッダーなし・前置き付きは書式別コードを使い、共通検査に合格済みとは扱わない。
4. CSVはノードの表にしない。款・項・目・節が別の列に並び、取り込みで復元する木がないため、原文の表のまま渡す。ノードの形への変換は dbt の intermediate で行う。

## text PDF

1. 対象頁を表示し、文字層から必要な本文を取得できるか確認する。頁番号だけが文字で本文が画像なら、本文はscan PDFとして扱う。
2. **Popplerの `pdftotext -bbox-layout` で単語と座標を取得する。** 通常の入口は単語単位とし、文字単位への再分割を標準処理にしない。単語は抽出器の区切りであり、日本語の意味上の単語とは限らない。
3. 文字層があるのに文字化けする場合は、文字対応表・フォントの復元を検討する。復元できない領域だけOCRへ回す。アウトライン化された文字もOCRの対象になる。
4. 生の単語・座標を保持し、次の「PDFの表の組み立て」でノードと金額へまとめる。

座標は原点、単位、CropBox・回転の扱いを記録する。異なる抽出手段を混ぜるときは、同じ表示頁の座標系へ変換してから対応付ける。

## scan PDF

### 文字・位置を取得する

1. OCRは **共通入口** `pipeline/ingestion/lib/scan_ocr.py` を通して行う。既定はPaddleOCR small、Apple Visionは `backend="vision"` で選べる。原典別の抽出器にエンジン呼び出し・画像描画・座標復元を複製しない。入口と設定の詳細は [モジュールの説明](../../../../pipeline/ingestion/lib/scan_ocr.md) を参照する。
2. 対象の物理頁・領域を指定し、300dpiを初期条件にする。表示上のCropBox・回転を反映して描画し、切り出し後の座標を元の頁へ戻す。
3. Paddleは **PP-OCRv6 small、検出長辺1280px、原解像度で文字認識** を初期条件にする。この条件だけで全セルの文字保持を保証しない。観測のないセルは下記の欠落セル再読へ、検出済み名称の誤読は意味照合による補正へ進む。必要な見出し帯・セルの再読領域は原典別に宣言し、原画の切り出しで読む。前後のnative出力・採用した観測・座標、版・固定モデルSHA・描画条件・読み取り領域を保持する。Appleを選ぶ場合は **accurate、revision 3、日本語・英語** を初期条件にし、OSの版・build、revision、言語補正も記録する。Appleの内部重みは固定できるとは扱わない。
4. Appleの `usesLanguageCorrection` をonにする場合は、コードと別管理の `ocr_vocabulary.json` を `customWords` に渡す。辞書は正しい名称の候補であり、認識成功や単独の0の検出を保証しない。Paddleの原文をこの辞書で自動置換しない。
5. 原典の列・表領域を確認して切り出し、文字列・観測枠・単語／数値の部分枠を取得する。頁全体のOCRだけで、すべてのセルを検出できたとは判断しない。
6. OCRの `raw_text`、候補のconfidence、観測ID、読み取り領域、元の頁での座標を保持する。枠が取れない文字も捨てず、座標なしとして残す。親候補から引き継いだconfidenceを文字単位の精度と解釈しない。

OCRモジュールは文字と位置を返す。**表の列・セル・階層の検出は別の処理**で行い、OCR出力をそのまま完成した表とは扱わない。表や階層を生成するVLMはこのフローの標準経路にしない。

### 文字観測がないセルを再読する

単独の0などが初回OCRで観測されない場合は、次の順で再読する。

1. **OCRとは独立にセルの範囲を決める。** 罫線・表の列配置・行境界から金額セルを特定する。罫線がない表は書式宣言や原典確認を使い、不確かなセル範囲は未確認として残す。正解の数値を見て再読対象を選ばない。
2. 初回は表・列の領域で読む。セルと観測枠を対応付け、文字観測がないセルを再読候補として記録する。未検出候補には本当に空欄のセルも含まれる。
3. **欠落セルだけ、内側を小さく切り出して同じOCRモジュールへ渡す。** 罫線を避ける余白を設定し、初回の正常な観測は保持する。全セルをセル単位のOCRに置き換えない。
4. 得られた文字と枠を元の頁へ戻し、同じセルの再読観測として追加する。初回と再読の対応・設定・結果を残し、重なった観測を重複加算しない。
5. まだ読めない場合は、切り出し範囲・白い余白・拡大率を変える有限の再試行を行う。条件と回数の上限を先に定める。
6. 上限後も観測がないセルは未検出のまま残し、原典確認へ渡す。**空欄を0で埋める、合計に合う数字を推測する、`customWords`で0を強制する処理は行わない。**

### 検出済み名称は意味を照合してから再読する

名称の字形誤読や中点の差を見つけても、すぐcrop再読へ回さない。観測のないセルや数値の誤読は、名称補正とは分けて扱う。

1. **確認済みの共通訂正辞書を先に照合する。** 既知の科目・法定節の名称、欄の役割、節番号、所属の文脈から候補を絞る。「徵収費→徴収費」「負担金·補助及び交付金→負担金・補助及び交付金」のような、確認した誤読パターンは適用条件とともに共通辞書へ蓄積し、条件が合う別PDFでも再利用する。認識エンジン・モデル版による違いも適用条件に含める。原典・セルを限定する個別訂正は、その原典だけの例外に使う。
2. 辞書にない場合は、既知名称とOCRの混同パターンを意味的に照合する。候補が一意に決まり、観測済み文字の字形差で説明できる名称は、crop再読を省いて補正候補を作れる。新しい科目名・説明文を生成したり、名称から金額・単位・所属を補ったりしない。
3. 候補が複数ある、辞書の適用条件が合わない、誤読か原典の表記か区別できない場合だけ、該当領域をcropして再読する。解決しなければ未確認として原典画像の確認へ渡す。
4. **意味の一致だけで原典の字形まで確認済みとしない。** 旧字・異体字・句読点の一括置換で原典を標準語形へ揃えない。原典に「高齡者」と印字されていれば「齡」を保持する。補正箇所は原典字形と適用条件を確認し、誤った補正は撤回する。
5. nativeの元文字・観測ID・頁・座標を上書きせず、補正前後、適用したルールと辞書の版またはSHA、理由と確認範囲を残す。訂正辞書は認識器へ渡す語彙辞書とは区別する。

共通の後処理は [ocr_names.py](../../../../pipeline/ingestion/lib/ocr_names.py)、確認済みの名称パターンは [節名称辞書](../../../../pipeline/ingestion/lib/fiscal_setsu_name_corrections.json) と [科目名辞書](../../../../pipeline/ingestion/lib/fiscal_subject_name_corrections.json) を使う。番号を含む欄は呼び出し側で番号を分離し、名称全体だけを渡す。原文の空白・折り返しを保つ場合は `correct_name_preserving_layout` を使い、文字数が変わる規則の `layout_policy` も記録する。

これは名称補正の手順であり、共通辞書の自動適用が全抽出器に実装済みという意味ではない。

### 前処理と再試行の判断

- `minimumTextHeight` は指定値と実際の値を記録する。初回から0なら、さらに下げて改善する余地はない。大きく設定すると小さい文字を落とす可能性がある。
- 罫線除去は標準処理にしない。試す場合は元画像を保持し、文字の欠損・未検出・数値の不一致を比較する。
- 全頁の高解像度化・全セルの再読より、欠落領域だけの再読を先に試す。描画・OCR・再試行それぞれの時間を測り、再読対象が多い場合は列・セルの設定を見直す。
- 画像や設定を変えるときは、変更済みの条件にだけ再実行を限定する。キャッシュのキーには原典SHA、頁・領域、描画条件、OCR設定・版、辞書のハッシュを含める。

## PDFの表の組み立て（text / scan共通）

単語・OCR観測から行・列・階層を組み立てる処理は、Pythonコードと書式別の宣言にする。共通処理には `pipeline/ingestion/lib/pdf_table.py` を使い、列境界・見出し・見開きなど書式の違いを宣言で指定する。[共通モジュールの使い方](../../../../docs/pdf-table-module.md)を参照し、新しい書式では原典を確認してコード・宣言を作り、対象頁で検査してから同じ書式へ適用する。

layoutは年度・会計ではなく書式ごとに管理する。年度・会計が違っても列配置・見出し判定・階層表現が同じなら再利用し、設定値の違いで対応できる場合は同じ処理へ設定を渡す。書式の規則が変わる場合は別のlayoutにする。一つのPDF内でも頁・表ごとに書式が違えばlayoutを切り替える。年度・会計は上流から受け取り、layoutから推定しない。別会計・独立した表へ移るときは階層の文脈をリセットする。

LLMを使う場合は、このコード・宣言の作成と修正を支援させる。取り込み実行時に、各PDFの行・金額・階層を毎回LLMへ生成させない。

1. **見開きが1つの表なら、左右の単語・観測を共通座標系へ合わせてから行にまとめる。** 頁ごとに作った行番号で結合しない。折り返しの違いで左右の行数が一致しないため、表の基準線・列を使って対応させ、元の頁・座標も保持する。
2. 原典で列の役割を確認し、名称・金額・節・説明欄を区別する。ヘッダーも原典の文字・位置から構築し、複数段・結合範囲・単位と本文列への対応を保持・検査する。列名とx境界を手動指定しただけでは、この対応を確認したことにしない。固定したx境界だけで長い名称や桁の多い金額を切り捨てない。罫線、配置、文字の並びを合わせて判断する。
3. 款・項・目の見出しを取り、その文脈を同じ会計・表の明細へ継承する。継続頁の再掲見出しで文脈を消さず、見出しの変更・表や会計の終了で更新する。
4. 事業・説明の階層は、字下げ・番号・罫線・金額の配置を原典で確認して復元する。階層数や名称の意味を自治体共通の固定ルールにしない。名称の左端や金額の右端だけで一意に決めない。
5. 名称の折り返しは位置と文脈を確認して結合し、説明文・積算根拠を名称に混ぜない。折り返しが終わってから名称を確定する。原文も保持し、名称に含まれる数字を通し番号だと推測して削除しない。
6. **法定節一覧と事業・説明欄は、内部の構築・検査で独立して扱う。** 印字行番号・y座標を使って節と説明を結合しない。見開きの共通座標は文字の配置のために使い、意味上の関係の根拠にはしない。説明内に確認済みの節見出しがある場合は、事業・節・細目の親子関係と同じ目の節一覧への対応を保持する。対応が未確認なら、確認済みの目への所属と説明内の経路までを保持する。保存する取り込み表では、説明内の各段の項目をノードにし、親子で階層を表す。原典で名称・金額が一つの欄に印字されていても、JSON・配列・STRUCT列に格納しない。法定節一覧は説明とは別の軸の枝にし、境界で継続中の項目は検査用の観測として保持する。説明内の段を節と名付ける解釈は後段の宣言で行い、原典の見出し・値に混ぜない。対象ページだけでは末端を確定できない項目は検査結果に未完了として示す。抽出元の欄や範囲の終了状態など、抽出・検査の状態を原典の値として追加しない。欄はノードの軸、終了状態は観測と検査結果へ残す。説明の項目金額と法定節総額を区別し、同じ高さの行や名前だけから配賦された内訳を作らない。
7. 内訳がない目も残す。集計値と内訳は区別して保持し、同じ金額を二重に加算しない。不明な階層や対応は推測で埋めず、原典で確認できる粒度を出す。

法定節一覧と説明欄を別に構築することは、説明欄内に節の区分がないという意味ではない。説明が「事業→節→細目」を印字している場合は、その節見出しと細目への所属を保持する。目の全範囲と継続頁を確認し、説明内の節別金額を目×節へ集約して法定節一覧と照合する。名称だけ・同じ高さの行だけでは対応を確定せず、原典内の節名称・区分の対応、階層、対象範囲、節別金額の一致を合わせて確認する。財源内訳は別の分解であり、原典に事業・細目ごとの配分がなければ結合して配分額を作らない。今回の局所確認と適用範囲は [共通モジュールの説明](../../../../docs/pdf-table-module.md) を参照する。

組み立てたノードと金額は型を固定し、`pipeline/ingestion/lib/conversion.py` の `write_conversion()` に渡す。内部で `parquet.py` による保存を行い、ローカルの出力情報を返す。表IDに対応する戻り値は、ノードの表と金額の表のパスと、表の会計名・notesにする。移行前の横持ちの表を出す既存の変換器は、パスとmetadataの戻り値を使える。既存の表は、横持ちの表とmetadataからノードの表と金額の表を作る共通の変換で移行する。未割当の観測も保存して受け渡す。PDFの読み取り・表の組み立て・Parquetの保存を別の処理として扱い、書き出し時に金額や階層を推論しない。

「最小の構築」の対象が少数ページなら、ページ数を限定して本来の取り込み構造を作る。ヘッダー、名称の折り返し、階層、独立した表の分離を省いた印字行グリッドを、取り込み完了と扱わない。範囲末尾で続く階層は継続中として保持し、閉じた範囲の検算と区別する。見開きtext PDFの実装例は [statement/text_spread.py](../../../../pipeline/ingestion/fiscal/layouts/statement/text_spread.py)、今回の適用範囲は [共通モジュールの説明](../../../../docs/pdf-table-module.md) を参照する。

## PDFの金額検査

PDFは原典の内部で重複して印字された数字どうしの一致で確かめる。保存した候補Parquetを読み戻し、階層ごとに「直下の内訳の合計＝原典に印字された親の金額」を照合する。

| 集計する内訳 | 比較する原典の金額 |
| --- | --- |
| 説明欄の末端明細（確認済みの所属で目・節ごとに集計） | 同じ目の法定節一覧の節額 |
| 同じ目に属する節額 | 目の金額 |
| 同じ項に属する目の金額 | 項の金額 |
| 同じ款に属する項の金額 | 款の金額 |

- 同じ会計・金額段階・金額列・単位の中で、名称ではなく所属経路で比較する。反復した親の金額は親ごとに一度だけ数え、`SUM(DISTINCT 金額)` は使わない。小計と内訳、独立した分解（法定節一覧と説明欄・財源内訳）を足し合わせない。
- 結果は一致／不一致に加え、継続頁・未読・所属未確認は「保留」、比較する印字合計や完全な内訳がない場合は「検算不可」とし理由を残す。欠けた金額を0で補わない。
- 合計一致では名称の欠損や同額の取り違えを検出できない。名称・未読セル・欠落・二重収録は、合計が合わない箇所と補正した箇所を中心に原典で確認する。OCRの未検出・誤読・表への対応未確認は分けて報告する。
- 不一致・保留・検算不可を一覧にして原因（欠落・二重収録・誤読・誤所属・範囲不足・原典の不整合）を切り分け、下の手順で修正して影響範囲と上位階層を再検査する。同じ問題が2回程度の修正で解消しない場合は、階層・粒度・継続頁・単位と検査側の集計キーの前提を原典で見直す。合計を合わせるための推定・配賦やParquetの直接書き換えはしない。
- 金額セルを科目番号・積算根拠と区別し、年度・会計・単位・金額段階・当年／前年の列を原典の見出しと照合する。補正は基準額・増減額・補正後額を区別し、未収録の変更を0にしない。
- 共通の検査は `bun run ingestion:verify --manifest <JSON>`（候補は `--candidate <候補dir>`）。表ごとの階層・識別キー・比較列は管理JSONと対になる `jurisdictions/<団体>/sum_checks/<年度>/<資料区分>/<方向>.json` に宣言する。検査の宣言は表の作り方を変えないため、fingerprintに入るconverter optionsや、変換器が出す管理JSONのmetadataには置かず、表を保存し直さずに直せるよう分けている。型は [sum_check.schema.json](../../../../pipeline/ingestion/fiscal/sum_check.schema.json)、判定は [sum_check.py](../../../../pipeline/ingestion/fiscal/sum_check.py) を正本とする。原典で印字なしと確認した空欄は `blank`、抜粋の資料は `excerpt`、比較できない表は `uncheckable` に理由を書く。詳細は `.build/ingestion-verify/` へ出力され、標準出力は表ごとの件数だけになる。
- 不一致・未宣言・宣言不整合があれば終了コード1になるが、保存（`ingestion:convert --remote`）を自動では止めない。保存前に候補で実行し、CSVと同じ保証にはしていない。保留は継続頁・未読・所属未確認として理由付きで残せる結果のため終了コードでは失敗にせず、件数と理由を詳細で確認する。

## 誤りが見つかったときの修正

1. 原典と観測を確認し、文字の未検出・誤読、セルや階層への誤割当、原典自体の空欄を区別する。合計の不一致だけで欠落セルや訂正値を決めない。
2. 検出済み名称の誤読は [意味照合による補正](#検出済み名称は意味を照合してから再読する) を先に行い、一意に決まらない箇所を再読する。未検出や数値の誤読は対象領域の読み取り条件を見直して再読する。誤割当は書式別の列境界・行結合・見出し判定を修正する。共通化できる処理はモジュールへ置き、Parquet書き出しへ原典別の例外を追加しない。
3. 再読・ルール修正で解消しない値は未解決として残す。原典を確認した個別訂正が必要な場合は、原典SHA・物理頁・セル枠・取得済みの観測IDで対象を限定し、訂正値と理由を宣言で別管理する。元の文字・観測なしの状態を上書きせず、印字が確認できない値を推測しない。
4. 修正対象の表を組み立て直し、新しい候補Parquetへ保存する。採用済み入力は上書きしない。影響する範囲で保存・読み戻しと合計検査を再実行し、同じ書式の他の表への影響も確認する。

## 変換結果の受け渡し

`ConversionContext` で、原典ID・表ID、抽出コード・layout設定への参照を渡す。Aからの入力では `prepareIngestion()` の選定参照と、使用した全原典の保存参照を渡す。変換が複数の原典を受け取る場合は、表ごとにどの原典から作ったかを対応させる。型は [conversion.py](../../../../pipeline/ingestion/lib/conversion.py) を参照する。`convert_csv()` と `write_conversion()` は、これらの参照とParquetのローカルパス・SHA-256・サイズ・行数を `ConversionResult` として返す。`dataclasses.asdict()` でJSONにできる辞書へ変換できる。

年度・会計等を推定・定義せず、受け取った対象・scopeと変換結果を表IDで対応させて管理側へ渡す。変換器は `convert(inputs, destination, options)` と同じフォルダの `options.schema.json` を定義し、表IDとローカルParquetの対応を返す。変換器からGitの管理JSONやR2を更新しない。型と制約は [管理schema](../../../../pipeline/ingestion/fiscal/manifest.schema.json) と [実行時検査](../../../../pipeline/ingestion/fiscal/manifest.py) を正本とする。

## 管理JSONを確認して変換する

1. `pipeline/ingestion/fiscal/jurisdictions/<団体>/<年度>/<資料区分>/<方向>.json` に入力SHA、変換コード・設定、期待する表を定義する。形式・会計・ページ範囲はselectionから解決する。複数原典・複数変換・複数表は同じ対象のJSONへまとめる。
2. `pipeline/` から `bun run ingestion:check --manifest <対象JSON>` を実行する。型・正規配置・選定との対応・表IDの所有者が不正なら修正してから進む。
3. 原典のSHAからローカルパスへの対応JSONを渡す。原典の復元が必要なら `bun run ingestion:originals --manifest <対象JSON> --output <入力パスJSON> --remote` を使う。
4. `bun run ingestion:convert --manifest <対象JSON> --inputs <入力パスJSON> --output <新しい候補dir>` を実行する。件数とファイルパスだけをcontextへ返し、表・OCR・検査の詳細はファイルへ保存する。
5. CSVは自動保持検査の結果を確認して保存へ進む。PDFは候補Parquetと未確認事項を原典照合へ渡す。R2へ保存する場合は次の手順へ進む。

## 現在版の保存・差し替え

1. 管理側から現在の選定・scope・設定を受け取り、入力条件を確定する。同じ対象の原典更新・変換・保存・後段処理は順番に実行し、並行更新しない。原典はAの保存先を使用し、Bで別の原典領域へ複製しない。
2. 必要な全表をローカルで生成・検査する。異常の詳細はファイルに保存し、件数と対象だけを返す。
3. 新しい候補dirを指定し、`ingestion:convert` に `--remote` を付ける。入力条件が変わっていないことを確認し、管理側の保存処理が対象の方向の領域へ全表を上書き保存する。新しい補助入力のR2保存は未実装であり、必要なら保存方法を先に実装する。
4. 期待する表と処理済み・未処理範囲を確認し、全アップロード成功後に管理側が表の管理情報を更新する。局所再処理では、変更しない表の参照も保持する。未処理・欠落や未確認の0行を、表の廃止として扱わない。失敗時は後段へ進まず、同じ入力条件で必要な全表を再保存する。
5. 対象かつ指定した方向のingestion領域だけを全ページ一覧取得し、現在の管理情報が参照しない直下のParquetを削除する。削除直前にも現在の参照を確認する。同じkeyの表は上書き済みなので別途削除しない。掃除に失敗したら `bun run ingestion:cleanup --manifest <対象JSON>` を実行する。別年度・別補正号・別方向を削除しない。
取り込みは表と管理情報の保存・差し替えまでで完了する。保存済みの管理情報とParquetの読み込み、入力条件・SHA・サイズの照合はdbt側の入力準備で行う。保存途中の表を読み始めない。

保存キー・管理情報の置き場は [設計書](../../../../docs/prd/ingestion-storage/design-doc.md) を参照する。局所再処理は `--conversion <ID>` を使い、変更しない表が現在の条件と一致していることを確認する。
