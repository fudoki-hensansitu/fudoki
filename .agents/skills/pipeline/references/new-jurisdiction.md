# 自治体を取り込む

1自治体の予算・決算（歳出・歳入）・事業評価を、調査から PR まで1本の流れで取り込むときの方針。各工程のやり方は工程の reference とコードにある。

## 取る範囲

- 資料は当初予算・決算・事業評価。予算・決算は歳出と歳入を同じ流れで取り込む。補正予算は取らない。
- 選定した資料が款だけの表（審査意見書の款別の表など）でも、款の粒度で取り込む。項・目の載る資料が無いことを見送る理由にしない。
- 年度は R6〜R8 を必ず選び、同じ様式（同じ宣言で読める）で公開されている過去の年度も足す。様式が変わる年度の手前で止め、資料の種類ごとに判断する。公開されていない年度は欠けたままにする。
- 読み方を別に書く必要がある様式の会計も、宣言・quirk・共通コードを足して取り込む。どうしても読めないときは選定の scope だけ入れて見送る。取り込んでいない選定は選定の一覧から分かるので、issue は立てない。

## 進め方

- 選定より前に自治体マスタ（`packages/jurisdictions/jurisdictions.json`）へ登録する。
- 最初に公開の頁を調べ、資料ごとの年度・様式・会計を1表にして、取る範囲を依頼者へ1回だけ伝える。
- 1年度・1会計で読み方を固めてから、同じ宣言を他の年度・会計へ写す。
- 歳入は歳出と同じ冊・同じ様式なら歳出の宣言を写し、歳入の頁で違う欄だけを足す。説明・備考は節の内訳ではないので、除外の種類「歳入の説明」で外す（[歳入の設計](../../../../docs/prd/fiscal-revenue/dd.md)）。
- 待ち時間の長い OCR は早く始め、その間に text PDF・評価を進める。
- 款の和を、出典に印字された歳出合計・歳入合計（会計別の総括など）と全会計で突き合わせる。
- 1つの書式だけの読み方は宣言（`quirks` など）に書き、他の自治体にも効く直しは共通コードに入れる。
- 決めたこと・取れなかったものは自治体の README に残す。
- 手元では、変換した表の検査と、その自治体だけの dbt build までを確かめる。全表の作り直し・R2 への保存・本番への反映は CI に任せる（[workflow](workflow.md#手元で確かめることと-ci-に任せること)）。

## 取り込み済みの自治体に歳入を足す

- 歳出だけを取り込んだ自治体には、歳入を自治体ごとに1 PR で足す。年度・会計の範囲は取り込み済みの歳出に揃える。
- 歳入の頁が選定の範囲に無い（別冊・同じ冊の別の頁）ときは、その冊・頁を選定に足して保存し直す。歳入を載せる資料が無い年度・会計は欠けたままにする。
- 企業会計のように歳入の款の形を持たない会計は取り込まない。
