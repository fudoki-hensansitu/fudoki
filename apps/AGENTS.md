# apps

公開 web は**入口の1枚**（`/` の紹介・`/favicon.svg`・`/robots.txt`）と、そこから始める**風土記の AI との会話**（`/s/:id` と `/api/*`）を返す（他は 404）。その頁が使う重いファイル（録画・出典の切り抜き）と会話の画面の JS・CSS（build で作る `static/_app/`）は `web/static/` に置き、Workers static assets で配る。D1 などのデータの binding は持たせず、データは apps/api の MCP に Service Binding で問い合わせる。ディレクトリ掲載の作者 URL に使う。API・MCP は ADR 0022 の構成（Worker + D1）に置き換わった。`availability.test.ts` が web の応答を確認し、root の `bun run test` から実行される。

- `api/`（`@fudoki/api`）: Cloudflare Workers + D1。`src/operations.ts` で操作を一度だけ定義し、`src/app.ts` が REST（`/v1/expenditure/*`・`/v1/jurisdictions`、`/openapi.json`）と MCP（`/mcp`）に登録する。検索の入力（構造化 JSON）の schema と SQL の組み立ては `src/search.ts`、MCP Apps の View（結果の表）は `ui/` で、`bun run --cwd apps/api view` が bundle して生成物 `src/view.generated.ts` に書く（手元の古い `node_modules` を bundle が拾うと CI の再生成と食い違うので、`bun install --frozen-lockfile` の状態で作り、`bun run --cwd apps/api ui/build.ts --check` で一致を確かめる。`view.test.ts` も同じ検査をする）、D1 の migration は `migrations/`、公開列の契約は生成物 `src/columns.json`。事業の評価の検索（`src/evaluations.ts`、設計は `docs/prd/evaluation-search/dd.md`）は、AI Search の binding で頁単位の候補を引き、出典の所在と軽微な抜粋だけを返す（頁の本文は返さない）。`operations` の一覧の末尾に登録済みで、REST・OpenAPI・MCP の tool（`search_evaluations`）に出る。止めるのは `control` の `evaluation_search`（`off` の間は 503）。plugin の skill の手順は `plugins/fudoki/skills/compare-expenditure/references/evaluation.md`。処理の順は kill switch（`control` の `serving`・`evaluation_search`）→ 収録の確認 → IP の流量（rate limit binding）→ 全利用者の回数（`src/evaluation-quota.ts` の Durable Object `EvaluationSearchQuota`）→ AI Search で、`control` の `evaluation_search`（初期値 `off`）・`evaluation_search_per_minute`（30）・`evaluation_search_per_day`（1000）で止める・上限を変える。描画できる tool を変えるときは `apps/web/server/chat.ts` の SYSTEM も同じ commit で直す（描画 tool の名前と enum は `operations.ts` の `view` から作られるが、SYSTEM の文面は手書きで、片方だけ古いまま残った例がある）。デプロイ・運用のハマりどころは `.agents/skills/cloudflare-api-ops/`
- `web/`（`@fudoki/web`）: Cloudflare Workers。`deploy/cloudflare.config.ts` が `../worker.ts` を entrypoint にし、入口の1枚（`landing.ts`）と AI との会話を返す。会話は入口の入力（React の島）→ Turnstile → `/s/:id`（React の SPA）で、`server/` が Workers AI と apps/api の MCP（Service Binding）を繋ぎ、結果は apps/api の MCP Apps の View を sandbox の iframe に描く。会話は保存せず、利用状況だけを Analytics Engine に書く。構成・上限・手で設定するもの・集計の SQL は `web/README.md`。brand・map の資産生成（`build:brand` / `fetch:boundaries`）はこの package の script。DESIGN.md とデプロイ後の確認は `.agents/skills/web-frontend-ops/`
- `docs/`（`@fudoki/docs`）: API・MCP の利用者向け文書（docs.fudoki.dev）。Blume で `content/` の MDX を静的に書き出し、Worker のコードを持たない assets だけの Worker で配る（`workers.dev`・preview URL は閉じる）。API リファレンスは build の前に `apps/api` の route 定義から書き出す `openapi.json`（`apps/api/openapi.ts`）から生成するので、操作の説明は `apps/api/src/operations.ts` を直す。ページに書くのは接続方法・データの読み方など schema に無いことだけ

## 公開 web の配信

**公開 web は `https://fudoki.dev/` で配信する。** これは派生物であって正本ではない。公開 web の絶対 URL（`canonical` / `og:image`）はこのドメインを指す。

- 置き場は Cloudflare。
- 配信は Cloudflare Workers（`web/deploy/cloudflare.config.ts`、domain は `fudoki.dev`）。現在は `web/worker.ts` が入口の1枚を返す。main に入ると `.github/workflows/deploy-web.yml` が自動でデプロイする（手元からは `bun run --cwd apps/web deploy`）。web を変える PR は `.github/workflows/preview-web.yml` が Worker Previews で `pr-<番号>.fudoki.dev` に出す（PR を閉じたら消す。fork の PR は出さない。preview は Cloudflare Access の「fudoki previews」で Cloudflare アカウントのログインだけを通す。Access の宛先はホスト名のパターンでなく Worker 単位の `preview_worker` にする — Deployment URL は `abc123-pr-12.fudoki.dev` のように前置きが付き、ホスト名のパターンでは当たらない。検索エンジンも Access で止まるので noindex は付けない）
- build/deploy は公開 app のコードだけを扱い、dbt・出典の全量生成は実行しない
- api・docs は main に入ると GitHub Actions がデプロイする（`.github/workflows/deploy-api.yml`・`deploy-docs.yml`、パスで対象を分ける）。認証は repo の secret `CLOUDFLARE_API_TOKEN`・`CLOUDFLARE_ACCOUNT_ID`。手元の `deploy:*` は手動で出し直すときだけ使う。D1 の migration とデータの投入は自動では行わない
- 公開 app は `pipeline/` を import しない（`pipeline/verify/boundaries.ts` が検査する）
