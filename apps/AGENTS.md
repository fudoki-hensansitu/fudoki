# apps

公開 web は**ホーム**（`/`。うちのまち・見られる情報・更新への入口）と**紹介の読み物**（`/about`）、`/favicon.svg`・`/robots.txt`、サイドバーの「アシスタント」（`/assistant`）から始める**風土記の AI との会話**（`/s/:id` と `/api/*`）、**自治体の頁**（`/jurisdictions`・`/tokyo/nakano`）を返す（他は 404）。ファイル（icon・録画・出典の切り抜き）は `web/public/` に置き、Workers static assets で配る。D1 などのデータの binding は持たせず、データは apps/api の MCP に Service Binding で問い合わせる（例外は web 自身のデータ（今は会話の保存）を書く D1 `fudoki-web`、binding `DB`）。ディレクトリ掲載の作者 URL に使う。API・MCP は ADR 0022 の構成（Worker + D1）に置き換わった。`web/server/availability.test.ts` が web の配るファイルと PWA の繋ぎを確認し、root の `bun run test` から実行される。

- `api/`（`@fudoki/api`）: Cloudflare Workers + D1。集約ごとの dir（`src/jurisdiction/`・`src/expenditure/` など）に型（`model.ts`）・問い合わせ（`queries.ts`）・REST の route（`routes.ts`、`@hono/zod-openapi` で書き下ろす）・MCP の tool（`tools.ts`）を置き、`src/rpc.ts` が route をまとめて型 `AppType` を export する（web は `@fudoki/api/rpc` を import し、Hono RPC の `hc<AppType>` を Service Binding の fetch で呼ぶ）。`src/app.ts` が middleware・MCP（`/mcp`）・`/openapi.json` を持つ（REST は `/v1/jurisdictions*`・`/v1/expenditures/*`・`/v1/evaluations/*`・`/v1/budget-proposals/*`・`/v1/projects*`）。設計は `docs/prd/aggregate-api/dd.md`。検索の入力（構造化 JSON）の schema と SQL の組み立ては `src/shared/search.ts`、MCP Apps の View（結果の表）は `ui/` で、`bun run --cwd apps/api view` が bundle して生成物 `src/gen/view.ts` に書く（`src/gen/` は commit しない。依存の更新のたびに生成物の差分が出て CI が落ちていたため。`test`・`typecheck`・`dev`・`deploy`・`openapi` の script が先に作り直すので、生成物を import する script を足すときは同じく `bun run view &&` を前に付ける）、D1 の migration は `migrations/`、公開列の契約は生成物 `src/columns.json`。出典の頁の文字を読む内部の RPC `SourcePages`（`src/source-pages-entrypoint.ts`、処理は `src/source-pages.ts`）は HTTP の route・MCP に載せず、web だけが Service Binding（entrypoint）で呼ぶ。R2 の binding `SOURCE_TEXT`（`fudoki-inputs`）はこの RPC だけが `get` で使い、key は出典の記録に照らした sha256 から組み立てる（設計は `docs/prd/source-reading/dd.md`）。描画できる tool を変えるときは `src/app.ts` の `RENDER_DESCRIPTION` も同じ commit で直す（描画 tool の enum は tool の `view` から作られるが、description に並べた tool の名前は手書き）。デプロイ・運用のハマりどころは `.agents/skills/cloudflare-api-ops/`
- `web/`（`@fudoki/web`）: [Void](https://void.cloud/)（Vite）で build する Cloudflare Workers。設定は `void.config.ts`、build（`vite build`）が cf の Build Output（`.cloudflare/output/v0`）を書き出し、deploy・preview は cf がそれを読む。頁（ホーム・紹介・アシスタント・会話・自治体の一覧と個別ページ）は `pages/`（Void の Pages。layout のサイドバーを残したまま頁の間を SPA で移る）、API・sitemap・PWA は `routes/`。会話はアシスタントの入力 → Turnstile → `/s/:id` で、`server/` が Workers AI と apps/api の MCP（Service Binding）を繋ぎ、出典の頁を読む tool `read_source_page`（`server/source-pages.ts`、頁の文字は AI にだけ渡し画面と保存には出さない）を足し、結果は apps/api の MCP Apps の View を sandbox の iframe に描く。画面の会話の履歴はブラウザに置き、利用状況を Analytics Engine に、会話（質問と回答。復元と分析に使い、ログインしていない会話は90日）を D1 `fudoki-web`（binding `DB`）に保存する。構成・上限・手で設定するもの・集計の SQL は `web/README.md`。brand・map の資産生成（`build:brand` / `fetch:boundaries`）と、自治体の OG 画像の字形（`build:og`。画像は `/jurisdictions/<code>/og.png` を Worker が頁と同じデータから描く。字形は自治体マスタに自治体を足したとき・分野の名前を変えたときに作り直す）はこの package の script。DESIGN.md とデプロイ後の確認は `.agents/skills/web-frontend-ops/`
- `docs/`（`@fudoki/docs`）: API・MCP の利用者向け文書（docs.fudoki.dev）。Blume で `content/` の MDX を静的に書き出し、Worker のコードを持たない assets だけの Worker で配る（`workers.dev`・preview URL は閉じる）。API リファレンスは build の前に `apps/api` の route 定義から書き出す `openapi.json`（`apps/api/openapi.ts`）から生成するので、操作の説明は各集約の `apps/api/src/<集約>/tools.ts`・`routes.ts` を直す。ページに書くのは接続方法・データの読み方など schema に無いことだけ。見た目は `theme.css` で本体サイト（DESIGN.md の色・書体・薄緑のサイドバー）に揃え、icon は `public/icons/` の Phosphor（regular）の SVG を `/icons/<name>.svg` で指す（Blume の既定は Lucide）。`<img>` で出るので `theme.css` の mask で文字色に塗る。SVG を frontmatter や import で渡すと「Markdown としてコピー」・llms-full.txt に SVG や JSX が混ざるので使わない。ロゴは fudoki.dev への戻り口

## 公開 web の配信

**公開 web は `https://fudoki.dev/` で配信する。** これは派生物であって正本ではない。公開 web の絶対 URL（`canonical` / `og:image`）はこのドメインを指す。

- 置き場は Cloudflare。
- 配信は Cloudflare Workers（`web/void.config.ts`、domain は `fudoki.dev`）。main に入ると `.github/workflows/deploy-web.yml` が自動でデプロイする（手元からは `bun run --cwd apps/web deploy`）。web を変える PR は `.github/workflows/preview-web.yml` が Worker Previews（`cf previews deploy`。binding・var は `void.config.ts` の `preview` の分岐）で `pr-<番号>.fudoki.dev` に出す（PR を閉じたら消す。fork の PR は出さない。preview は Cloudflare Access の「fudoki previews」で Cloudflare アカウントのログインだけを通す。Access の宛先はホスト名のパターンでなく Worker 単位の `preview_worker` にする — Deployment URL は `abc123-pr-12.fudoki.dev` のように前置きが付き、ホスト名のパターンでは当たらない。検索エンジンも Access で止まるので noindex は付けない）
- build/deploy は公開 app のコードだけを扱い、dbt・出典の全量生成は実行しない
- api・docs は main に入ると GitHub Actions がデプロイする（`.github/workflows/deploy-api.yml`・`deploy-docs.yml`、パスで対象を分ける）。認証は repo の secret `CLOUDFLARE_API_TOKEN`・`CLOUDFLARE_ACCOUNT_ID`。手元の `deploy:*` は手動で出し直すときだけ使う。D1 の migration とデータの投入は自動では行わない
- 公開 app は `pipeline/` を import しない（`pipeline/verify/boundaries.ts` が検査する）
