# 自治体一覧の設計

要件は [PRD](prd.md) に置く。個別ページ・URL の決め方は `apps/web/README.md` の「自治体の個別ページ」が正本。

## 画面

上から「地図＋選んだ自治体のカード」「表」の順に置く（2026-11-05 に地図・表・区画タイルの3案を比べ、地図と表の組み合わせを選んだ）。

- **地図**: 「日本 › 東京都」の2段。日本は47都道府県のタイル地図（`jurisdiction/japan-tiles.ts`）を収録した市区町村の数で塗り、収録のある都道府県を選ぶとその都道府県の市区町村の地図に進む。最初は収録した市区町村がいちばん多い都道府県（今は東京都）を開く。市区町村の地図は、最新の決算の一般会計の歳出の総額で塗る。濃さは金額の平方根に比例させ（面積で見比べるため）、未収録は地の色で区別する。島しょは本土と縮尺を揃えると点になるので、本土の横に挿入図（伊豆諸島・小笠原諸島）として描き、本土の自治体と同じように塗って hover・タップで選べるようにする（地図にない自治体だけを地図の下のチップに出す。他の都道府県の自治体は混ぜない）。日本と都道府県の切り替えは View Transition で、選んだタイルが都道府県の地図へ拡大する（戻るときは縮む）。動きを減らす設定では切り替えるだけにする。
- **選んだ自治体のカード**: 総額・金額の大きい款3つ・収録年度・個別ページへのボタン。マウスは hover で選び、クリックで個別ページへ。指は1回目のタップで選んでカードを見せ、2回目で開く。
- **表**: 名前（ローマ字の slug でも当たる）で探す、種類（都道府県・区・市・町村）で絞る、総額か自治体コードで並べる。行は個別ページへのリンク。

区画タイル案（自治体の形のシルエットをカードにする）は採らなかった。見た目は良いが、数と金額の比較がしにくい。形のシルエットは、表の行や個別ページの見出しのアイコンとして後から使える。

## データ

`apps/web/server/jurisdiction.ts` の `loadIndex` が、収録の一覧（`/v1/jurisdictions`）から決算のある自治体を選び、最新の決算の年度が同じ自治体ごとに `nodes:search` で款をまとめて引く。総額は個別ページと同じ「一般会計の款の和」。1回の検索に載せる自治体は 60 まで（API の bind の上限 90 から年度・会計などの条件を引いた余裕）。結果は Worker の cache に1時間置く（収録の一覧と同じ TTL）。款が引けない自治体は 0 円と出さずに一覧から外す。

全国に広げると、款の行は「自治体数 × 款の数（約12）」になる（1,700 自治体で約2万行、1,000行ずつ約20回の検索）。その段階では、API の収録範囲に最新の決算の総額を持たせる（marts で集計する）ほうが軽い。

## 地図のデータ

境界の正本は `apps/web/public/<都道府県>.geojson`（`map/build.py` が国土数値情報 N03 から作る。東京都は自治体マスタの62自治体、他の都道府県は N03 の市区町村すべてを、検査数字を付けた6桁のコードで描き、政令市の区は市にまとめる）。数百KB の GeoJSON を Worker と画面に載せないよう、`bun run --cwd apps/web build:map` が投影（その都道府県の中央の緯度で経度を縮めた正距円筒）、800×560 の枠への収め、0.8px の単純化と 0.5px への丸めを済ませた SVG の path を `jurisdiction/map.generated.ts`（東京都・兵庫県で約84KB）に書き、それを commit する。島しょの挿入図は `PREFECTURES` の `insets` に自治体コードを並べ、240×300 の枠に収める。島の自治体はそれぞれ中心から 26px 以上に拡大し（真の縮尺では点になり選べない）、最大の島の 2% 未満の岩礁は落とす。小笠原村は父島・母島列島だけを `clip` で切り出す（沖ノ鳥島・南鳥島まで入れると枠が広がりすぎる）。都道府県を足すときは `map/build.py` の `OTHER_PREFECTURES` と `map-build.ts` の `PREFECTURES` に並べる。

## 全国に広げるとき

全国の市区町村（約1,740）を一枚の地図に塗ると、23区などの小さな区が潰れて選べない。全国版は2段にする。

1. **全国（`/jurisdictions`）**: 47都道府県のタイル地図（各都道府県を同じ大きさの四角で、おおよその位置に並べる）を、収録した市区町村の数で塗る（実装済み。今は同じ頁の中で都道府県の地図へ切り替える）。表は全国の自治体を並べる（今の表と同じ）。
2. **都道府県（`/tokyo`）**: その都道府県自体の財政（東京都自体の決算）と、都道府県内の市区町村の地図と表。今の一覧の地図と表は、都道府県を引数に取る形にしてここへ移す。境界のデータは都道府県ごとに `map/build.py` で作り、`build:map` で path にする。

検討して採らなかった案:

| 案 | 採らなかった理由 |
| --- | --- |
| 全国の市区町村を一枚の SVG で塗る | 小さな自治体が選べない。全国の path は数MB になる |
| MapLibre などの地図ライブラリとベクトルタイル | ズームで解けるが、依存とタイルの配信が増える。都道府県で区切れば SVG で足りる |

### URL

都道府県自体の頁は `/tokyo` にする。`jurisdictionPath` は自治体コードの先頭2桁と slug で `/<都道府県>/<自治体>` を作るが、都道府県（コードの3〜5桁目が `000`。東京都は 130001、slug は `tokyo`）だけは `/<都道府県>` を返す（`/tokyo/tokyo` にしない）。経路も `/:prefecture` を受け、都道府県の slug でなければ次へ渡す。今は個別ページと同じ画面を出し、都道府県内の市区町村の地図と表は全国化のときにここへ移す。一覧の表では、都道府県自体を種類「都道府県」の行として出し、地図には塗らない（市区町村と面が重なるため）。

自治体の頁が増えたとき（選挙など）は、自治体を頭に置き、テーマをその下の段にする（2026-11-05 に決めた）。`/tokyo/shinagawa` を自治体の入口にし、`/tokyo/shinagawa/elections` のように並べる。都道府県自体は `/tokyo/elections`。利用者は自治体の単位で見に来るので、入口の頁からテーマを渡り歩けるようにする。都道府県自体のテーマと市区町村が `/tokyo/` の下の同じ段に並ぶので、テーマの段の名前（`jurisdiction/path.ts` の `TOPIC_SEGMENTS`）を市区町村の slug に使わないことをテストで確かめる。テーマを頭に置く案（`/elections/tokyo/shinagawa`）は、衝突は起きないが自治体の入口が無くなるので採らなかった。

## 後から加えるもの

- **人口**: 人口データを取得したら、`IndexEntry` に人口を加え、表の並べ替えと地図の塗りに「住民1人あたり」を足す。比べる指標の本命は1人あたりで、取得後は既定の指標を1人あたりに切り替える。画面の注記（「1人あたりは人口データを収録してから加えます」）を外す。個別ページの `jurisdiction/dummy.ts` の仮の値も同じデータで置き換える。
- **年度の揃え**: 最新の決算の年度が自治体ごとに違う（令和6・7年度が混在）ので、表の金額の横に年度を出している。収録年度が揃ってきたら、年度を選んで揃える切り替えを加える。
- **狭い画面の地図**: 幅 390px では 23区が小さく、タップで選びにくい。狭い画面では表を主にし、地図は区部を拡大する切り替えを検討する。
