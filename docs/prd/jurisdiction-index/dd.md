# 自治体一覧の設計

要件は [PRD](prd.md) に置く。個別ページ・URL の決め方は `apps/web/README.md` の「自治体の個別ページ」が正本。

## 画面

上から「地図＋選んだ自治体のカード」「表」の順に置く（2026-11-05 に地図・表・区画タイルの3案を比べ、地図と表の組み合わせを選んだ）。

- **地図**: 「日本 › 東京都」の2段。日本は47都道府県のタイル地図（`jurisdiction/japan-tiles.ts`）を収録した市区町村の数で塗り、収録のある都道府県を選ぶとその都道府県の市区町村のタイル図に進む。最初は収録した市区町村がいちばん多い都道府県（今は東京都）を開く。市区町村も日本と同じく、同じ大きさの名前入りのタイルをおおよその位置に並べ（2026-11-05 に境界の地図から切り替えた。面積の差で区が潰れず、名前が読めるため）、最新の決算の一般会計の歳出の総額で塗る。濃さは金額の平方根に比例させ、未収録は地の色で区別する。島しょは本土のタイルの下の段に北から並べる（他の都道府県の自治体は混ぜない）。狭い画面では本土のタイルは名前が読める大きさを保って横にスクロールさせ、歳出の総額の重心が真ん中に来るところから見せる。島しょの段は同じマスの幅のまま折り返し、スクロールさせない。日本と都道府県の切り替えは View Transition で、選んだタイルが都道府県の図へ拡大する（戻るときは縮む）。動きを減らす設定では切り替えるだけにする。
- **選んだ自治体のカード**: 総額・金額の大きい款3つ・収録年度・個別ページへのボタン。最初は開いている都道府県自体（東京都）を見せる。収録した自治体のタイル（と「地図の外」の名前）は個別ページへのリンクで、押すとその自治体へ進む（2026-11-06 に「押して選ぶ」から切り替えた。モバイルでは押してもカードが図の下に出るだけで、何が変わったか分かりにくかったため）。マウスを載せる・フォーカスするとカードにその自治体を出し、地図から出ると都道府県自体に戻る。
- **検索**: 頁の上の検索（shadcn の Combobox）は地図のためのもの。名前（ローマ字の slug でも当たる）で候補を出し、市区町村を選ぶとその個別ページへ進み、都道府県を選ぶとその図を開く。
- **表**: 種類のタグ（都道府県・区・市・町村）を押すと、その種類の候補の Combobox が開いて複数選べる。都道府県は47都道府県（収録の無いものは選べない）、区・市・町村は収録した自治体を並べ、先頭の「すべての〇〇」で選べる候補を一度に選ぶ・外す。都道府県の選択と市区町村の選択は AND で、同じ都道府県・市区町村どうしは、どれかに当たれば残す（八王子市と町田市を選べば両方）。「すべて」で選択を外す。歳出総額の大きい順・小さい順で並べる。行は個別ページへのリンク。

区画タイル案（自治体の形のシルエットをカードにする）は採らなかった。見た目は良いが、数と金額の比較がしにくい。形のシルエットは、表の行や個別ページの見出しのアイコンとして後から使える。

## データ

`apps/web/server/jurisdiction.ts` の `loadIndex` が、収録の一覧（`/v1/jurisdictions`）から決算のある自治体を選び、最新の決算の年度が同じ自治体ごとに `nodes:search` で款をまとめて引く。総額は個別ページと同じ「一般会計の款の和」。1回の検索に載せる自治体は 60 まで（API の bind の上限 90 から年度・会計などの条件を引いた余裕）。結果は Worker の cache に1時間置く（収録の一覧と同じ TTL）。款が引けない自治体は 0 円と出さずに一覧から外す。

全国に広げると、款の行は「自治体数 × 款の数（約12）」になる（1,700 自治体で約2万行、1,000行ずつ約20回の検索）。その段階では、API の収録範囲に最新の決算の総額を持たせる（marts で集計する）ほうが軽い。

## 地図のデータ

位置の正本は `apps/web/public/<都道府県>.geojson`（`map/build.py` が国土数値情報 N03 から作る。東京都は自治体マスタの62自治体、他の都道府県は N03 の市区町村すべてを、検査数字を付けた6桁のコードで描き、政令市の区は市にまとめる）。`bun run --cwd apps/web build:map`（`jurisdiction/map-build.ts`）が、各自治体のいちばん大きなリングの重心を格子のマスに割り当て、列・行と名前だけを `jurisdiction/map.generated.ts`（東京都・兵庫県で約5KB）に書き、それを commit する。割り当ては、重心の座標と順位を 4:6 で混ぜて（23区のような密集を広げる）、タイル数の 1.35 倍のマスに距離の近い順で決め、2つのマスの入れ替えで距離の二乗和が減らなくなるまで直し、空いた行・列を詰める。島しょ（`island`）は格子に入れず、北から並べる。都道府県を足すときは `map/build.py` の `OTHER_PREFECTURES` と `map-build.ts` の `PREFECTURES` に並べる。

## 全国に広げるとき

全国の市区町村（約1,740）を一枚の地図に塗ると、23区などの小さな区が潰れて選べない。全国版は2段にする。

1. **全国（`/jurisdictions`）**: 47都道府県のタイル地図（各都道府県を同じ大きさの四角で、おおよその位置に並べる）を、収録した市区町村の数で塗る（実装済み。今は同じ頁の中で都道府県の地図へ切り替える）。表は全国の自治体を並べる（今の表と同じ）。
2. **都道府県（`/tokyo`）**: その都道府県自体の財政（東京都自体の決算）と、都道府県内の市区町村の地図と表。今の一覧の地図と表は、都道府県を引数に取る形にしてここへ移す。境界のデータは都道府県ごとに `map/build.py` で作り、`build:map` でタイルの列・行と名前にする。

検討して採らなかった案:

| 案 | 採らなかった理由 |
| --- | --- |
| 全国の市区町村を一枚の SVG で塗る | 小さな自治体が選べない。全国の path は数MB になる |
| MapLibre などの地図ライブラリとベクトルタイル | ズームで解けるが、依存とタイルの配信が増える。都道府県で区切ったタイル図なら名前も読めて足りる |

### URL

都道府県自体の頁は `/tokyo` にする。`jurisdictionPath` は自治体コードの先頭2桁と slug で `/<都道府県>/<自治体>` を作るが、都道府県（コードの3〜5桁目が `000`。東京都は 130001、slug は `tokyo`）だけは `/<都道府県>` を返す（`/tokyo/tokyo` にしない）。経路も `/:prefecture` を受け、都道府県の slug でなければ次へ渡す。今は個別ページと同じ画面を出し、都道府県内の市区町村の地図と表は全国化のときにここへ移す。一覧の表では、都道府県自体を種類「都道府県」の行として出し、地図には塗らない（市区町村と面が重なるため）。

自治体の頁が増えたとき（選挙など）は、自治体を頭に置き、テーマをその下の段にする（2026-11-05 に決めた）。`/tokyo/shinagawa` を自治体の入口にし、`/tokyo/shinagawa/elections` のように並べる。都道府県自体は `/tokyo/elections`。利用者は自治体の単位で見に来るので、入口の頁からテーマを渡り歩けるようにする。都道府県自体のテーマと市区町村が `/tokyo/` の下の同じ段に並ぶので、テーマの段の名前（`jurisdiction/path.ts` の `TOPIC_SEGMENTS`）を市区町村の slug に使わないことをテストで確かめる。テーマを頭に置く案（`/elections/tokyo/shinagawa`）は、衝突は起きないが自治体の入口が無くなるので採らなかった。

## 後から加えるもの

- **人口**: 人口データを取得したら、`IndexEntry` に人口を加え、表の並べ替えと地図の塗りに「住民1人あたり」を足す。比べる指標の本命は1人あたりで、取得後は既定の指標を1人あたりに切り替える。表の列名・カードの見出しを1人あたりの指標に合わせる。個別ページの `jurisdiction/dummy.ts` の仮の値も同じデータで置き換える。
- **年度の揃え**: 最新の決算の年度が自治体ごとに違う（令和6・7年度が混在）ので、表の金額の横に年度を出している。収録年度が揃ってきたら、年度を選んで揃える切り替えを加える。
