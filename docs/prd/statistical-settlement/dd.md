# 統計の決算（普通会計）の設計

要件は [PRD](prd.md)、出典の実測は [統計系の出典の実測](../../survey/fallback-statistics-sources.md) に置く。

## 出典

e-Stat の「地方財政状況調査 市町村分 調査表 年次」の xlsx を使う（認証なしで取得できる）。同じ元データの総務省「市町村別決算状況調」より、年次ファイルが年度ごとに揃い、年度を増やしやすい。

- 表07「歳出内訳及び財源内訳」は、列が目的別の款・項、行が性質別。その1 は議会費・総務費で、他の款は その2 以降に分かれる（API の統合表で確認。年次ファイルの分かれ方は未確認）。
- 款・項の金額は、性質別の行の合計（歳出合計の行）から取る。年次ファイルに歳出合計の行があるかは未確認で、無ければ性質別の行の和で作り、表の外の値（決算カードの目的別歳出）と照合する。
- 単位は千円。円換算は既存の intermediate の規則に乗せる。
- 収録する年度の範囲は、年次ファイルで同じ表の形が取れる年度を実測して決める。

## 宣言

選定の宣言（`pipeline/source_selection/<自治体>.json`）には何も足さない。統計の決算は選定結果に関係なく収録するので、選定との接点が無い。

- 統計は全国共通の1本の出典なので、自治体ごとに同じ URL を書くと drift の元になる。
- 選定は「自治体が公開した資料の判断」のまま保ち、null の意味を変えない。

統計の出典は年度ごとに1つの宣言（URL・sha256・表の一覧）として、選定とは別の置き場に持つ。対象の自治体は自治体マスタ（収録対象の一覧）から引く。

## 取り込み

統計の年次ファイルを、既存の PDF と同じノードの表・金額の表に落とす変換器を1つ足す。

- 入口は既存の `prepareIngestion`（`pipeline/ingestion/selection.ts`）とは別に置く。統計の入口は「統計の宣言（年度）」と「収録対象の自治体の一覧」を入力に取り、統計にその自治体・年度の行がある組を変換する。行が無い組は作らない。
- 出力は既存の管理 JSON と同じ形で、`dbt/scripts/prepare.py` が生成する staging の入力一覧（`fiscal_pdf_relations()`）に載る。これで `stg_fiscal__nodes`・`stg_fiscal__amounts` → `int_fiscal__settlement_expenditure_nodes` → `int_fiscal__expenditure_transfers` の既存経路を通り、木の検査（`fiscal_tree_balances`）も当たる。
- 木は「普通会計 → 款 → 項」。内訳の列が無い款は款を葉にする。
- 保存の関門は既存の木の検査（項の和＝款）と単位の確かめ（款の和＝歳出合計）を当てる。目の支出済額の過半を求める検査（ADR 0029）は、目を持たない出典なので対象から外す。

## dbt・配信

- 専用の union 枝は作らず、上の staging・intermediate の経路で `settlement_expenditure_node` に入る。`account_name` は「普通会計」とし、`account_kind` は `int_fiscal__expenditure_transfers` が `account_kind_map` から引くので、辞書に普通会計を一般会計とは別の種類として足す。
- 同じ自治体・年度に一般会計と普通会計が並ぶ。API の収録範囲と検索は今も会計（`account_name`）ごとに返すので、特別会計と同じ扱いで別の会計として返り、既定の並びは一般会計が先のまま変えない。ただし普通会計は一般会計と一部の特別会計を含むので、特別会計と違い「全会計を足す」と二重に数える。列の説明（`_models.yml`・`columns.json`）とデータの説明（apps/docs）に、普通会計を他の会計と足さないことを書く。
- 統計由来であることは、明細から引ける列で示す。候補は `origin.format`（xlsx）だけに頼らず、粒度を表す列（例: 款まで・項まで）を木の表に足す案。列の名前と語彙は実装時に決める。
- `origin` は自治体ごとに1行を持つ（同じ URL・sha256 を自治体ごとに繰り返す）。今の `dbt/scripts/prepare.py` は sha256 を `origin_id` にし、同じ sha256 で対象が違うと `conflicting source targets` で止まる。統計の出典だけ `origin_id` を sha256 と自治体コードから作り、自治体ごとの行を別の ID にする。`origin.sha256` は全自治体で同じ値のまま、ファイルの同一性を示す。自治体の資料の `origin_id`（sha256 そのもの）と競合検査は変えない。
- `expenditure_coverage` は木の表から作るので、変更なしで「普通会計」の行が載る。
- 頁・印字の枠の列は NULL（xlsx の行・列の位置は持たない）。
