# 原典 PDF の該当箇所の表示

## Problem

数字が怪しいと思った利用者は、原典の PDF を開き、該当の頁を探し、さらに頁の中で項目と金額を探す必要がある。MCP の UI の中では、PDF をそのまま埋め込んで表示できない。頁へのリンク（`#page=N`）は、Safari やダウンロード扱いの PDF では効かない。

## 導出

Story の「数字が怪しいと思ったときに、原典と合っているか・注意点が無いかを確かめる」を、明細を見ている場所から離れずに行えるようにする。提供用データは明細ごとに、印字された頁と枠を既に持っている。

## Overview

利用者が MCP の UI で明細を見ているとき、原典を開くと、UI の中に原典 PDF の該当の頁が表示され、その明細の項目と金額が印字された位置が、単一頁の枠で特定できる場合に強調される。PDF は、風土記の API が自治体の公開 URL から取得して中継する。

### Goals

- 利用者が、明細の UI から離れずに、原典の該当箇所を目で確かめられる。

### Non-Goals

- 保存済みの原典の公開配布。R2 は非公開のままとし、表示用の中継だけを行う。
- 中継した PDF が取り込んだ原典と同じ内容であることの確認。
- 自治体のサイトから消えた原典の表示。
- CSV の原典の表示。
- PDF の文字の選択・検索。

## Domain Model

- 頁は原典 PDF ファイルの1始まりの頁番号であり、紙面に印刷された頁番号ではない。提供用データの `source_page`・`amount_source_page` と同じ数え方である。
- 印字の枠は、頁の左上を原点とする pt の座標で、提供用データにある。枠が無い明細（団体により横の座標が無い、金額が複数の印字の和など）や、項目が次の頁へ続くため `source_y0 > source_y1` となる明細は、頁の表示だけにとどめる。
- 中継するのは、提供用データの原典に載っている URL だけである。利用者が任意の URL を指定して中継させることはできない。

## Acceptance Criteria

- 利用者が MCP の UI で明細の原典を開くと、UI の中に原典 PDF の該当の頁が表示され、単一頁の枠がある場合は項目の印字の位置が強調される。
- 金額の頁と枠がある明細では、金額の印字の位置も強調される。項目と金額が別頁なら左に項目・右に金額を同時表示し、同頁なら同じ頁に両方の枠を表示する。単一の既知の頁は隣接頁と見開きにし、PDFが1頁だけの場合は1枚で表示する。利用者は前後の見開きへ頁を送れる。
- 枠は文字の領域から2pxの余白を取り、強調箇所の中心を通る縦横のガイド線を表示する。
- 枠が無い明細や `source_y0 > source_y1` の明細では、該当の頁が表示され、項目の枠は強調しない。
- 利用者は、表示中の PDF の取得 URL・取得日時と、取り込み時の原典と内容が異なる可能性があることを確認できる。
- 自治体のサイトから原典を取得できないとき、利用者は表示できないことと、原典の URL・頁番号を得られる。
- 利用者は、提供用データの原典に無い URL を中継させられない。

## Non-Functional Requirements

- 既存の API・MCP と同じく、認証なしで返す。
- 利用者の閲覧のたびに、自治体のサイトへ同じ原典を取りに行かない。保持期限内は同じ取得 URL の PDF を再利用し、期限後は再取得する。取得失敗は成功した PDF として保持しない。
- 中継には取得サイズ・時間とリクエスト頻度の上限を設ける。上限を超えた場合は取得できない場合と同じ表示にする。中継する PDF の範囲、上限値、保持期間と再検証の方法は実装前の設計書で定める。

## Success Metrics

頁と枠がある明細、枠が無い明細、項目が次の頁へ続く明細を使い、利用者が UI の中だけで、頁を探さずに該当箇所を確認できるかを確かめる。取得できない原典では、URL と頁番号を得られるかを確かめる。
