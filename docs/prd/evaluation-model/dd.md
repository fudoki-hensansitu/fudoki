# 事業評価を整理する — 設計書

状態: 合意（2026-11-15 yuito）。決めること1・2を実装した（ADR 0048）。5は ADR 0049 で実装した。3・4は未着手。

## 背景

予算の単位（款・項・目と、その下の事業の内訳）は当初予算書から格納できている。事業（`project`）は、当初予算書に事業の内訳がある52自治体で、merge のたびに自動で作っている（ADR 0046）。

事業は当初予算書（2月に予算案として出る）の内訳から作り、評価シートからは作らない。評価シートは N+1 年の秋に出たあと、すでにある事業に後から付けるだけで、事業ができる時期は評価を待たない。

評価の側は荒い。いまの `evaluation_sheet`（44自治体・約2.8万枚）には、次の問題がある。

1. **事業へつながるのは品川だけ**。
   - いまのつなぎ方は、シートに印字された予算科目の名前（会計・款・項・目）で決算書の目を決め、その下で事業名が当たる内訳を探す。
   - この方式は、科目の名前を印字する様式でしか動かない。いま事業につながるのは品川の 630枚だけ。
2. **決算書の内訳を経由してつないでいる**（`expenditure_detail_id` → `project_year.settlement_expenditure_detail_id`）。
   - 決算書に事業の内訳があるのは28自治体で、事業を作る当初予算書（52自治体）より少ない。
3. **読んだ科目の番号を捨てている**。
   - 款・項・目の番号は16自治体のシートで、取り込みの表まで読めている。
   - しかし marts に載せていないので、つなぐのに使えない。
4. **資料の目的が違うものが同じ表に入っている**。混ざっているのは次の3つ。
   - 事務事業の評価
   - 決算の附属書類「主要施策の成果」
   - 実施計画・重点事業の進行管理

   評価の区分が空のシートは多いが、その理由を区別できない。理由には次がある。
   - 区分の欄が無い
   - 区分が図の中の印で、文字から読めない
   - 区分を読んでいない

## 評価の単位（前提）

- **予算の単位**（款・項・目）は法で決まっており、議決と執行管理のための単位である。
- **評価の単位**（政策 → 施策 → 事務事業）は、自治体が総合計画に沿って任意に作る。
- 同じお金でも、2つの体系で分け方が違う。予算書は1つの事務事業を所管課ごとの行に分けて載せることがあり（八王子「議会の運営[議事課]」「議会の運営[庶務調査課]」）、逆に品川の評価シートは事業の下の小事業ごとに1枚ある。したがって**シートと事業は多対多**になる。
- 総合計画の層は次の3つ。
  - 基本構想（10〜20年）
  - 基本計画（施策、5〜10年）
  - 実施計画（事務事業。毎年見直す。計画事業だけのことが多い）
- 事務事業評価は、N 年度に行った事業の評価が N+1 年の夏〜秋に出る。
- 風土記が取り込むのは**事務事業の粒度だけ**とする。施策評価（複数の事業を束ねた評価）は取り込まない（2026-11-15 yuito）。

## 決めること

### 1. シートと事業のつながりを、つなぎの表に持つ

`evaluation_sheet_project`（評価の集約の表）に、シート×事業を1行ずつ持つ。

| 列 | 中身 |
| --- | --- |
| `sheet_id` | `evaluation_sheet` のシート |
| `project_id` | `project` の事業 |
| `fiscal_year` | シートの実施年度（事業の年度は `project_id` とこの年度で決まる） |
| `method` | `code`（番号で目を決めた）・`subject_name`（科目の名前で目を決めた）・`name`（自治体の中の事業名）・`seed`（人の判断） |

- 1枚が複数の事業に付くこと（所管課ごとの行）も、複数の枚が1つの事業に付くこと（小事業）も、そのまま持つ。
- シートの金額は事業の金額と足さない。シートの額は、シートに印字された額のままとする。
- 事業の集約の外から参照するので、`project_year_id` ではなく {事業, 年度} で指す。

#### つなぎ方

候補は、その年度の当初予算書と決算書の内訳（分け方が事業）を一度に使う。どちらの行も `project_year` から事業に引ける。

1. **目を決める**。
   - シートの会計・款・項・目の番号が、同じ会計の目に1つだけ当たれば、その目とする。
     - 会計は必須。款1 はどの特別会計にもあるため。
     - 会計名は表記が違うので、会計の種類（`account_kind`）で比べる。
     - 番号は数として比べる（先頭の0を無視する）。「会計-款項目」のまとめ書き（131130）は、宣言で分けて読む。
   - 番号が無ければ、科目の名前で同じことをする（品川の方式）。
2. **目が決まったら、その目の下だけで事業名を比べる**。
   - 当たった行のうち、所管課がシートの担当課に当たるものをつなぐ。所管課ごとの行（同じ名前で課だけが違う行）は、シートの担当課に並ぶ課の分を全部付ける。
   - 所管課の比べ方は手順3と同じ。シートの担当課がどの行の課にも当たらないとき、または所管課が印字されていないときは、当たった行を全部付ける。
   - 当たった行の子孫に同じ名前の行があれば、いちばん上の行だけを採る（子の額は親に含まれるので、両方に付けない）。
   - 品川の小事業は、予算科目の事業の子孫で小事業名が当たる事業に付ける（いまと同じ）。
   - 目の下で当たらなければ、つながない（ほかの目には探しに行かない）。
3. **目が決まらないシートだけ**、自治体・年度の中で事業名を比べる。
   - シートに会計が印字されていれば、その会計の中に限る。
   - 1つの事業にだけ当たるときにつなぐ。同じ名前が複数の目にあるときは、つながない。
   - 所管課で絞ってよい。比べ方は、シートの担当課を「・」で分け、それぞれの末尾が内訳の所管課と一致するかで見る（シートは「総務部職員課」、予算書は「職員課」）。
4. **事業名の比べ方**: 両方に `link_projects.normalize` をかけてから、一致で比べる。
5. 事業の番号（`jigyo_code`）は使わない。予算書の内訳の番号とは別の体系だから（八王子のシートは11桁、予算書は1桁）。

機械でつながらないものは、上書き用の seed（`evaluation_sheet_link.csv`）で直す。

- 鍵は (`jurisdiction_code`, `fiscal_year`, `origin_id`, `page`, `position`)。`project_id` は取り込みを直すと変わりうる（ADR 0046・0052）ので、鍵にも値にも使わない。
- 値は内訳の `detail_id`（複数なら行を分ける）と `method`。

名前の近さで当てる方式（施策のつなぎの Dice 係数と Jev）は、この PR では使わない。一致で当たらないものの量を測ってから決める。

**実測（ローカルの3自治体。事業名の一致だけで、目を決めずに当てた場合）**:

| 自治体 | 年度 | シート | いま | 1つに当たる | 1つ以上に当たる |
| --- | --- | --- | --- | --- | --- |
| 中央区 | R6 | 164 | 0 | 136 | 139 |
| 中央区 | R7 | 165 | 0 | 143 | 146 |
| 品川区 | R6 | 652 | 630 | 563 | 601 |
| 八王子市 | R7 | 568 | 0 | 309 | 388 |

- 八王子で複数に当たるものは、ほぼすべてが同じ目の中の所管課ごとの行。手順2で全部付ければ、つながる。
- 全自治体の率は、実装の PR で測って書く。

#### 年度に事業の内訳が無いとき

シートの実施年度に、当初予算書と決算書のどちらにも事業の内訳が無ければ、そのシートは事業につながない。

- シートのある自治体×年度の 123組のうち 46組がこれに当たる。多くは、予算書の収録が2024年度からで、実施年度2023のシート。
- 前後の年度の事業には付けない。付けると、事業の始めた年度より前に評価があることになる。
- 埋めるには、その年度の予算書を取り込む（R5 以前の取り込みは進めている）。
- 当初予算書に事業の内訳がまったく無い自治体（シートのある所では 131032・131172・132110・132136・134015）も、シートを事業につながない。シートから事業は作らない。

### 2. 目へのつなぎは残す

目へのつなぎは、`project_year` と同じく当初と決算の2列（`initial_expenditure_subject_id`・`settlement_expenditure_subject_id`）で持つ。いまの `expenditure_subject_id` は、この2列に置き換える。

- web の評価のタブは、年度ごとに当初か決算の目で分野を絞っている。1列だと、web が見せている資料とずれた年度で、シートが絞り込みから漏れる。
- 事業の内訳が無い自治体では、目が唯一のつなぎ先になる。
- 手順1は、当初予算書と決算書の目にそれぞれ別に当てる。片方でしか決まらなければ、もう片方は空にする（科目の番号か名前が同じ目を、もう片方へ写すことはしない）。
- `expenditure_detail_id` はやめ、つなぎの表に置き換える。

公開 API は互換を保たない（まだ利用者がいない）。次は同じ PR で書き換える。

- `SheetRow`
- MCP の説明（`evaluation/tools.ts`・`project/tools.ts`）
- web の事業から評価を引く所（`api.ts`）

事業から評価を引くときは、つなぎの表を {事業, 年度} で引く。


### 3. 資料の目的と区分の状態を、シートの列に持つ

宣言の単位（1冊の中で様式が違えば `parts` の単位）に次の3つを書き、シートの列まで落とす。web の件数も、この列で絞る。

- `sheet_purpose`（資料の目的）:
  - `evaluation`: 事務事業の評価。行政コストのシートも含む。
  - `settlement_results`: 決算の成果。主要施策の成果・決算事業報告書。
  - `plan_progress`: 計画の進行管理。実施計画・重点事業。
- `grade_status`（区分の状態）:
  - `printed`: 区分を印字し、読んでいる。
  - `no_field`: 区分の欄が無い。
  - `unreadable`: 区分が図の中の印などで、文字から読めない。
  - `not_read`: 区分の欄はあるが、1つの区分にならないので読まない（点数のランク、観点ごとのチェック、委員の回答の人数など）。
- `coverage`（評価した範囲。出典の宣言に書く）:
  - `all`: 一般会計の事務事業の全部。
  - `planned`: 計画事業だけ。
  - `sampled`: 抽出した事業だけ。
  - `unknown`: 資料から分からない。

いまのつながる率では、「つながらなかった事業」を「評価されていない事業」とは言えない。そのため `coverage` は資料の説明としてだけ出し、事業ごとに「評価なし」の印は付けない。

`project_origin.document_type`（sheets・press）は、プレスを消したので列ごと消した。

### 4. 施策名はシートの列にとどめる

施策を独立した表にはしない。シートに施策名が印字されている様式だけ、`policy_name`（任意）としてシートの列に持つ。総合計画の体系を軸として作るのは、施策の単位で比べたい要望が出てからにする。

### 5. プレス（予算案の施策）は消す

事業は予算書の内訳（事業名を印字しない団体は予算の概要など）から作り、プレスからは作らない。プレスの施策（`budget_measure`・`budget_proposal`）は、表・API・MCP の操作・画面ごと消す（2026-11-15 yuito）。新規かどうかは事業の始めた年度から出す。

## やること（PR の単位）

1. **つなぎ方の作り直し**:
   - `evaluation_sheet_project` を作る。
   - `evaluation_sheet` の `expenditure_detail_id`・`expenditure_subject_id` を、目の2列とつなぎの表に置き換え、科目の番号を通す。
   - seed を作る。
   - API・MCP・web を切り替える。
   - 全自治体のつながる率と、品川の 630枚が残ることを PR に書く。
   - ドメインモデルの文書と ADR を直す。
2. **資料の目的・区分の状態・範囲**:
   - `origins.json` の各宣言（`parts`）に書き、シートと出典の列に出す。
   - web の評価の件数を `sheet_purpose = evaluation` に絞る。
   - Glossary に「評価シート」「資料の目的」「評価の範囲」を足す。
3. **施策名**: 印字のある様式で `policy_name` を読む。
