# 事業名で事業の評価を引く — 設計

要件は [PRD](prd.md)。ここでは、原典の選定の形式、検索の基盤と登録の形、第1段（引き当ての精度の測定）の進め方を決める。

## 原典の選定

事業の評価の資料は、団体ごとの選定ファイル（`pipeline/source_selection/<団体>.json`）に、金額の原典とは別の配列 `evaluation_selections` として持つ。型は `schema.ts` の `evaluationSelectionSchema`。

```jsonc
"evaluation_selections": [{
  "target": { "jurisdiction": "131172", "fiscal_year": 2025, "document_kind": "settlement" },
  "candidates": [{ "id": "representative", "title": "...", "landing_url": "...", "inspected_at": "...",
    "files": [{ "download_url": "...", "sha256": "...", "format": "pdf", "pdf_type": "text", "pages": null }] }],
  "selected_candidate_id": "representative",
  "archive": null,
  "reason": "..."
}]
```

- **target は評価する実績の決算を指す。** 令和7年度の実績を令和8年度に評価した資料なら、target は令和7年度の決算になる。同じファイルの `selections` に同じ target が無ければ止める。評価の年度が決算とずれることを防ぐ。
- **ファイルは会計・お金の向きを持たない。** 評価の資料は会計ごとに分かれていないので、頁範囲（`pages`、null は全頁）だけを持つ。選定済みのファイルには sha256 が必須。
- **`selections` に混ぜない。** `document_kind` は金額の資料区分の語彙で、API の enum もここから取る（[ADR 0022](../../adr/0022-serve-marts-via-worker-d1-rest-and-mcp.md)）。取り込みと dbt は `selections` だけを読むので、別の配列なら金額の処理は変わらない。
- **ファイルは分けない。** 選定の調査は団体の公式の頁を団体単位で見て進める。別のファイルにすると、団体の記録が2か所に分かれる。
- **資料の名前でなく中身で選ぶ。** 主要施策の成果説明書の中身は団体ごとに違い、目黒区の「主要な施策の成果等報告書」は款・項・目ごとの金額の表と不用額の理由だけで、評価の記述が無い。目標と実績、評価の区分、課題、今後の方向のどれかが書かれた資料を選ぶ。
- **保存は公開・拡大の前に行う。** 第1段は URL と sha256 の固定までで、`archive` は null だけを受ける。AI Search の built-in storage にも PDF が残るが、インスタンスを消すと一緒に消え、作り直しにも原典が要るので、原典の保管場所にしない。第1段で自治体の URL から消えた資料は、sha256 で同じものを探すか選び直す。選び直した資料では、それまでの測定を検証し直せない。保存するときの R2 の key は `fiscal/source-selection/<団体>/<年度>/settlement-evaluation[-<n>].pdf` とし、決算書の key（`.../settlement[-<n>].pdf`）と分けて `archive.ts` の連番の検査とぶつけない。保存を入れるときに `archive` の型と `archive.ts` を広げる。

| 団体 | 資料 | 形 | 読み方 |
|---|---|---|---|
| 中野区（131148） | 令和7年度主要施策の成果 本冊63頁・別冊75頁 | 別冊は施策ごとの評価シート（成果指標の目標と実績・良かった点と要因・今後の戦略、主な事業ごとの実績・効果と次年度の方向性（継続・拡充・縮小・廃止）） | text |

## 検索の基盤と登録の形

Cloudflare AI Search を使う。原典の PDF をそのまま built-in storage に入れ、区切りと文字の抜き出しは AI Search に任せる。自前で md に起こさない。

- **PDF はそのまま入れる。** AI Search は PDF を Markdown に変え、頁の境目に頁の見出し（OCR なしは `### Page N`、OCR ありは `<!-- page N -->`）を入れて区切る。chunk は大きさで区切られるので、2頁が一つの chunk に混ざることがあるが、受け手の AI が頁の見出しで読み分ける。
- **大きい PDF だけ頁の範囲で分ける。** OCR なしで受けるのは 4MiB まで（新宿区 37MB、小金井市 30MB、中野区の別冊 6.9MB は超える）。分けたファイルには、元の物理頁の開始をメタデータに持たせ、chunk の頁の見出しに足して原典の頁に戻す。
- **custom metadata**（1インスタンス5項目まで、文字列で絞れるのは先頭64バイトまで）: `jurisdiction`（text）・`fiscal_year`（number）・`origin_sha256`（text）・`page_offset`（number。分けたファイルの開始頁−1、分けなければ 0）・`document`（text。資料の種類）。絞り込みは `jurisdiction` と `fiscal_year` だけで使う。
- **tokenizer は `trigram`。** `porter` は空白・記号で区切った語を単位にするので、日本語では空白に挟まれた語句（表のセル）しか語として当たらない。`trigram` は3文字ずつの断片で照合するので、文の中の語にも部分一致で当たる。2文字以下の語は当たらないので、呼び出す AI に3文字以上の言い換えを足させる。語の一致は `keyword_match_mode: or` にする（`and` は文の問いで何も返さない）。
- **埋め込みは `@cf/qwen/qwen3-embedding-0.6b`**（8,192 token まで）。`@cf/baai/bge-m3` は 512 token までで、評価のシート1頁（約3,000 token）が収まらない。
- **OCR はインスタンスを分ける。** OCR を有効にすると文字の層がある頁にも OCR がかかり、表の構造は良くなるが、文字を誤る（「令和」が「合和」、「実績」が「实績」、「決算額」が「决算额」など簡体字に寄る）。文字の読める資料は OCR なしのインスタンスに入れる。
- **文字の層が壊れた PDF は OCR で直らない。** 目黒区の分冊（50頁）を OCR ありで入れると、34頁は化けた文字の層がそのまま使われ、OCR がかかったのは8頁だけだった（8頁は空）。選定で `pdf_type: scan` にした資料は、頁を画像にした PDF に変えてから OCR ありのインスタンスに入れるか、既存の OCR（`ingestion/lib/scan_ocr.py`）で読む。試行の2団体はどちらも text なので、第1段では扱わない。
- **作り直せること**: 抜き出しと区切りは AI Search が行うので、同じ原典から同じ索引ができるとは限らない。要件は「固定した原典から作り直せる」ことで、検索の候補は数字の答えに使わないので、これで足りる。

### 結果に返るもの（2026-10-13 に確かめた）

- chunk ごとに `item.key`・`item.metadata`（登録した custom metadata）・`text`・`score`。hybrid では `scoring_details` に `vector_score`（0〜1）と `keyword_score`（BM25）が分かれて返る。
- `score_threshold` を 0 にしても、意味の近さが 0.40 未満の候補は返らなかった。短い語（「平和」）だけの問いは、語の一致にも意味の近さにも当たらず、候補が0件になる。
- 意味の近さのスコアは 0.40〜0.67 に固まり、正解と不正解の差が小さい。

### 費用（2026-10-13 の公式文書。課金は 2026-11-01 から）

| 対象 | 毎月の無料枠 | 超えた分 |
|---|---|---|
| 取り込み | 500万 token | $0.75 / 100万 token |
| OCR（画像の処理） | 取り込みと同じ枠 | 追加で $0.50 / 100万 token |
| 保存 | 10 GB-month | $2.00 / GB-month |
| 意味・hybrid の検索 | 1,000回 | $0.75 / 1,000回 |
| 全文検索 | 1,000回 | $0.10 / 1,000回 |

- 評価のシートは1頁あたり約3,000 token（中野区の別冊75頁で 209,255 token、`cl100k_base`）。取り込みの無料枠は月に約1,600頁分で、超えると1,000頁あたり約 $2.3。索引を作り直すと（tokenizer・custom metadata の変更を含む）、取り込みをもう一度数える。
- 保存は PDF の大きさで、中野区の別冊は1頁あたり約90KB。26団体・8,000頁でも約1GB で、無料枠に収まる。原典は別に非公開 R2 に置く。
- 費用で効くのは検索の回数である。AI は一つの問いで何度も検索するので、公開するときは流量の制限と kill switch を置く。

## 第1段の進め方

精度を測るだけで、公開しない。手順と結果は同じ dir の [`trial.md`](trial.md) に残す（2026-10-13 に2団体で頁への到達だけを測定。次に測ることも trial.md に置く）。

1. **索引を作る。** 選定した URL から取得し、sha256 が選定と一致することを確かめた PDF を、大きいものは分けて、メタデータを付けて入れる。
2. **正解の集合を作る。** 両団体の評価の資料の事業名と、marts の目の名前から問いを作り、問いごとに正解の事業の評価（0件も正解）と頁を付ける。候補は機械で出してよいが、正解は人が原典の頁を見て決める。
3. **AI に引かせる。** 呼び出す AI に、団体・年度と問いを渡し、検索の問いを組み立てさせて引かせる。AI が候補を読んで目的の事業の評価を選んだ結果も記録する。
4. **測る。** 正解が上位10件に入る割合（主な指標）、AI が正しい評価を選んだ割合、正解が無い問いで AI が「該当なし」とした割合。分母と合否の閾値は手順2の前に `trial.md` で決める。

### 予備の試行（2026-10-13、中野区の別冊10〜19頁）

手で書いた9問（事業名4問・文の問い5問）で、正解の頁が上位5件に入った数を比べた。

| 入れ方 | `porter` | `trigram` |
|---|---|---|
| 施策ごとに自前で起こした md（抜き文字のまま） | 5/9 | 5/9 |
| PDF をそのまま | 7/9 | 6/9 |

問いが少なく、方式の優劣は決められない。自前の md は表の崩れた抜き文字のままで、区切りを揃えた利点は出なかった。この結果から、PDF をそのまま入れる形にした。
