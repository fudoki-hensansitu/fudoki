### AI の利用手順（`trial/agent_run.py`・`agent_tool.py`・`agent_prompt.md`）

- 問いごとに新しい会話（Claude Code の headless、Sonnet）を起こす。道具は検索（`search`）と回答（`answer`）だけで、正解のファイルは渡さない。会話をまたいで知識は残らない。
- 検索は1問3回まで。候補は上位10件の chunk の全文を、頁の見出しで（原典・頁）に区切って渡す。同じ問いの中で既に見せた chunk は本文を省き、既出と知らせる。
- 引き直す条件は「候補が0件」「目的の事業の評価が候補に無いと判断した」。止める条件は「目的の事業の評価の頁が見つかった」。3回で見つからなければ `not_found`、決められなければ `ambiguous`（頁を挙げる）、同じ名前の事業が複数の頁に載れば全部を挙げて `found`。
- `found` のときは、目的の事業ごとに 目標・実績・評価区分・課題・方向性 を、候補の本文の連続した文字列（`quote`）と頁と読み（`reading`、どの指標・年度の値か）で答える。資料に無い項目は null。
- 記録: 最終の status・頁・引用、検索の回数と検索語、会話の費用。回答しないで終わった会話は1回だけやり直し、それでも回答が無ければ「回答なし」として誤りに数える。

### 採点

- **正答**: `found` で、選んだ頁 P が T と交わり、P が A に含まれる（S5 で T が空・A が空でないときは A と交わる）。負例では `not_found`。
- **取り違え（誤帰属）**: `found` で、P に A の外の頁がある。目的ではない事業の評価を、目的の事業の評価として示したことになる。負例では `found` が取り違え。`ambiguous`・`not_found` は取り違えに数えない（正答にも数えない）。
- **部分**（S4a）: `found` で P ⊆ A だが、T の頁を全部は挙げていない。正答とは別に数える。
- **判定**: P に T の外の頁があるときだけ、別の会話（Sonnet、AI の理由は見せない）に、目的の事業の正式名と、その頁の原典の文字（pdftotext -layout）を渡し、「この頁に目的の事業の評価が載るか」を判定させる（`trial/judge2.py`）。載るなら A に足す。判定は全件を人（Claude のオーケストレーター）が読み直し、判定と違えば人の判断を採り、その数を報告する。
- **成否の読み取り（3）**: 正答した問いの引用の各項目について、(a) 写しの一致: 空白を除いた `quote` が、AI に見せたその頁の本文に含まれる。(b) 帰属: 別の会話（Sonnet）に、原典のその頁の文字（pdftotext -layout、表の行と列が保たれる）、目的の事業、項目、`quote`・`reading` を渡し、「正しい」「別の事業の行」「別の年度・列」「別の項目（計画を実績として読む、前年度の評価など）」「原典に無い」「判断できない」のどれかに分けさせる。取り違えは「別の事業の行」「別の年度・列」「別の項目」「原典に無い」の合計。判定のうち、取り違えとされたもの全部と、無作為の30件を人が読み直し、人と判定の不一致の率を報告する。
- **全文検索だけと hybrid（5）**: AI を通さず、同じ検索語（S1〜S4 は名前・言い換え・略称そのもの、S5 は目の名前、第1段の 214問・80問も含める）を1回ずつ `retrieval_type` を `keyword` と `hybrid` で引き、T（S5 は T が空でない目だけ）が上位10件に入る割合と候補0件の数を比べる。

インスタンスを読み直し、`trigram`、`or`、上位10件、埋め込みモデルと索引の構成が計画どおりであることを確認した。なお、試行のリクエストは `score_threshold: 0` を送っていたが、[現行の公式API](https://developers.cloudflare.com/api/resources/ai_search/subresources/namespaces/subresources/instances/methods/search/)が定義するリクエストの閾値は `match_threshold` である。リクエストによる0への上書きが効いたとは確認できていない。ここでは測定中のリクエストを変えず、その実際の設定の比較として報告する。閾値を変えた再測定は別の条件として扱う。

## 第1段の測り方

### 索引

試行用の AI Search のインスタンス `fudoki-eval-trial-v1`（公開の口は無効）に、選定の宣言の PDF をそのまま入れた。中野区の別冊（6.9MB）は 4MiB を超えるので、1〜38頁と39〜75頁に分け、2つ目に `page_offset: 38` を付けた。

| ファイル | 頁 | chunk |
| --- | --- | --- |
| 北区 令和8年度事務事業評価（`80b62f85965f…`） | 108 | 57 |
| 中野区 令和7年度主要施策の成果 本冊（`628b02ba7d8f…`） | 63 | 5 |

| 中野区 同 別冊 39〜75頁 | 37 | 18 |

設定: `keyword_tokenizer: trigram`、`keyword_match_mode: or`、`chunk_size: 4096`、`chunk_overlap: 0`、`score_threshold: 0`、`max_num_results: 10`、埋め込み `@cf/qwen/qwen3-embedding-0.6b`。検索は団体（`jurisdiction`）だけで絞った。年度（`fiscal_year`、number）でも絞ると語の一致の側が毎回0件になるため（下記）。資料は2025年度だけなので、結果は変わらない。

### 正解の集合

原典の印字から機械的に作った（`trial/truth.py`）。人が頁を読んで付けたものではないが、名前と頁の対応は印字そのものである。

- 北区: 各頁の「事業名︓」。98事業（10〜107頁、重複なし）。
- 中野区: 別冊の「施策 N」の頁（続きの頁を含む）56施策と、①〜で始まる主な事業の取組名200件。取組名は無作為に20件を見て、成果指標の行が混ざっていないことを確かめた。名前が重複した「居住支援体制の推進」は外した。
- 原典の名前の問い（`trial/exact.json`）: 北区98件・中野区の施策56件・取組から無作為の60件（seed 7）。
- 言い換えの問い（`trial/para_queries.json`）: 上から無作為の80件（北区40・中野区40）について、原典の本文を見せずに名前だけを Sonnet に渡し、特徴的な語を別の言葉にした問いを作らせた。

### 判定

- 検索の当たり: 上位10件の chunk のどれかが正解の（原典・頁）を含めば当たり（`trial/run.py`）。chunk が含む頁は、chunk の本文の `### Page N` から読み、`page_offset` を足して、item の `origin_sha256` と組にした。1つの chunk は約2頁を含むので、「上位1件」は頁の単位より粗い。
- LLM の選択（参考、初版の採点）: 言い換え80問について、上位10件の chunk を頁に分け、各頁の先頭600字と問いを Sonnet に渡して、目的の事業の頁を選ばせた（`trial/judge_prep.py`・`trial/score.py`）。実際の利用では chunk の全文を渡すので、この判定は控えめに出る。
- 引き直し（参考、初版で外れた問い）: 1回で外れた11問について、問いだけを Sonnet に渡し、行政資料で使われそうな別の検索語を3つ作らせて引き直した（`trial/retry_queries.json`・`trial/retry.py`）。

## 第1段で分かったこと

- **年度で絞ると、語の一致が効かなくなる。** `fiscal_year`（number の custom metadata）を filter に足すと、`hybrid_meta.keyword_result_count` が毎回0になり、意味の近さの側だけで返った。原典の名前の問いでも上位10件の割合が 83% に落ち、候補0件が34問出た。
- **同じ問いでも、ときどき意味の近さの側が0件を返す。** 同じ問いを同じ条件で8回引くと、1回だけ `vector_result_count: 0` になった組があった（「電線を地下に…」を北区で）。呼び出す AI には、0件なら同じ問いでも引き直させる。
- **候補が0件になる問いがある。** 言い換え80問のうち7問は、候補が1件も返らなかった（例: 「電線を地下に埋める工事は計画通り進んでいる？」、正解は「無電柱化の促進」）。`score_threshold: 0` を送っても、意味の近さが0.4未満の候補は返らなかった。リクエストの閾値の上書きが効いたかは未確認なので、0件の原因は断定しない。0件は「資料に無い」ことを意味しないので、AI には引き直させる。
- **意味の近さのスコアは差が小さい。** 上位1件の `vector_score` は中央値 0.62（0.41〜0.82）。スコアで当たり外れを分けることはできない。
- **「該当なし」は測れなかった。** 北区の事業名を中野区で、中野区の施策名を北区で引く30問を負例にしたが、14問で LLM が頁を選んだ。見出しを見ると、14問ともその団体の同じ分野の施策・事業（例: 北区の「いじめを見過ごさない取組み」→ 中野区の「いじめの防止等に向けた体制の整備」）で、問いの読み方として妥当だった。無関係な頁を選んだ例は無い。団体をまたいだ名前は負例にならないので、「該当なし」は別の作り方で測り直す。
- **同じ問いでも、引くたびに結果が少し変わった。** 頁の対応付けを直す前後で、同じ言い換えの問いの当たりが数問変わった（中野区の取組の言い換えで 71% と 76%）。数値は ±数ポイントの幅で読む。

## 第1段の限界

- 2団体・1年度だけで、どちらも文字として読める PDF である。scan や文字の層が壊れた資料（目黒区）は測っていない。
- 原典の名前の問いは、検索にとって易しい（原典の語そのもの）。利用者が知っているのは、多くの場合この中間（名前の一部や略称）である。
- 言い換えの問いを作る LLM と判定する LLM は、どちらも Sonnet である。
- marts の目の名前から評価を引く問いは測っていない（決算書が目の下の事業を印字しない団体では、目の名前と評価の事業名が大きく違う）。
