# 事業名で事業の評価を引く — 第1段の精度の測定

担当者: wwwyo / Claude
更新日: `2026-10-13`
状態: 頁への到達だけを測った（2団体）。成否の読み取りと AI の利用手順は未測定

## Summary

[設計](dd.md)の形（原典の PDF をそのまま AI Search に入れ、`trigram`・`or`・`@cf/qwen/qwen3-embedding-0.6b`）で、北区の事務事業評価と中野区の主要施策の成果を引いた。採点は（原典の sha256・物理頁）の組で行う。

| 問い | 問いの数 | 正解が上位10件に入った割合 |
| --- | --- | --- |
| 評価の資料に印字された事業名・施策名・取組名そのもの | 214 | **100%**（上位1件で 98%） |
| 言い換え（名前だけを見た LLM が作った問い）を1回引く | 80 | **82%**（外れ14問、うち候補0件が7問） |

- **言えること: 評価の資料に印字された名前で引けば、その頁は確実に候補に入る。** 言い換えでは2割ほどが1回の検索で外れる。
- **まだ言えないこと: AI が事業の成否を正しく読めるか、公開・拡大してよいか。** 測ったのは頁に辿り着けるかだけで、決算の科目（marts の目）から評価を探す経路、略称・同名の事業、AI が自分で引き直して止まるまでの手順、引用した成否の文が正しい事業のものかは測っていない（[次に測ること](#次に測ること)）。

### 参考（採点を直す前の結果）

次の2つは、正解の集合と採点に誤りがあった版（2026-10-13 初版。中野区の本冊と別冊の頁番号が重なるのに頁番号だけで採点し、施策の続きの頁を別の取組に付けていた）で測った。数値は判断に使わない。

- 1回で外れた11問を、正解を見せない LLM に別の検索語を3つ作らせて引き直すと、11問とも上位10件に入った（直した採点でも同じ）。ただし外れた問いを正解で選んでおり、AI が自分で引き直して回復する割合ではない。直した採点で新たに外れた4問は引き直していない。
- 言い換え80問の上位10件の候補（各頁の先頭600字、10頁まで）を LLM に読ませると、正解の頁を選んだのが61問、「該当なし」が14問、別の頁を選んだのが5問だった。候補の識別が頁番号だけで、本冊と別冊を区別できていない。

## 次に測ること

Codex のレビュー（PR #137）を受けて、公開・拡大を判断する前に次を測る。分母・合否の閾値・誤帰属の定義は測る前にここへ書く。

1. **入口を増やす。** marts の目・事業の名前、略称、同名の事業からの問い。
2. **AI の利用手順をそのまま測る。** 正解を知らせず、検索回数の上限と引き直し・停止の条件を決めた手順を全問に当て、最終の選択・検索回数・「該当なし」を記録する。候補は chunk の全文を渡し、（原典・頁）で識別する。
3. **成否の読み取りを確かめる。** AI が答えた目標・実績・評価区分・課題・方向性の引用が、原典の頁の正しい事業の行のものかを確かめる（表の行と列の対応、続きの頁の欠け）。
4. **負例を作り直す。** 「資料に事業が無い」「事業はあるが評価の記述が無い」を原典で確かめた問い。
5. **比べる。** 同じ問いで全文検索だけと hybrid を比べ、表や事業の境目の誤読が残るなら、事業単位の構造化抽出を検討する。

## 測り方

### 索引

試行用の AI Search のインスタンス `fudoki-eval-trial-v1`（公開の口は無効）に、選定の宣言の PDF をそのまま入れた。中野区の別冊（6.9MB）は 4MiB を超えるので、1〜38頁と39〜75頁に分け、2つ目に `page_offset: 38` を付けた。

| ファイル | 頁 | chunk |
| --- | --- | --- |
| 北区 令和8年度事務事業評価（`80b62f85965f…`） | 108 | 57 |
| 中野区 令和7年度主要施策の成果 本冊（`628b02ba7d8f…`） | 63 | 5 |
| 中野区 同 別冊 1〜38頁（`f3b089e84c0b…`） | 38 | 18 |
| 中野区 同 別冊 39〜75頁 | 37 | 18 |

設定: `keyword_tokenizer: trigram`、`keyword_match_mode: or`、`chunk_size: 4096`、`chunk_overlap: 0`、`score_threshold: 0`、`max_num_results: 10`、埋め込み `@cf/qwen/qwen3-embedding-0.6b`。検索は団体（`jurisdiction`）で絞った。

### 正解の集合

原典の印字から機械的に作った（`trial/truth.py`）。人が頁を読んで付けたものではないが、名前と頁の対応は印字そのものである。

- 北区: 各頁の「事業名︓」。98事業（10〜107頁、重複なし）。
- 中野区: 別冊の「施策 N」の頁（続きの頁を含む）56施策と、①〜で始まる主な事業の取組名200件。取組名は無作為に20件を見て、成果指標の行が混ざっていないことを確かめた。名前が重複した「居住支援体制の推進」は外した。
- 原典の名前の問い（`trial/exact.json`）: 北区98件・中野区の施策56件・取組から無作為の60件（seed 7）。
- 言い換えの問い（`trial/para_queries.json`）: 上から無作為の80件（北区40・中野区40）について、原典の本文を見せずに名前だけを Sonnet に渡し、特徴的な語を別の言葉にした問いを作らせた。

### 判定

- 検索の当たり: 上位10件の chunk のどれかが正解の（原典・頁）を含めば当たり（`trial/run.py`）。chunk が含む頁は、chunk の本文の `### Page N` から読み、`page_offset` を足して、item の `origin_sha256` と組にした。1つの chunk は約2頁を含むので、「上位1件」は頁の単位より粗い。
- LLM の選択（参考、初版の採点）: 言い換え80問について、上位10件の chunk を頁に分け、各頁の先頭600字と問いを Sonnet に渡して、目的の事業の頁を選ばせた（`trial/judge_prep.py`・`trial/score.py`）。実際の利用では chunk の全文を渡すので、この判定は控えめに出る。
- 引き直し（参考、初版で外れた問い）: 1回で外れた11問について、問いだけを Sonnet に渡し、行政資料で使われそうな別の検索語を3つ作らせて引き直した（`trial/retry_queries.json`・`trial/retry.py`）。

## 分かったこと

- **候補が0件になる問いがある。** 言い換え80問のうち7問は、候補が1件も返らなかった（例: 「電線を地下に埋める工事は計画通り進んでいる？」、正解は「無電柱化の促進」）。語の一致が無く、意味の近さが下限（0.4。`score_threshold: 0` でも返らない）に届かないためである。0件は「資料に無い」ことを意味しないので、AI には引き直させる。
- **意味の近さのスコアは差が小さい。** 上位1件の `vector_score` は中央値 0.62（0.41〜0.82）。スコアで当たり外れを分けることはできない。
- **「該当なし」は測れなかった。** 北区の事業名を中野区で、中野区の施策名を北区で引く30問を負例にしたが、14問で LLM が頁を選んだ。見出しを見ると、14問ともその団体の同じ分野の施策・事業（例: 北区の「いじめを見過ごさない取組み」→ 中野区の「いじめの防止等に向けた体制の整備」）で、問いの読み方として妥当だった。無関係な頁を選んだ例は無い。団体をまたいだ名前は負例にならないので、「該当なし」は別の作り方で測り直す。
- **同じ問いでも、引くたびに結果が少し変わった。** 頁の対応付けを直す前後で、同じ言い換えの問いの当たりが数問変わった（中野区の取組の言い換えで 71% と 76%）。数値は ±数ポイントの幅で読む。

## 限界

- 2団体・1年度だけで、どちらも文字として読める PDF である。scan や文字の層が壊れた資料（目黒区）は測っていない。
- 原典の名前の問いは、検索にとって易しい（原典の語そのもの）。利用者が知っているのは、多くの場合この中間（名前の一部や略称）である。
- 言い換えの問いを作る LLM と判定する LLM は、どちらも Sonnet である。
- marts の目の名前から評価を引く問いは測っていない（決算書が目の下の事業を印字しない団体では、目の名前と評価の事業名が大きく違う）。

## 再現

1. 選定の宣言（`pipeline/source_selection/131172.json`・`131148.json` の `evaluation_selections`）の URL から PDF を取り、sha256 が一致することを確かめる。
2. `python truth.py <北区PDF> <中野区の別冊PDF> <作業dir>/trial` で正解の集合を作る（このリポジトリの `trial/*_truth.json` と同じになる）。
3. AI Search のインスタンスを上の設定で作り、PDF とメタデータ（`jurisdiction`・`fiscal_year`・`origin_sha256`・`page_offset`・`document`）を入れる。
4. `trial/` の JSON を `<作業dir>/trial/` に置き、`python run.py <作業dir>`（検索の当たり）、`judge_prep.py` → LLM の判定 → `score.py`、`retry.py` を回す。
