# 文書ごとの組版の設定（`<方向>.layout.json`）

更新日: `2026-10-14`
状態: 内訳6項目と欄の役割の受け口実装済み。採用の状況と停止した表は末尾に記録する。

汎用の組み立て（[設計書](dd.md)）が内訳（備考・節・説明）の欄の段を読み違える原因の多くは、団体ごとの組版の習慣である。字下げの意味、行頭の印、名前の均等割付、注記と名前の折り返し方がそれにあたる。共通の規則を足すと別の団体とぶつかるので、その習慣を文書ごとの設定として LLM が書き、組み立ては設定のある文書でだけ、それを手がかりに使う。設定が誤っていても、保存の関門（木・網羅・単位）で止まる。

## 置き場と範囲

- 管理 JSON の隣の `<方向>.layout.json`（例: `ingestion/fiscal/jurisdictions/132128/2025/settlement/expenditure.layout.json`）。
- 団体・年度・資料区分・方向ごとに1つ。汎用text・scanの両経路に当てる。既存の書式別変換器はこの受け口を呼ばない。表ごとの上書きは、要る実例が出てから足す。
- 項目はすべて省略でき、書いた項目だけが効く。未対応の項目や無効な値はschema検査で停止する。決まっていない項目は書かない。
- 設定は表の中身を変えるので、指紋（`input_fingerprint`）の入力に入れる。

## 形

```json
{
  "schema_version": 1,
  "breakdown": {
    "備考": {
      "marks": {"□": "説明", "○": 1},
      "fitted_names": {"chars": 5, "overflow_left_chars": 1},
      "wrap": "amount_on_last_line",
      "notes": ["○同目"],
      "amount_brackets": true,
      "indent_chars": 1
    }
  }
}
```

`breakdown` のキーは、内訳の欄の見出し（軸の見出し。`備考`・`節` など）である。

`columns` は欄の役割と印字された軸の見出しを指定する。キーは帯の見出し経路（上から「／」で結ぶ）。`kind` は `amount`（金額欄）か `label`（名前欄）で、内容の多数決より先に役割を確定する。金額を読めなければ停止し、文字を数字に置き換える設定ではない。`axis_header` は名前欄が属する印字見出しで、見開き中央などで見出しが切れて別の欄に印字される場合に指定する。text・scanで同じ項目を読む。原典から役割を確かめた欄だけ指定し、未指定の欄は従来の判定を使う。

```json
{
  "schema_version": 1,
  "columns": {
    "予算現／区分": {"kind": "label", "axis_header": "節"},
    "翌年度繰越額／事故繰越": {"kind": "amount"}
  }
}
```

国立2025決算では「予算現額」が見開き中央で切れ、左の節の名前欄に「予算現／区分」、右の金額欄に「節／金額／額」が載る。「節」は右欄に印字されているため、左の名前欄も節の軸と指定する。繰越額の欄は印字された0をOCRがCと読むため、内容の多数決では名前欄になる。`kind:amount`を指定し、原文の個別再読で金額を確認する。数字を含まないOCR文字を金額へ訂正する場合も、この明示された金額欄の中に限る。

| 項目 | 意味 | 例（原典で見たもの） |
| --- | --- | --- |
| `marks` | 行頭の印と、その印が示す段の対応。段は内訳の最上段を 1 とする。複数の印に一致する場合は正規化した印の長さが長いものを先にし、同長は印の固定順にする。JSONのキー順で結果を変えない。`"説明"` は金額を持たない文で、木に入れない。印は文字（`○`・`・`・`□`）か番号の形（`1`・`(1)`・`ア`・`①`）で書く | 武蔵野: 目の説明文は「□」で始まり、事業は「○」で始まる → `{"□": "説明", "○": 1}` |
| `fitted_names` | 名前を均等割付する枠の字数（`chars`）と、枠に入らない名前が左へ出る字数（`overflow_left_chars`）。書き出しの位置ではなく枠で段を決める | 日野: 「消　耗　品　費」は5字の枠に均等割付し、「議会図書室図書」のような6字以上の名前は1字左から書き出す → `{"chars": 5, "overflow_left_chars": 1}` |
| `wrap` | 名前の折り返し方。`amount_on_last_line` は、2行目以降も名前と同じ位置から書き、金額を最後の行に印字する | 町田: 「シティプロモーション事業（政策」／「） 13,441,499」。小金井: 「3 青年教育事業に要する」／「経費（公民館） 2,050,393」 |
| `notes` | 注記の行の始まりの語。語の途中で折り返しても、同じ欄の金額の行までを1つの注記とし、木の和に入れない。別の金額欄を所有する注記やその続きは、支出へ取り違えないよう保存前に停止する | 町田: 「○同目・委託料から同目・旅費へ流」／「用 22,000」 → `["○同款", "○同項", "○同目"]`。日野: `["(繰越明許費)"]` |
| `amount_brackets` | 指定欄の行末にある括弧で囲まれた単一金額を読む。括弧を含む印字文字と範囲を保持し、既存の金額の読みで正負を決める。括弧だけで負数と解釈しない。部署名など文字を含む括弧は金額にしない | 日野: `( 14,101,213)`・`(0)` |
| `indent_chars` | 1段の字下げの字数（正整数）。本文字の高さで換算し、欄の左端からの名前位置で段を決める。頁の枠の移動を段にしない。明示したmarksの段が優先する | 清瀬: 事業・節・細節・細々節を1字ずつ下げる → `1` |

## 書き方

1. 対象の文書から、内訳の欄が見える頁を2〜5頁描画する（`pdftoppm`）。描画するのは、木の検査に落ちた頁と、落ちていない頁の両方。
2. 内訳6項目と `columns` のうち、その文書で原典から確かめられたものだけを書く。
3. 組み立てを当て、関門を通るかを確かめる。通らない区画は、設定を直すか、設定の外の原因として報告する。

## 保存の関門と順序

金額の所有を確かめ、科目名の続きも結んだ後で設定を当てる。名称の折り返しと指定語で始まる注記の続きは、同頁・同じ名称位置・近接・前行が金額を持たない条件に加え、同じ科目の区画にあることを要求する。科目イベントの所属と同じ境界で判定し、次の科目の通常明細を前の科目へ移さない。明確な流用などの金額注記は、印の段や説明より先に扱う。「説明」とした行が金額を持つ場合は停止し、金額の網羅の検査を緩めない。

均等割付の枠は名称を結び終えた後に一度だけ判定する。先頭行の短い名前だけで段を決めたり、枠の補正を先に行って折り返しの位置照合を妨げたりしない。

設定のない文書・軸では従来の組み立てを使う。設定の有無・内容は、この受け口を使う変換器の指紋に含め、追加・変更・削除でStaleを検出する。配置した組版JSONは取り込み表の管理JSONとして数えない。

候補は正規convertとverifyで木・数字の網羅・単位を確かめる。既存表はrefreshで内容同一を先に確認する。Jevは保存を止める向きだけに使い、一度保存した回答で検査を再現する。設定で解けない表を報告だけにして保存せず、停止したまま保持する。
