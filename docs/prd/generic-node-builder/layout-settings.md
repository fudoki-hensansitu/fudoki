# 文書ごとの組版の設定（`<方向>.layout.json`）

更新日: `2026-10-15`
状態: 内訳6項目・欄の役割・見開きの受け口実装済み。採用の状況と停止した表は末尾に記録する。

汎用の組み立て（[設計書](dd.md)）が内訳（備考・節・説明）の欄の段を読み違える原因の多くは、自治体ごとの組版の習慣である。字下げの意味、行頭の印、名前の均等割付、注記と名前の折り返し方がそれにあたる。共通の規則を足すと別の自治体とぶつかるので、その習慣を文書ごとの設定として LLM が書き、組み立ては設定のある文書でだけ、それを手がかりに使う。設定が誤っていても、保存の関門（木・網羅・単位）で止まる。

## 置き場と範囲

- 管理 JSON の隣の `<方向>.layout.json`（例: `ingestion/fiscal/jurisdictions/132128/2025/settlement/expenditure.layout.json`）。
- 自治体・年度・資料区分・方向ごとに1つ。汎用text・scanの両経路に当てる。既存の書式別変換器はこの受け口を呼ばない。表ごとの上書きは、要る実例が出てから足す。
- 項目はすべて省略でき、書いた項目だけが効く。未対応の項目や無効な値はschema検査で停止する。決まっていない項目は書かない。
- 設定は表の中身を変えるので、指紋（`input_fingerprint`）の入力に入れる。

## 形

```json
{
  "schema_version": 1,
  "breakdown": {
    "備考": {
      "marks": {"□": "説明", "○": 1},
      "fitted_names": {"chars": 5, "overflow_left_chars": 1},
      "wrap": "amount_on_last_line",
      "notes": ["○同目"],
      "amount_brackets": true,
      "indent_chars": 1
    }
  }
}
```

`breakdown` のキーは、内訳の欄の見出し（軸の見出し。`備考`・`節` など）である。

`columns` は欄の役割と印字された軸の見出しを指定する。キーは帯の見出し経路（上から「／」で結ぶ）。`kind` は `amount`（金額欄）か `label`（名前欄）、または `ignore`（表の一部でない欄。読まない。府中の施策番号の欄）で、内容の多数決より先に役割を確定する。金額を読めなければ停止し、文字を数字に置き換える設定ではない。`heading` は、欄の見出しが `金額` としか印字されない決算書で、その欄の意味（`決算額`）を宣言する（狛江）。`inline` は、金額の語（`国`・`都`・`その他`）が金額の前に同じ升で印字される欄で、宣言した語をそのまま見出しの末尾にする（`財源内訳／特定財源`）。`axis_header` は名前欄が属する印字見出しで、見開き中央などで見出しが切れて別の欄に印字される場合に指定する。`axis_header: "科目"` は、見出しの語（`区分`）が科目の欄と読めない決算報告書で、その名前欄を科目の欄（字下げで款・項を分ける）と宣言する（小金井の下水道事業決算報告書）。text・scanで同じ項目を読む。出典から役割を確かめた欄だけ指定し、未指定の欄は従来の判定を使う。ノードが0のときは、金額の欄が名前の欄と判定されていないかを先に疑う（金額と単位が間隔 2.5pt 以内で1つの語として読まれ、その欄の行の半数以上が金額と読めない語になると `label` になる。間隔が開いていれば `amount` のまま。`926,900,286 円` が1語に読まれた足立2024 は `columns` に `kind: amount` を書くと 0 が外れた）。キーは帯の見出しの観測の文字と照合するので、scan では誤読後の文字を鍵にする（足立2024 は `水算説明`・`决算額`）。同額の行が並ぶ印字を二重読みと誤認しない。

```json
{
  "schema_version": 1,
  "columns": {
    "予算現／区分": {"kind": "label", "axis_header": "節"},
    "翌年度繰越額／事故繰越": {"kind": "amount"}
  }
}
```

国立2025決算では「予算現額」が見開き中央で切れ、左の節の名前欄に「予算現／区分」、右の金額欄に「節／金額／額」が載る。「節」は右欄に印字されているため、左の名前欄も節の軸と指定する。繰越額の欄は印字された0をOCRがCと読むため、内容の多数決では名前欄になる。`kind:amount`を指定し、原文の個別再読で金額を確認する。数字を含まないOCR文字を金額へ訂正する場合も、この明示された金額欄の中に限る。

| --- | --- | --- |

| `fitted_names` | 名前を均等割付する枠の字数（`chars`）と、枠に入らない名前が左へ出る字数（`overflow_left_chars`）。書き出しの位置ではなく枠で段を決める | 日野: 「消　耗　品　費」は5字の枠に均等割付し、「議会図書室図書」のような6字以上の名前は1字左から書き出す → `{"chars": 5, "overflow_left_chars": 1}` |

| `names_end_with_kind_words` | 金額の無い項目の次の行は、金額の種別の語（`計`・`事業`など）だけの行でも、名前の続きにする（既定は、その語を直前の項目の金額の種別と読む）。種別の行は金額を持つ項目にだけ付く | 清瀬: 「140 校舎外壁等改修工事実施設」／「計 9,900,000」の `計` は名前の末尾 |
| `bracketed_remainder` | 括弧書きの所属（`（選挙管理委員会事務局）`）が、名前の行に収まらず次の行へ回る。前の行の右端に足すと欄の右端を超えるときだけ、名前の続きにする。番号は右揃えで、1桁は2桁より半字右から始まるため、続きの行の左端の差を半字まで許す | 日野: 「3 衆議院議員選挙・最高裁判所裁判官国民審査運営経費」／「（選挙管理委員会事務局） 51,164,097」 |
| `name_columns` | 名前を2つの欄（`給　料` | `市長　１人`）に分けて組み、続く行（`副市長　１人`）が前の行の2つ目以降の語と同じ位置から始まり、1つ目の欄を持たない。番号のない続きの行を、その前の行と同じ段にする | 日野: 「給 料 市長 １人」の次の「副市長 １人」「教育長 １人」は給料の内訳（市長と同じ段） |
| `note_kinds` | 注記の行の始まりの語と、その金額の注記の種類。共通の辞書に語がない注記（債務負担行為の表示）を、金額の段階を付けずに注記として保持する。種類は文書の設定の中だけの語で、共通の辞書は変えない。印字の値は書き換えず、合計に加えない | 日野: 「市民プール高圧開閉装置等修繕（債務負担行為分） 1」 → `{"市民プール高圧開閉装置等修繕": "債務負担行為"}` |
| `plain_names` | 注記の語を含むが項目の名前である語（2字以上）の一覧。この語を含む行を注記（流用・充用…）と読まず、金額も注記として足さない | 日野: 「補充用備品」（`充用` を含むが補充用の備品の購入） |
| `notes` | 注記の行の始まりの語。語の途中で折り返しても、同じ欄の金額の行までを1つの注記とし、木の和に入れない。別の金額欄を所有する注記やその続きは、支出へ取り違えないよう保存前に停止する | 町田: 「○同目・委託料から同目・旅費へ流」／「用 22,000」 → `["○同款", "○同項", "○同目"]`。日野: `["(繰越明許費)"]` |
| `amount_brackets` | 指定欄の行末にある括弧（丸・角）で囲まれた単一金額を読む。名前に接して1語に繋がった括弧も字の位置で切る。行全体が括弧の行（`（委員長 780,000）`）は名前と金額に分け、閉じ括弧は金額に含めない。括弧を含む印字文字と範囲を保持し、既存の金額の読みで正負を決める。括弧だけで負数と解釈しない。部署名など文字を含む括弧は金額にしない | 日野: `( 14,101,213)`・`(0)`。福生: `[187,037,067]`・`…課）(1,047,226)` |
| `bare_amounts` | 項目に番号を持たない軸で、数字だけの行（`176`）を上の名前の金額とする（既定は番号の候補で、コンマの無い数字は名前の金額にしない） | 狛江: 節説明 |
| `rows` | この軸の項目は罫線の行ごとに1つ。行の全ての行が名前で、番号を読まず（数字で始まる名前が番号にならない）、全て兄弟（字下げで段を決めない） | 狛江: 事業名の欄（`３・４・１６号線…`） |
| `rows_from` | `rows` の軸で、罫線の行に金額はあるが名前が無いとき、別の欄（`name`）がその行の名前になり、金額は `amount` の欄にある。（事業名の無い2つ目の主管課の事業は、主管課が名前） | 狛江: `{"name": "主管課", "amount": "決算額"}` |
| `sum_levels` | 括弧書きの小計（`通信運搬費 (1,568)`）の後に続く項目が、その小計とちょうど一致する間は1段下の子、それ以外は1段目。字下げでは小計の子と小計の無い節の項目が同じ位置から始まり分けられないため、和で決める | 狛江: 節説明（細節） |
| `single_part_notes` | 金額の注記（`繰越事業費不用額 12,236,373 円`）の直下にある、注記と同額の1行を、注記の内訳として読む。既定は、合計が注記と等しい2行以上だけを内訳とする（1行は、注記と同額の別の項目かもしれないため） | 港: 「繰越事業費不用額 12,236,373 円」／「負担金、補助及び交付金 12,236,373 円」 |
| `indent_chars` | 1段の字下げの字数（正整数）。本文字の高さで換算し、欄の左端からの名前位置で段を決める。頁の枠の移動を段にしない。明示したmarksの段が優先する | 清瀬: 事業・節・細節・細々節を1字ずつ下げる → `1` |
| `headings` | 金額の無い名前だけの行は、直後に深く字下げされ金額のある行が続くとき、金額の無い見出しの項目とし、その下の行を子にする（既定は説明の文として木に入れない）。見出しより「深い」とは、名前の書き出し（記号・番号の次、`○`・`・` で始まる名前は記号の次）より 6pt を超えて右（段の学習が3ptで切り、6pt未満の少ない段を捨てるので、それ以下の差は段として残らない）。見出しより深い行を名前の2行目として結ばず、「金額の欄が段の欄と合う」という学習（`amount_depth`）で見出しと次の行を1つにしない（この結合の停止は見出しの項目にだけ効き、見出しでない行の結合は従来どおり）。`headings` を有効にした軸では、名前の書き出しより 6pt を超えて右に下げた行は、直前の項目が見出しでなくても折り返しとして結ばない（昭島では、この折り返しの停止 150 件がすべて直前の項目が見出しの場合）。見出し自体は金額を持たず、木の検査は子の和で閉じる。制限: `notes`・`note_kinds` の接頭辞で始まる深い金額行も子と数えるので、これらと併用する文書が出たら、`heads_items` で注記の接頭辞を除く修正を先に入れる | 昭島: `水道料金減免事業補助金` ／ `繰越明許費分 41,963,647` ／ `本年度分 247,860,745` |

## 会計ごとの設定（`accounts`）

同じ出典に載る会計が、同じ印を別の段に使うことがある。トップレベルの `accounts` に会計名（選定の `account`）をキーとして、`breakdown`・`columns`・`spread`・`header` を置くと、その会計の変換では、書いた項目が文書全体の設定を置き換える（項目単位）。会計を書かない設定は全会計に当たる。

```json
{
  "schema_version": 1,
  "accounts": {
    "一般会計": {"breakdown": {"備考": {"wrap": "amount_on_last_line"}}}
  }
}
```

東大和2024では、一般会計に `wrap` を当てると木が崩れ、後期高齢者医療だけが必要とした。港2024では、一般会計だけが `single_part_notes` と `wrap` を要る。設定の追加・変更は同じ文書のすべての変換の指紋を変える（refresh で内容同一を確かめる）。

## 見開きの開いた外枠

`spread: {"gutter": 0.5}` は、一つの物理PDF頁に見開きを印字し、綴じ側の外枠の縦線を省略する文書を指定する。`gutter` は用紙の左端を0、右端を1とする綴じ位置で、0より大きく1より小さい比で書く。新宿2025決算は中央の0.5である。綴じ位置の左右に最も近い、40ptを超える高さで反復した横罫線端を開いた外枠として使う。欄の中の端点を新しい境界にせず、設定のない文書では従来どおり縦罫線だけを使う。

```json
{"schema_version": 1, "spread": {"gutter": 0.5}}
```

欄の意味を表す `columns`（印字見出しの経路をキーに欄の役割と軸の見出しを指定）とは別の項目で、同じ文書設定に併置する。文書の出典を描画して見開きと綴じ位置を確かめた場合だけ書き、関門に落ちる文書を設定のない共通規則で通さない。

## 見開きの題字（`header`）

`header: {"ignore_frame_title": true}` は、頁の題字（「歳　出」）が表の枠の上端に印字され、その枠の全幅にまたがる升目を列の見出しに入れない文書を指定する。目黒2025決算は題字「歳出」を見開きの左右で別の枠に分けて印字するため、左の枠の列は「歳／予算現額」、右の枠は「出／支出済額」と読まれ、款の不用額と項の不用額が別の見出しになって木が合わなかった。枠の全幅の升目は、どの列にも属さないので見出しの経路から外す。設定のない文書には当てない（見出しが枠の全幅の升目に載る作りは他にありうる）。

```json
{"schema_version": 1, "spread": {"gutter": 0.5}, "header": {"ignore_frame_title": true}}
```

## 字の読み直し（`repairs`）

`repairs` は、共通の読み取りに足す字の補正を文書ごとに選ぶ。補正は保存済みの他の表の字の位置や文字を変えうるので、自動では当てない。

- `opening_cell`: 全角の開き括弧（`（仮称）`）で始まる語の左端を、Poppler の墨の位置（字の枠の右半分）でなく字の起点にする。品川2024は `（仮称）…` を隣の名前と同じ位置に並べるため、墨の位置では7pt 右にずれて別の字下げに読まれた。東大和は備考の `（同事業、…` の左端が6pt 動き、保存済みの表が変わる。
- `split_at_rules`: 本文の語を、縦罫線が字の境界（±2pt）に通るところで分ける（Poppler は隣の升の端の字を一つの語に繋ぐ: `政`＋`行政…`、`4,123,524国`）。狛江は罫線で升を区切るので当てる。他の文書では語の座標が変わるので当てない。
- `stacked_rows`: 縦書きの語（1字ずつ縦に積んだ列）の判定から、同じ行の右に数字を含む語がある字を外す（`国 639,349` の `国` は縦書きでない）。
- `overprint`: 太字を重ね打ちした字（`100,000円` が `1100,000000円` と読める）を、字の位置の近傍（±1pt）で一つにする。従来は並びの直近8字だけを見る。東大和2024は従来の読みに重ね打ちの名前（`((生涯涯学学習習課課`）が保存されているので、当てない。

```json
{"schema_version": 1, "repairs": ["opening_cell", "overprint"]}
```

## 薄い罫線（`rules.dark`・scan）

scan の罫線は画素の濃さが既定（128 未満）に届かないことがある（狛江 2024 は 190–200 の灰色で、内側の縦罫線が取れず列 tile が壊れた）。`"rules": {"dark": 215}` と書くと、この文書の罫線の検出を 215 未満の画素まで広げる。取得の request には同じ値を `rule_dark` で書く（列 tile の切り出しに使う）。書かない文書の罫線は変わらない。

## 右寄せのコード（`codes: "right"`）

`codes: "right"` は、款項目のコードが升目の右端でそろう文書（府中2025は入れ子の箱で、`5` と `10` の右端がそろい、二桁の左端が一桁より一字分左に出る。瑞穂2024も、款・項・目が1つの帯の階段で、`1` から `10` で目の字下げが 4pt 割れる）を指定する。二桁のコードの左端を一桁の位置に読み替えて字下げの段を決める。自動で判定すると、葛飾2024の款の題字（`10` と一桁が偶然右端でそろう）にも当たって保存済みの表が変わったため、設定のある文書だけに当てる。

```json
{"schema_version": 1, "codes": "right"}
```

## 書き方

1. 対象の文書から、内訳の欄が見える頁を2〜5頁描画する（`pdftoppm`）。描画するのは、木の検査に落ちた頁と、落ちていない頁の両方。
2. 内訳6項目・`columns`・`spread` のうち、その文書で出典から確かめられたものだけを書く。
3. 組み立てを当て、関門を通るかを確かめる。通らない区画は、設定を直すか、設定の外の原因として報告する。

## 保存の関門と順序

金額の所有を確かめ、科目名の続きも結んだ後で設定を当てる。名称の折り返しと指定語で始まる注記の続きは、同頁・同じ名称位置・近接・前行が金額を持たない条件に加え、同じ科目の区画にあることを要求する。科目イベントの所属と同じ境界で判定し、次の科目の通常明細を前の科目へ移さない。明確な流用などの金額注記は、印の段や説明より先に扱う。「説明」とした行が金額を持つ場合は停止し、金額の網羅の検査を緩めない。

均等割付の枠は名称を結び終えた後に一度だけ判定する。先頭行の短い名前だけで段を決めたり、枠の補正を先に行って折り返しの位置照合を妨げたりしない。

設定のない文書・軸では従来の組み立てを使う。設定の有無・内容は、この受け口を使う変換器の指紋に含め、追加・変更・削除でStaleを検出する。配置した組版JSONは取り込み表の管理JSONとして数えない。

候補は正規convertとverifyで木・数字の網羅・単位を確かめる。既存表はrefreshで内容同一を先に確認する。Jevは保存を止める向きだけに使い、一度保存した回答で検査を再現する。設定で解けない表を報告だけにして保存せず、停止したまま保持する。採否は、設定を書いて測る → 設定で届かなければ後処理の擬似実装（行番号の写しを外す・同番号で名前が前方一致する行を子にする等）で木の不一致の数を出す → 関門に届かなければ規則を書かずに停止として残す、の順で決める。擬似実装は本番のコードに入れず、測った条件と数を dd.md に残す（足立2024）。

## 出典の印字のずれの宣言（`source_inconsistencies`・2026-10-15）

出典が印字した親の値と、その内訳（子）の印字の和が合わないことがある。和に合わせた再親付けや値の書き換えはしない。文書の設定（`<方向>.layout.json`）の最上位の `source_inconsistencies` に、1件ずつ宣言する。コードは受け口だけで、自治体や頁の分岐は持たない。

| 項目 | 意味 |
| --- | --- |
| `table_id` | 対象の表 |
| `page` | 親の物理頁 |
| `axis` | 親子の軸（`備考`・`節`・`科目`） |
| `parent.code`・`parent.name` | 親の番号（無ければ `null`）と、表に保存された名称 |
| `printed` | 親の印字値 |
| `children_sum` | 内訳の印字の和 |
| `difference` | `children_sum - printed` |
| `basis` | 印字値を出典のままにする根拠（上の目が内訳の和で閉じる等。10字以上） |

木の検査は、宣言の `page`・`axis`・親の番号と名称・`printed`・`children_sum` がすべて一致するずれだけを `宣言済みのずれ` として通す。1円でも違えば `不一致` のままで停止する。表に現れない宣言も停止する（古い宣言を残さない）。印字値は書き換えず、marts も印字値のままである。検査は変換・保存の前の関門・`ingestion:verify`・`prepare_save` が同じ宣言を読む。dbt の `fiscal_tree_balances` は `prepare.py` が組版設定から作る `ingestion.source_inconsistencies` と、頁・親（番号・名称）・印字値・内訳の和がすべて一致するずれだけを通す。生成機の木の選択（段のパターン）は宣言を読まないので、宣言で表が変わらない。

例（日野2025一般会計・頁3）:

```json
{"table_id": "general-expenditure", "page": 3, "axis": "備考",
 "parent": {"code": "1", "name": "特別職及び職員人件費(職員課)"},
 "printed": 3003925159, "children_sum": 3004207994, "difference": 282835,
 "basis": "…内訳の和にすると目「1 一般管理費」の印字 3,357,521,662 が事業の合計で閉じる。印字値は書き換えない。"}
```

## 繰越事業費を節に配らない目（`繰越事業費の未配当`）

目の予算現額（計）が、節の予算現額の和より、その目が印字した「継続費及び繰越事業費繰越額」だけ大きい。節の行は繰越事業費を配らず、目だけが持つ。差が目の印字の繰越事業費の金額にちょうど等しいときだけ、予算現額と、そこから決まる不用額を一致として扱う（`tree_checks.UNDISTRIBUTED_PHASES`）。1円でも違えば不一致。羽村2025の頁98「7 財産管理費」（予算現額 156,167,000 = 節の和 155,885,000 + 繰越事業費 282,000。支出済額 140,054,796 は節の和と一致する）。

## 名前のない行が親の金額を繰り返す（`親の繰り返し`）

予備費は節の名前を印字しないため、節の行に名前がなく、支出済額・繰越額・不用額だけが印字される（羽村2025の頁363の4行目: 0・0・30,000,000）。名前のない行の印字された金額が、すべて、直上の款・項・目の同じ列の金額と一致するときだけ、親の繰り返しとして網羅の対象から外し、除外の範囲に記録する（種類 `親の繰り返し`）。行は消さない。1円でも違う、親が印字しない列に金額がある、のどれかなら従来どおり行の無い金額として停止する。

## 欄の役割の指定で小さな分冊の不用額欄を金額にする（`columns`・日野2024）

欄の役割は文書全体で内容の多数決で決まる。日野2024の分冊12（一般会計の款12・1頁）は「不用額」の欄が `0` と `762`（カンマのない3桁の金額）だけで、`762` を項目番号とみなして名前欄になった。`columns` に印字された見出しを書き、`kind: amount` を指定する。

```json
{"columns": {"不用額": {"kind": "amount"}}}
```

見出しの経路（`／`で結ぶ）に一致する欄だけが対象で、他の欄は従来の判定を使う。他の分冊も不用額は金額欄である。

## 文字層の無い頁だけを OCR で読む（`ocr_inputs`・調布2024）

text PDF の数頁だけ文字層が空（頁ごと画像）の原典は、その頁を変換の `ocr_inputs`（request の `pages` と観測の `sha256`。[ADR 0019](../../adr/0019-freeze-scan-ocr-observations.md)）に宣言すると、text の変換（`generic_text`）が **その頁だけ** 固定した観測の語に差し替えて組む。組版の設定に頁の一覧は足さない。頁の一覧と観測の参照は、`ocr_inputs` が既に持っているからである（二重に書くと食い違う）。

| 項目 | 意味 | なぜ既存の項目で言えないか |
| --- | --- | --- |
| `ocr_inputs`（変換の宣言） | OCR で読む頁（`request.pages`）と固定した観測（`sha256`）。text の変換にあれば、その頁の語は観測から、罫線は描画から読む | 組版の設定は文書の読み方、`ocr_inputs` は頁ごとの事実。既にある項目なので増やさない |
| `rules.dark`（既存） | 描画から読む罫線の暗さ。text の頁は罫線をベクタから読むので **OCR の頁だけ** に効く（調布: 罫線が灰 215 で、既定の 128 では拾えない） | 新しい項目を足す必要はない（text の頁に効かない既存の意味が、そのまま混在で正しい） |
| `amount_corrections`・`code_corrections`・`amount_readings`・`code_readings`・`dropped_readings`・`unit_readings`・`header_readings`・`name_corrections`（`observation_id` 形）（変換の options） | scan の変換と同じ宣言。OCR の頁だけに効く。実装は scan の `read_pages` を共有する | text の変換の options に無かった（text は読み違いを訂正する宣言が無く、名称は節点の形だけだった） |

OCR の頁が text の頁と混ざるとき、次を汎用の処理で行う（設定で有効にするものではない）。

- 帯の種類（金額か名前か）は text の頁の見出しから学び、OCR の頁は学習に入れない（OCR の頁の見出しの読み違い・金額の読み違いが、文書全体の帯の学習に混ざって全頁が崩れた）。OCR の頁の見出しは scan と同じ補正（`scan_header_corrections.json`）をかけてから引く。ただし text の頁が印字する見出しと同じ読みは補正しない（補正の `事故繰越し` → `事故繰越` は他の原典の誤読向けで、調布は「し」まで印字する。補正すると欄の種類を学べず、OCR の頁の事故繰越しの 0 が41個落ちた）。節点の組み立ての学習（番号の左端・名前の右限・積み重ねの欄）も text の頁だけで行う。字下げの段も text の頁が節点を印字する軸は text の頁から学び、OCR の頁の行頭はその段へ寄せる（`snap_ocr_levels`。OCR の行頭は1〜3pt ずれる）。text の頁に節点の無い軸（OCR の頁だけが印字する、または text の頁では注記だけ）は OCR の頁から学ぶ。
- 描画で見えない款・項・目の細い列（点線）は、text の頁が同じ幅の枠で引く列（`mixed.learn_frames`）を、描画から読んだ罫線に足す。語を罫線で切る前に足さないと、隣り合う番号（`10` `35`）が1語に結合する。
- OCR の頁の金額の欄に、OCR の箱にも罫線にも覆われない墨（観測の `unread_ink`）や、`columns` で金額と宣言した欄の読めない1字があれば、scan の変換と同じく変換を止める（空欄として黙って消さない）。text の頁が印字しない見出し（OCR の誤読）で種類の決まらない欄に、読めた金額か読めなかった墨があるときも止める（欄ごと金額が消えるため）。Paddle が頁を帯に分けて読んだ継ぎ目で落とし、読み返しでも戻らなかった行（観測の `unread_seams`）も、scan の変換と同じくどの欄でも止める（名前は木の検査に掛からないため）。設定で読まないと宣言した欄（`kind: ignore`・`excluded`）は、墨と種類の決まらない欄の検査の対象にしない（継ぎ目の行は欄を問わず止める）。組み立てが表として読まない頁（款項目の欄も金額の欄も無い表）は対象に残す。OCR が金額の欄の見出しを誤読した頁も同じ形になり、見分けられないため（流用の一覧のような頁は、その欄を `excluded` と宣言する）。数字の上に単独で印字された符号（`△`・`▲`）は組み立てが符号として読むので、読めない1字にしない（scan も同じ）。Paddle の字形の置き換えは受領証に残す。読み直しの宣言（`amount_readings` ほか、`observation_id` 形の `name_corrections`）は OCR の頁にだけ効くので、OCR の頁の無い変換に書くと止める。細い字体の単独の0は `unread_ink` にも残らないことがある（調布の 7 個）ので、原画で確かめて `amount_readings` で補う。
- OCR の行頭の印（`◎` `○` `・`）は、観測の語の範囲から落ちることがあり、備考の入れ子（字下げ）が崩れる。OCR の頁だけ、行の読みの頭の印を最初の語に戻す。scan の変換は変えない。

## 公営企業会計の収入・支出が同じ頁に載る様式（小金井2025下水道事業会計・scan）

決算報告書・収益費用明細書・資本的収支明細書は、収入の表と支出の表を1頁に上下に並べ、各表の上に左端の題（`収入`・`支出`）を印字する。scan の組み立ては、管理 JSON の方向の題の下の部分だけを読む（`scan.direction_sections`）。題のない頁は前の頁の節に続く。方向の違う節の語と罫線は読まず、その方向だけの頁は読まない。題が1つもない scope には当てない。収入の節は歳出の表に入らない。歳入の管理 JSON はまだ無く、132101/2025 の収入の表は誰にも読まれていない（取り込んだのは歳出19冊だけ）。題は、すぐ下に表の上端の罫線がある行だけを題と読む（欄外の `支出` の語は題にしない）。頁を題で割った頁には、頁全体の題（`歳入`・`歳出`）の判定を当てない。

- 備考の `予算額 16,689,000`（節ごとの予算額）は、備考の欄が目の枠に1つの升で、行ごとの罫線がないため、目の注記（種類は `note_kinds: {"予算額": "予算額"}`）として保持する。どの節の予算額かは印字の位置にだけ残り、注記の名前では分からない。節の行に結ぶには、備考の欄の行を節の欄の行に合わせる規則が要る（未実装）。
- 見出しに `第26条` などを含む列の見出しは、読み崩れた升を `header_readings` で宣言する。数字の網羅の検査は `第N条` の語を非金額と読む。
- `(単位:円・税込)` だけの行は項目にしない。
- 淡い罫線は `rules.dark`、款項目の3つの狭い欄は `header.staircase` を、文書の設定に置く（会計を分ける設定は不要だった）。
