# 官公需情報ポータル API の実測（2026-08-14）

## 官公需 API は tender までしか埋めない（2026-08-14 実測）

レスポンスは12フィールド固定（`ProjectName` / `ProjectDescription` / `CityCode` / `OrganizationName` / `CftIssueDate` / `ExternalDocumentURI` ほか）。`Result=1` や `Award=1` を付けても件数もタグ集合も変わらない（**未知パラメータは無視される**）。

- **落札者のフィールドが無い。** `OrganizationName` は発注機関（例: `国立大学法人岡山大学`）であって supplier ではない
- **したがって法人番号も無い。** 英国 ONS が詰まった supplier identifier の問題を法人番号で回避する案は、この経路では成立しない

「誰に落ちたか」を埋めるには各自治体の入札結果公開システムが要るが、東京電子自治体共同運営・東京都電子調達システムは robots が全面拒否。**award の取得条件は取得元ごとに判断する**。

⚠️ **11自治体・17自治体といった数字を「東京62自治体を横断」と言い換えない。** 母集団の誤りは後段の精度改善では救えない。カバレッジは主張ではなく成果物に数値で同梱する。
