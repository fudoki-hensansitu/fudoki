# 事務事業評価を構造化データとして取り込めるか（調査）

2026-11-06。`apps/api/src/evaluation-catalog.json`（46自治体・1,390冊）から、型ごとに実物の PDF を取り、`pdftotext -layout` で文字が取れるかと、載っている項目を確かめた。決算との突き合わせは本番 API（`/v1/expenditure/nodes:search`）で行った。

## 結論

- **「事業ごとのシート」型は構造化できる。** 項目の顔ぶれ（事業名・担当・目的・概要・指標の計画/実績・予算/決算・評価区分）は自治体をまたいでほぼ共通で、違うのは配置と呼び名だけ。
- **決算額で検算できる。** 府中市ではシートの決算額が風土記の決算の木の金額と**1円単位で一致**し、杉並区では千円の表示単位で一致した。[evaluation-search の設計](../prd/evaluation-search/dd.md) が構造化（方式C）を後回しにした理由の1つ「評価シートには合計による検算が無い」は、金額については当てはまらない。
- **ただし共通にできるのは「事業の台帳＋金額＋指標」まで。** 文章（目的・取組・課題）は様式ごとの差が大きく、出典の利用条件（転載・二次利用の禁止）にも当たるので、配るなら所在と短い抜粋にとどめるのが安全。
- 施策ごとの評価・概要一覧だけの自治体は、事業の単位にならない。施策の台帳として別に持つか、対象外にする。

紐づけは3段階になる。

1. **コードで一致**（杉並・府中・青梅）: 款・項・目（と事業）のコードで決算の木の節点を一意に決める。
2. **目＋名前で一致**（品川・豊島など）: 目を決めたうえで、事業名と備考の名前を照合する。名前の揺れは残る。
3. **目まで**（荒川など決算の木に事業の段が無い自治体、頁参照だけの墨田・千代田）: 目に1対多でぶら下げる。

名前での紐づけ（段階2）の手法は、新規事業スレッドがプレス発表の施策→予算書の内訳（fiscal_expenditure_detail, breakdown='事業'）で決めたものを流用できる（2026-11-07 共有、project memory の press-to-budget-linking）。①正規化した名前の一致、または部分一致かつ額の一致で先に確定 ②残りは Intl.Segmenter（ja, word）で単語に分け、共通語（事業・経費・推進・支援など）・助詞・1文字の平仮名を除いた単語 Dice 係数で、同じ自治体・年度の内訳から上位12件を候補にする ③TypeSafe Jev の choice に候補12件＋「どれでもない」から選ばせ、確信度0.6以上だけ採用。品川で直接当たらなかった51頁では、文字 bigram 4/16、e5 ベクトル 3/12、単語 Dice 6/20、候補→Jev 13/22（0.6以上は全部正解）。全行を Jev に見せる案は choice が255択までで目しか選べず不採用。評価シートは決算額も持つので、②の候補を額の一致でさらに絞れる。

どの段階でも、**シートの決算額と木の金額が一致するか**を検査にできる。一致しない分は「紐づけ不明」として残し、風土記の判断で寄せない。

## 共通スキーマ案

事業1件＝1行の台帳と、年度×項目の値の表に分ける。

**evaluation_project（事業の台帳）**
- 自治体コード・評価対象の決算年度・出典（origin_sha256・物理頁）
- 自治体の事業コード（あれば）・事業名・担当部課
- 予算科目: 会計・款・項・目・事業のコードと名前（出典に印字された分だけ）
- 上位の施策（コード・名前）
- 評価: 自治体の評語（原文のまま）と、方向性（原文のまま）
- 紐づけ: 決算の木の node_id・紐づけの段階（code / name / moku）・金額の一致

**evaluation_amount（金額）**: 事業 × 年度 × 段階（当初・予算現額・決算）× 区分（事業費・人件費・総事業費・特定財源など）。単位は出典のまま持ち、円換算を別の列にする。

**evaluation_indicator（指標）**: 事業 × 指標名・単位・種類（活動/成果）× 年度 × 計画/目標/実績。

**evaluation_fact（文章から抜き出した事実）**: 事業 × 種類（新規・拡充／実施件数／未達の理由／次年度の方向性など）× 根拠の一文（原文、短い抜粋）× 物理頁 × 抽出方法（規則 / AI）。画面には根拠の原文を出し、AI の要約は出さない。

- 「新規・拡充」の印は品川スレッドで検証済み（2026-11-06、品川 R6 の652枚、正解は当初予算の R6 新規・拡充11件）。文の規則（「令和6年度から」「開始」「始めた」「実証」等）で169枚・9/11件、費用の前年比+20%を足すと64枚・7/11件。64枚中15枚を読むと本当に新しいのは約6枚。誤りの多くは「指定管理者制度を導入している」の決まり文句と、統合・閉館。規則の段階で除外する。
- 取り出しは二段階: 規則で候補を絞り、小さい AI（Haiku 級か Workers AI）に特徴的事項・取組内容の欄だけ（1枚約2,000トークン）を渡して、該当の一文と頁を必ず返させる。費用は1自治体・1年度で数十〜数百円の見込み（未実測）。
- 「新しくできた事業（シートごと新規）」は別の規則で判定する: 事業期間の開始年度＝その年度、前年度の行政コスト小計Dが0、前年度までの指標の実績が空、の3つがそろうシート（品川 R6 で15件）。開始年度だけだと組み替え・名寄せのシートが混ざる。事業期間が空欄のシートが282枚ある。
- 品川の指標の表は `pdftotext -bbox` で列の x 座標を見ると R4〜R7 と目標値が取れる（`-layout` の文字列では列がずれる）。
- 限界: 避暑シェルター・携帯トイレの全戸配布のように、シートに書かれない新規事業は拾えない。当初予算の新規・拡充の一覧と突き合わせる前提にする。

評価の評語は自治体ごとに尺度が違う（A〜C、4段階×3視点、順調/停滞、推進/縮小…）。共通の尺度へ寄せるのは風土記の判断になるので、原文のまま持ち、比べられるのは「方向性が拡充・縮小・廃止か」程度に絞るのが無難。

## 難しさと危険

- **様式ごとの抽出設定が要る。** 1自治体の中では様式が固定なので、設定は自治体（と年度の改訂）ごとに1つ。46自治体のうち事業シート型はおおむね30前後と見込む（題名からの推定）。
- **文字の層の質。** 墨田・中央・板橋で poppler-data が無い警告が出た（クラウド環境の既知の差）。府中などは長い文が欄外で切れる。表の取り出しには既存の取り込み（pdfplumber・ノードの表）を流用できる。
- **全件ではない自治体がある。** 青梅は19事業の抜粋、立川・国立などは対象を絞った評価。決算に対する「網羅率」を一緒に出さないと、事業が無い＝支出が無いと読まれる。
- **利用条件。** 北区・中野区は転載・二次利用を禁じている（[evaluation-search の設計](../prd/evaluation-search/dd.md)、2026-10-14確認）。金額・指標の数値と事業名は事実の記録として配りやすいが、目的・取組・課題の文章を配布物の列にするのは避け、所在と抜粋にとどめる。どこまで配るかは判断が要る。
- **PRD の Non-Goal との関係。** evaluation-search の PRD は「決算の科目と評価の事業の対応を風土記の判断として保存しない」としている。コードと金額の一致で決まる紐づけは判断ではなく出典どうしの照合なので、ここを PRD 改訂で線引きする必要がある。

## 次の一歩の案

杉並（コード・金額・指標がそろい、決算 R6・R7 も収録済み）で、台帳＋金額＋指標を取り出し、決算の木との一致率を測る。品川（名前での紐づけ）を2つ目にして、名前照合でどこまで当たるかを見る。この2つの結果で、全自治体に広げるかを決める。

- 見た10自治体はすべて、サイト全体を CC BY などで開いておらず、CC BY はオープンデータとして載せたデータだけに付いている。評価資料はどこもオープンデータに入っていない。
