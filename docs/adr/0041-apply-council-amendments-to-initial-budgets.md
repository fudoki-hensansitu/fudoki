# ADR 0041: 議会の修正案を当初予算の承認額に当てる

状態: 採用（2026-11-11）。

議会が当初予算を修正して可決し、予算説明書が原案の額で印字されているときは、修正案の資料も取り込み、dbt で予算説明書の承認額を修正後の額に直す。風土記の当初予算（approved）は議会が承認した額だからである。

修正案は、予算説明書とは別の出典として取り込む（例: 131148 中野区 R7 の第7号議案）。その表は、修正した事務事業だけを持つ。修正金額を本年度予算額、原案金額を予算案額とし、款・項・目と上位の事務事業は金額を持たない。予算説明書の表は印字のまま変えない。

修正案の表は seed `fiscal_budget_amendment` で宣言する。宣言した表のノードは木に加えない。行ごとに 修正金額−原案金額 を求め、予算説明書の同じノードと、款までのすべての祖先の承認額に足す。修正案の行は、予算説明書と同じ会計・款項目コード・事務事業の見出しと番号・名称を持つので、同じ node_id になる。

修正案が書かない枝は、原案の額のまま残る。中野区 R7 では、どの節を減らしたかが書かれていない。

## Consequences

修正した目と事務事業では、節の和が目の額と修正額の分だけずれる。木の検査（`fiscal_tree_balances`）は、修正したノードの子の和が修正前の額と一致するときだけ通す。

修正した額は、どの頁にも1つの印字として載っていない。そのため、修正したノードは金額の印字位置を持たない。

`fiscal_budget_amendment_applied` は次の2点を確かめる。

- 宣言した表があること。
- 修正案の行が予算説明書のノードに当たり、原案金額が予算説明書の印字と一致すること。

修正案の読み方は、自治体の変換器に置く（`jurisdictions/131148/layouts/council_amendment`）。この変換器は、第1表の款・項の差が事務事業の差の和と一致することも確かめる。修正案の書式は自治体ごとに異なるので、2例目が出たら共通の読み方にするかを決める。
