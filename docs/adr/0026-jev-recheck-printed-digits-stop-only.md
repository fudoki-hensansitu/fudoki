# ADR 0026: 印字された数字の網羅に Jev の聞き直しを、止める方向だけで足す

状態: 採用（2026-10-13）。[保存設計](../prd/ingestion-storage/dd.md) の印字された数字の網羅の検査（`check_digit_coverage`）に、Jev（TypeSafe）の聞き直しを足す。網羅の検査の合否の規則は変えず、止まる数字を増やす方向にだけ働かせる。

聞く数字は2種類だけにする。弱い規則（頁脚・年月日・番号・数量・％などの非金額の形）で非金額として通した数字と、金額の列の帯の外で説明がつかず報告だけになっている数字である。採用した金額・ノードの番号と名前、合計、宣言した非採用の範囲で説明がつく数字は聞かない。数字を含まない文字（名前・見出し）の網羅は入れない。問いは「この数字は表の項目の金額として取り込むべき値か」とし、0.7 以上を「取り込むべき金額」として止める。Jev の答えで、止まっている数字（帯の中の取りこぼし）を通すことはしない。

数字のまわりの文脈は、コードで文章に組み立てて渡す。同じ行の語を左から並べて対象を【】で示し、列の見出しと上下の行を添える。座標の数値と、規則が通した理由は渡さない。モデルは `jev-1.13.0` に固定する。

答えは入力の fingerprint（文脈の文・問いの文・基準・モデル・しきい値）と確率だけを `<方向>.digit-recheck.jsonl` として Git の manifest の横に保存し、検査のやり直しでは API を呼ばずに再現する。答えが無く API key も無いときは、飛ばさずに止める。

## 理由

網羅の検査の弱い規則は、形（桁区切りのない数、番号に見える数）から「金額でない」と決めるため、規則が誤っても沈黙する。帯の外の報告は、列の境界が宣言されていない取りこぼしを件数としてしか残さない。この2種類は規則だけでは網羅の穴の存在を確かめられず、文脈の意味を読む判断が要る。一方、判断を通す側に使うと、帯の中で止まっている本物の取りこぼしを Jev が通しうる。止める方向だけに使えば、Jev の誤りは「人が原典を見て分類する手間」に収まり、取り込み表の正しさは悪化しない。

規則が通した理由を渡さないのは、実験で理由を渡すと本物の金額を見逃しやすくなったためである。頁全体の座標の並びから対象を探させ、「役割」を4択で聞く方法（PR #107）は、確率が過剰な停止を生み、しきい値を 0.99 まで上げて効果が 0 件になった。対象を1つに絞り、同じ行の語として文章にして渡す方法に変えた。

答えを Git に置くのは、答えが「判断」であり、コード・宣言・判断・入力一覧を Git に置く保存の原則に合うためである。fingerprint と確率だけなら原典の文字は Git に入らず、PR で答えの差分を見られ、R2 とスキーマを触らずに再現できる。

## Consequences

- 確率は同じ問いでも、同じリクエストに入る他の問いの組み合わせで±0.1 前後動く（再実験で 660 問中 39 問が 0.7 をまたいだ）。1問ずつ聞くと確率の揺れは小さい（0.7 をまたぐのは 10 問）が、誤検出が 0.3% から 1.3〜2% に増え AUC も下がるため採らない。答えは保存して再現する記録であり、聞き直すと止まる数字が数個入れ替わりうる。問いはフィンガープリント順に束ね、同じ問いの集合は同じ組み合わせで聞く。
- 止まった数字は、人が原典の頁で本物か聞き方の誤検出かを分ける。本物は変換器（採用・非採用の宣言・注記の取り込み）を、誤検出は共通の規則を直す。誤検出を Jev の答えの上書きで通す設定は置かない。科目コードの印字（`1項`・`（目）2`）は、採用したノードの階層記号と番号の組として共通規則で説明する。
- 帯の外の報告のうち、確率がしきい値に満たない本物の金額は引き続き沈黙する。しきい値の較正は、本物の取り込み漏れを原典で分類した件数がそろってから見直す。
- `ingestion/lib/node_tables.py` は変換器の依存で fingerprint に入る。聞き直しの本体 `digit_recheck.py` は `node_tables.py` から import せず、Recheck を受け取る形にして、問い・モデル・しきい値の変更が保存済みの表を古くしないようにする。
