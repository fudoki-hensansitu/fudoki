# 結び付きの強いPDFの読み方も共有ルールとして選ぶ

自治体別の変換器には、表の境界・見出し・金額の所属を一緒に判定しないと現在の表を保てない処理がある。これらを既存の罫線・字下げパターンへ一律に押し込むと、印字の保持や親子の所属が変わるため、まとまりを保った読み方を共有ルールとして追加する。独立できる文字復元・見出し・継続合計などは選択式の部品へ分け、自治体側には実測値・文字の訂正などのJSON宣言と、そのルールの選択を置く。

## Consequences

`options.workflow.reading` が共有の読み方と宣言を、`components` が必要な部品を指定する。必要な部品の不足・重複・余分な選択は止める。利用例が一つでも共有ルールへ置けるが、別の自治体への適用は出典全体の検査で確認する。コードを共有の場所へ移したことだけで、未検証の資料にも対応したとは扱わない。

既存の層別workflowと追加のまとまった読み方は、同じカタログ・選択解決・指紋の仕組みに載る。後者は文字PDF専用の入口を使う。固定済みOCR観測の入力は既存の層別workflowを使い、今回の文字抽出に依存する読み方へ暗黙に流さない。

指紋は選択した読み方・部品・その依存と、参照するJSON宣言・schemaを含める。未選択のルールの編集では再変換しない。途中結果の新しい保存は設けず、既存の内容比較による指紋更新を使う。自治体別に残る独立検査や未採用資料の支持コードは、採用中の変換経路と区別して保持する。
