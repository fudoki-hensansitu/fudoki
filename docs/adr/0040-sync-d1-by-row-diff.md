# ADR 0040: D1 への同期は行の差分で行う

状態: 採用（2026-11-11）。[ADR 0022](0022-serve-marts-via-worker-d1-rest-and-mcp.md) の「更新は表ごとの全件の入れ替えで行う」を置き換える。

`serving:sync` は、既定で変わった行だけを D1 に書く。

1. 表ごとに D1 の列（名前・型・主キー）と index を `columns.json` と比べる。表が無い・違う表は、従来どおり `<表>__new` に全件を入れ、全行を読み戻して照合してから入れ替える。
2. 残りの表は、warehouse の主キー順に一定の行数ずつ区切った範囲ごとに D1 の行を読み、warehouse の同じ範囲と主キーで突き合わせて全列を比べる。D1 にだけある行を消し、新しい行と列のどれかが違う行を `insert or replace` で書く。
3. 書いた後は、差のあった範囲を読み戻して照合し、表の行数も比べる。
4. 変わる行が表の半分を超えたら、その表は作り直す。既存の行の置き換えは削除と挿入の2回分書くので、作り直すほうが書き込みが少ない。

`--full` で全表を作り直せる。`--jurisdiction` は、表ごとにその自治体の行だけを D1 と warehouse の両方から選んで差分を書き、他の自治体の行には触れない（2026-11-12 改訂。以前は D1 をその自治体だけに作り直す動作確認用だった）。自治体コードを持たない表は親の表の自治体で選ぶ。作り直しは全自治体の行が要るので、列・index が違う表にその自治体の行があれば止める。消す行は参照する表から、書く行は参照される表から流し、途中で止まっても親の消えた子の行を残さない。その自治体だけを build した warehouse（`dbt:build --jurisdiction`）は部分的なので、`--jurisdiction` なしで同期する前に全件で build し直す。

差は前回の同期の記録ではなく、D1 の今の中身と比べて決める。途中で止まった同期の続きや、手で消した行も次の同期で埋まる。D1 に hash や版の表を持たない。

D1 の書き込みは行数で課金され、表への1行の書き込みに加えて主キーと各 index にも1行ずつ数えられる。2026-11-10 時点で本番は約74万行あり、全件の入れ替えは1回で約290万行を書いていた。11月は10日までに約1,850万行を書き、Workers Paid に含まれる月5,000万行に近づいていた。23区・多摩の当初予算を入れると1回の同期が数倍になる。

## Considered Options

- **全件の入れ替えを続ける**: 実装が単純で、表の世代が揃う。書き込みが同期のたびに全行×（表＋主キー＋index）になり、行数とともに月の上限を超えるため採用しない。
- **自治体・年度などの区画ごとに hash を持ち、変わった区画だけ入れ替える**: 読み戻しが区画の hash だけで済む。区画の hash を D1 か別の場所に持つ必要があり、その記録と D1 の中身がずれると直らない。区画の中の1行が変わっても区画の全行を書く。行の差分は D1 の読み取りが全行分になるが、読み取りは Workers Paid に月250億行含まれ、全国規模でも小さいため、行の差分にした。
- **当初の決定（ADR 0022 の検討で退けた、パーティションごとの行の差分）**: 列が変わるたびに版を上げて全行を書き直し、手書きの列一覧と migration が要るとして退けた。今回は列か index が変わった表だけを作り直すので、版も migration も持たない。

## Consequences

同期の途中では、差分を書いた表と入れ替え前の表が混ざり得る。D1 は warehouse から作り直せる写しなので、従来どおり可用性は担保せず、失敗したら同期を流し直す。作り直す表の照合は本名の表に書く前に行うので、照合に失敗した同期は本名の表を変えない。

D1 の読み取りは、同期のたびに全行分になる。読み戻しは主キーの範囲で引くので、主キーの index で読む行だけを数える。
