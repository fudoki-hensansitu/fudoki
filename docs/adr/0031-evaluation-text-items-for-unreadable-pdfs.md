# ADR 0031: 検索の取り込みで本文が空になる評価資料は、手元で抜き出した頁の文字を item にする

状態: 採用（2026-10-19）。同日に実装し、60出典を文字の item で登録し直した（[拡大の確かめ](../prd/evaluation-search/dd.md#拡大の確かめ)）。[評価の検索の設計](../prd/evaluation-search/dd.md)の「頁単位の PDF を item にする」登録と、`index.py` の本文の確かめ（手元の文字数と取り込み後の文字数の比較）を前提とする。

評価資料の索引（Cloudflare AI Search `fudoki-evaluation-v1`）は、出典を1頁ずつの PDF に切り出して登録している。そのうち60出典（墨田区の2023年度の30、杉並区の2023年度の29、狛江市の2020年度の1）は、pdfium・pdftotext では読めるのに、AI Search の変換後の本文がほぼ空になる（手元で2,000字前後の頁が1〜5字）。どれも埋め込みの無い CID フォント（CMap `UniJIS-UCS2-HW-H`・`UniJIS-UTF16-H`、ToUnicode なし）を使っている。本文の確かめで登録の記録を書かず、catalog から外しているので、杉並区の2023年度と狛江市の2020年度は `not_covered`、墨田区の2023年度は一部のファイルが欠けている。

2026-10-19 に、杉並区・墨田区の1頁ずつで次を試した（試しの item は確かめた後に削除した）。

- 頁の PDF のフォントに恒等の ToUnicode を足して登録した: 変換後の本文は元の PDF と同じ2字で、変わらなかった。AI Search の変換は、文字の対応が分かっても埋め込みの無いフォントの文字を拾わないとみられる（変換器の中身は公開されていない）。
- pdfium で抜き出した頁の文字を `.md` の item として登録した: 変換後の chunk は抜き出した文字そのもの（2,502字）で、PDF のような見出し（`# <key>` …… `### Page 1`）は付かなかった。

## 決定

- 本文が空になる出典は、頁の PDF の代わりに、pdfium で抜き出したその頁の文字を item にする。key は `<origin_sha256>_p<頁4桁>.md`、metadata（`jurisdiction`・`fiscal_year`・`origin_sha256`・`page`）は PDF の item と同じ。頁と出典の対応は変えない。
- どの出典を文字の item にするかは、`pipeline/evaluation_search/instance.json` の config に出典の sha256 の一覧として宣言する。自動で判定しない。変換が読めない条件を推測でしか書けないため、本文の確かめで落ちた出典を宣言に足す。
- 抜き出しは `index.py` が行い、pdfium の版は `uv.lock` で固定する。同じ出典と版からは同じ文字になる。登録の形（PDF か文字か）は計画の fingerprint に含め、形を変えれば登録し直す。
- 本文の確かめ（取り込み後が手元の1/10以上）は、文字の item にも同じく当てる。
- catalog の各出典に登録の形を持たせ、Worker の照合（`verify`）は catalog の形から期待する key（`.pdf` か `.md`）を組み立てて照らす。どちらの形も受ける照合にはしない。見出しの除去（`stripHeader`）は、先頭が `# <key>` でない chunk をそのまま返すので変えない。
- 検索が返すものは変えない。URL・sha256・頁は出典の PDF を指し、抜粋は抜き出した文字から作る。利用者は出典の PDF で内容を確かめる。

## 検討した案

| 案 | 利点 | 採否 |
| --- | --- | --- |
| A. 抜き出した頁の文字を item にする（採用） | 手元で読めている文字をそのまま渡すので確実。Worker の変更は照合の key だけ | 文字の並びは pdfium の抜き出しのままで、表の列の対応は崩れる（PDF の変換でも同じ）。登録の形が2つになる |
| B. 頁の PDF に ToUnicode を足す | 登録の形が1つのまま | 試して効かなかった |
| C. 頁の PDF にフォントを埋め込む | 登録の形が1つのまま | MS ゴシックなどの埋め込みの許諾が要り、ファイルが大きくなる。変換が読むかは未確認 |
| D. OCR ありのインスタンスで取り込む | 文字の層が無い出典（scan）にも使える | 課金の資源が増え、文字の層があるのに認識で読み直すので誤りが入る |
| E. catalog から外したままにする | 何もしなくてよい | 杉並区の2023年度と狛江市の2020年度は引けず、墨田区の2023年度は欠けたまま |

## Consequences

- 60出典を catalog に戻せる。杉並区の2023年度と狛江市の2020年度は `not_covered` でなくなり、墨田区の2023年度の注記から「検索の取り込みで文字を読めない30ファイル」が消える。
- 文字の item は、AI Search の PDF の変換ではなく pdfium の抜き出しの結果である。変換で崩れ方が変わっても、文字の item には影響しない。
- 今後の拡大で本文の確かめに落ちた出典は、宣言に足して登録し直せば収録できる。scan の出典はこの方法では扱えない（抜き出す文字が無い）。
- `.md` の item は Markdown として扱われるとみられる。抜き出した文字の行頭に `#` などがあるときの扱いは確かめていない。本文の確かめで文字数が大きく減れば記録を書かないので、その時点で分かる。
