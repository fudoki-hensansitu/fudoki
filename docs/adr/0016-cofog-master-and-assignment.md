# ADR 0016: COFOG マスタと明細への割当を分ける

状態: 採用（2026-10-01、2026-10-03 に配布・検索の保存方式を除外、2026-10-11 に親コードをマスタから、根拠を明細から外す、2026-10-13 に項・款の fallback 規則を追記）

## 背景

分類コードの共通定義と、明細ごとの分類判断は別の概念である。同じ割当先を複数の階層列へ重ねて保存すると、分類の定義と結果の関係が曖昧になる。

## 決定

COFOG のコードと名称は共通マスタ `cofog_master` に置く。コードは `04.1.2` のように点で段を区切り、親は末尾の段を削ったコード（`04.1`）とする。親コードの列は持たない。コードから決まる値を別の列に重ねると、食い違いの検査が要るだけで情報が増えないためである。Git の `packages/fiscal/cofog-master.ts` の定義から現在使用するコードと祖先を生成する。

歳出明細は割り当てた粒度の `cofog_code` 一つと分類状態を持ち、上位分類はコードの前方一致（`04` 配下は `04` または `04.%`）で求める。未割当には NULL のコードと明示した状態を使う。歳入に COFOG を付けない。division / group / class を別々の列に宣言しない（同じ事実が3箇所に分かれ、粒度を下げたとき片方だけ古くなる）。

粗い粒度は誤りではない。款の名称だけで決まる規則（総務費→01、民生費→10）は division 止まりが正しく、空の下位は「該当が無い」ではなく「まだ降りていない」を意味する。

分類規則は Git の宣言から中間処理で適用し、規則 ID も規則の根拠の文も提供用データへ含めない。追跡はコード版・固定入力とパイプラインの検証記録で扱う。金額・分類・連結判断を上流と照合し、生成済みの表を独立編集する正本にしない。

COFOG を段ごとの列と規則の列で持っていた旧処理の配布契約（`packages/fiscal/detail.ts` など）は 2026-10-11 に削除し、COFOG のコードと名称は `packages/fiscal/cofog-master.ts` に残した。新しい提供用データの列は [dbt モデルの設計](../prd/fiscal-dbt-models/design-doc.md) を正とする。境界の判断で確信が持てない割り当ては、コードを付けたまま分類状態を `tentative` として区別する。特別会計の目は団体限定を足さず会計の種類で当てる共通の規則（`match_account_kind`）に寄せ、行き先が違う目だけ語の規則で分ける。

語の規則に当たらない目の受け皿として、項・款が機能を決める場合だけ項・款の名称で当てる共通の fallback 規則を最後に置く（`fallback-kou-*`・`fallback-kan-*`）。priority を語の規則より大きくするので、語の規則に当たる目の割り当ては変わらない。項の中身が混じる項（社会教育費・保健体育費・都市計画費・土木管理費）の fallback は `tentative` にする。代替案は団体ごとに目の名前を足す規則で、団体を増やすたびに規則が増え、同じ項の目の扱いが団体で揺れるため採らない。fallback は新しい目を黙って受けるため、`tentative` の目は確かめる一覧（cofog_status が tentative の目を金額順に並べたもの）で見直す。

## 結果と代替案

分類の共通定義と個々の判断を区別し、割当済みコードの参照と未割当の状態を検査できる。分類結果を独立した1対1表にする案は、明細と常に一緒に確定する判断に別の識別子を増やすため採用しない。配布・検索の物理的な保存形式は後段で検討する。
