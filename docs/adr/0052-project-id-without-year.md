# ADR 0052: 事業ID は年度と資料区分を除いた鍵から作る

状態: 採用（2026-11-17）。[ADR 0046](0046-projects-linked-on-every-build.md) の決定3を置き換える。

1. 事業ID は、事業の最初の年度の行の鍵から年度と資料区分を除いたもの（自治体・会計・款・項・目・比べる名前の並び）の sha256 にする。比べる名前は、つなぎで使う正規化（NFKC、所管課・注記・空白を除く）を通したもの。
2. 同じ鍵の別の事業（一度終わって同じ名前で始め直した事業、同じ年度に同じ並びが2つある行）は、後から現れたほうに始めた年度を足して分ける。同じ年度の中の順は、当初予算の行を持つほう、印字の順、`detail_id` の順で決め、`int_project__lines` の行の並びに左右させない。
3. 前の年度とつながった事業は、これまでどおり前の年度の ID を引き継ぐ。

ADR 0046 の鍵は年度を含んでいたので、過去の年度を取り込むと、それとつながる以降の年度の事業が全部別の ID になった。D1 の差分同期では事業と事業の年度が丸ごと消えて書き直しになり、2026-11 の D1 の書き込みが月の枠（5,000万行）を超えた一因になった。全自治体の取り込み（約99万行）で、最初の年度を1年分外した場合と外さない場合を比べると、ID が変わる行は ADR 0046 の鍵ではつながった事業のほぼ全部、この鍵では 19,506 行（約2%）だった。残る変化は、足した年度に同じ鍵の事業が2つあり、どちらが無印の ID を取るかが入れ替わるもの。事業の数（416,381）と行の分け方は ADR 0046 の鍵と全く同じで、ID の重なりは無かった。

## Considered Options

- **ADR 0046 の鍵のまま**: 過去の年度を足すたびに事業の表が丸ごと書き直しになる。
- **UUID・nanoid を振り、R2 などに保存して読み戻す**: 収録を足しても変わらないが、保存と読み戻しの仕組みが増え、build が保存先に依存する。手元の build と CI で ID が食い違わないようにする手間もかかる。
- **ID に年度を入れず、科目と名前だけで作る（この ADR）**: 保存を持たずに、収録を足しても大半の ID が変わらない。同じ鍵の事業が並ぶ場合だけ、足し方によって ID が入れ替わりうる。

## Consequences

- 過去の年度を取り込んでも、つながった事業の ID は変わらない。取り込みを直して最初の年度の行の科目・名前が変わると、その事業の ID は変わる。
- 切り替えの build では、全部の事業の ID が一度だけ変わる（D1 の書き込みは事業と事業の年度で約770万行）。
- 評価シートは ID が変わりうるので、引き続き `project_id` を鍵にしない（[評価モデルの設計](../prd/evaluation-model/dd.md)）。
