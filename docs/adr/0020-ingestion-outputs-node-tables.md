# ADR 0020: PDF の取り込みは出典の印字項目をノードの表と金額の表で出す

状態: 採用（2026-10-11）。2026-10-11 に管理JSONの PDF の表をノードの表と金額の表へ移行済み。

PDF の取り込み（B）は、出典に印字された項目（款・項・目・事業・節・細目など）を1行とするノードの表と、印字された金額を1行とする金額の表を出力する。ノードは親のノードと分解の軸を持ち、金額は所属するノードと金額欄の出典の見出しを持つ。末端の行に祖先の名称・金額を反復する横持ちの表は、新しい取り込みの出力にしない。CSV の出典は対象外で、原文の行と1対1の表のまま取り込む。

## 理由

取り込みは、PDF から款・項・目や事業 → 細目の所属を復元した時点で、すでに木を持っている。横持ちの表はその木を平らにしたもので、後段の dbt は平らな表からもう一度木を組み立てる必要があった。この往復のうち平らにする工程が、変換器ごとの列構成の違い（131024 の751列、段ごとの列名、`column_contexts` の `header_path`・`grain_columns` の宣言）を生んでいた。

ノードの表なら、目より下の段の数と種類が自治体ごとに違っても列は変わらない。一つの項目に並ぶ複数の金額（当初予算額・支出済額など）は金額の表に縦に持つので、金額欄の見出しを列の値として出典どおりに残せる。「子の金額の和＝親の金額」の検査も、自治体によらない一つの問い合わせで書ける。

## Considered Options

- **横持ちの表を続ける（現行）**: 変換器を変えずに済む。列構成の違いを dbt の書式ごとの宣言で吸収し続けることになり、平らにして戻す往復も残るため採用しない。
- **graph DB に入れる**: 任意の深さの探索に強い。対象は親が一つの浅い木で、主な処理は集計と検査である。Parquet の表で親子を持てば足りるため採用しない。
- **階層を JSON・配列の列に入れ子で持つ**: 出典の構造をそのまま表せる。取り込みの規約が出典の欄を JSON・配列・STRUCT の列に入れることを禁じており、集計と検査も展開が要るため採用しない。
- **段ごとに表を分ける（款の表・項の表…）**: 段の意味が列名で分かる。段の数と種類が自治体で違うので、表の種類が自治体ごとに増えるため採用しない。

## Consequences

- OCR・PDF から表を作るコストのうち、消えるのは平らにする工程だけである。各数字がどの段のどの項目に属するかを決める作業は、出力の形によらず取り込みに残る。
- 既存の73表と17の変換器はすぐには作り直さない（決定時の80表・18変換器から、2026-10-11 に 132039 水道の7表と変換を外した）。横持ちの表と metadata からノードの表と金額の表を作る共通の変換を取り込みに置き、移行する（2026-10-11 に管理JSONの移行が済み、横持ちの表は使わない）。新しい変換器はノードの表を直接出す。
- [保存設計](../prd/ingestion-storage/dd.md) と取り込み・dbt の手順（`.agents/skills/pipeline/references/ingestion.md`・`dbt.md`）は、2026-10-11 にノードの表を前提に改めた。新しい取り込みは横持ちの表を作らない。既存の横持ちの表は移行で置き換えた。横持ちの表から移行する共通処理と、旧形式の説明（[PDF の表の共通モジュール](../pdf-table-module.md) など）は残している。
- 表の単位で決まる事実（出典ファイルの SHA・会計名・注記）は管理 JSON に置き、ノードや金額の行へ反復しない。
- CSV は款・項・目・節が最初から別の列に並び、取り込みが復元する木がない。取り込みでノードの形に変えると、原文の行と1対1で全セルを照合する検査の保証が弱まるため、ノードの形への変換は dbt の intermediate で行う。dbt の入力は PDF のノードの表と CSV の原文の表の2つの形になり、CSV だけは書式ごとの staging が要る。
- dbt は構造の復元をしなくなり、金額の段階の選択・単位換算・自治体の統合・COFOG の判断・検査を受け持つ。設計は [dbt モデルの設計](../prd/fiscal-dbt-models/dd.md) を参照する。

## 改訂（2026-10-11、W-3）

- 金額の表の各行は、その金額の印字の頁・座標（文字層の単語の box）を持つ。text PDF の変換器が金額列ごとに位置列を出し、移行は金額自身の位置だけを使う（名称の位置の流用なし）。
- 保存前に、木の検査と並ぶ自治体共通の検査として、処理した頁・領域の文字層にある数字の印字の網羅を数える（text PDF のみ）。金額帯に入る未網羅の数字は保存を止め、帯の外の数字は件数と例を報告する。

網羅の検査の照合は同じ出典・物理頁を読む全表を集めて行う。非採用の表の範囲は観測用の読み分けから実行時に生成し、人が宣言するのは共通語彙の種類と理由だけとする。採用金額の枠に重なる数字の断片は、その数字を完全に再構成できる場合だけ網羅済みにする。

ラベルのない合計行は、同じ親（または同じ親の同じ頁）の採用金額の和を、独立した2列以上の0以外の印字と照合できる場合に限って網羅済みにする。合計の印字がある行も値を照合し、0だけの一致では認定しない。
