# ADR 0029: 決算の歳出の保存の関門に、款の軸と支出済額の存在を確かめる検査を足す

状態: 採用（2026-10-14）。[ADR 0027](0027-refresh-fingerprints-by-table-content.md) の保存の関門（`storage.prepare_save`）と、検査だけのモジュール（`*_checks.py`）を前提とする。[ADR 0028](0028-unit-check-in-the-save-gate.md) と同じ場所に当てる。

木の検査は「印字された親の金額＝子の和」、網羅の検査は「印字された数字が金額の行か非金額の規則で説明できたか」を見る。どちらも金額が付いたものの和と、印字の使われ方だけを見るため、**支出済額という金額の段階が無い表**と**款のノードが無い表**を止められない。金額が1つも無ければ親も子も 0 で和が一致し、印字された数字はすべて既存の弱い規則（頁脚・番号・数量・見出し）で説明できてしまう。単位の確かめ（ADR 0028）も、印字の歳出合計が無い表では桁だけになり、一般会計以外は比べるものが無い。

2024年度の16自治体60表を `generic_text` で関門に当てた実測で、通った7表（豊島の4表・練馬の介護保険・世田谷の一般会計と介護保険）がどれも支出済額の列を持たず、marts の目の金額が NULL になった（[実測](../prd/generic-node-builder/dd.md#関門の抜け)）。保存の前に、決算（`document_kind='settlement'`）の歳出のうち公営企業会計以外の表へ、次を要求する。モジュールは `ingestion/fiscal/subject_checks.py`（検査だけで、指紋の外）。

- 親の無い款のノードが1つ以上あり、そのうち1つ以上が印字された支出済額（印字された0を含む）を持つ。
- 目が1つでもある会計は、印字された支出済額を持つ目が過半（`2 * executed > total`）である。款・項だけを印字する会計は、印字されていない目を分母に足さない。

## 検討した案

| 案 | 利点 | 採否 |
| --- | --- | --- |
| 木の検査と網羅の検査だけで足りる | 新しい仕組みを足さない | 支出済額が0件の表で和が 0=0 になり通る。実測の7表で確認した |
| ノード数・金額数の下限を自治体ごとに置く | 会計の規模に合わせられる | 閾値の根拠がなく、正しい小さい会計を止める。自治体ごとの例外が増える |
| 款の存在だけを要求する | 規則が小さい | 款があっても支出済額が無い表（歳入様式・総括の混入）を通す。目の支出済額も要る |
| 款の存在と、目の支出済額の過半を要求する（採用） | 会計の規模に依らず、出典の印字だけで決まる | 款が無い表・支出済額の列が無い表を止める。款・項だけの会計は目を分母にしない |
| 変換器が支出済額の列を返す契約にする | 比べる値が確実 | 各自治体の変換器と scan の経路を直す必要があり、印字の列名の辞書で足りる |

## Consequences

- 決算以外（当初予算）、歳入、公営企業会計には当てない。`document_kind`・`direction`・`statement_kind` で場合分けし、当てない表は `applicable: False` を返す。
- 検査は `unit_checks.check_table` から呼び、ADR 0028 と同じく保存の関門（`run.convert`・`storage.prepare_save`）と `verify` で当たる。止まった理由は `describe` が「款の科目軸がない」「款の支出済額がない」「目の支出済額が過半に満たない」として返す。
- 検査のコードは `*_checks.py` に置くので指紋の外である。厳しくした後に保存済みの表を止めたい場合は、`ingestion:verify --remote` で全表に当て直す。
- 止まる表は、変換器（支出済額の列の読み）か宣言を直す。金額や科目を推定で補わない。
