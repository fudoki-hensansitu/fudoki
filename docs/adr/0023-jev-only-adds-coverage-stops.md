# ADR 0023: Jev は網羅検査の停止を追加するためだけに使う

状態: 採用（2026-10-12）

文字層の数字を網羅する検査では、金額の枠・ノードの番号と名前・非採用範囲による照合を先に行う。正規表現による「金額でない」、合計行、注記によって通った数字には、TypeSafe の Choice を用いて別に役割を尋ねる。共通処理 `ingestion/lib/jev_recheck.py` が、ルールと異なる選択を確率 0.99 以上で返した数字を追加で止める。現在止まっている数字と報告だけの数字も尋ねるが、回答は診断に添えるだけで合否を変えない。

## 理由と代案

正規表現や辞書の語の一致だけでは、実際の表の金額を誤って説明できたことにしてしまう。Jev を併用しなければ、その誤りは木の合計が成立する場合に見逃される。一方、Jev の回答で既存の停止を取り消すと、モデルの誤りが未収録の金額を通す経路になる。追加停止だけに使えば、確率の高い誤判定は人が調べる手間を増やすが、既存検査の保証を弱めない。

金額の枠・ノードの番号と名前を確認できた数字は尋ねない。非採用範囲には実際の金額があるため、その数字を尋ねても採用する表の欠落の根拠にならない。団体や表ごとの閾値・質問は持たず、検査の scope 外にある見出しも含む頁全体の文字と座標を共有 state にして対象の数字をまとめて尋ねる。上限を超える場合は質問の束、必要なら隣接行の文脈を保った頁の帯に分ける。

## 再現と版

モデルは `jev-1.13.0` に固定する。model・state の SHA-256・質問の SHA-256 を鍵に回答の確率分布を `<表ID>.jev.json` に保存する。閾値とルールの判定は鍵に含めず、同じ回答を別のルール・閾値でも評価できるようにする。同じ変換操作内の複数表が同じ state・質問を使う場合は回答を共有し、同じ原典の同じ数字に重複した問い合わせをしない。各表の sidecar には単独で再検査できる回答を持たせる。

候補の sidecar には網羅検査の scope と Jev に渡した頁全体の文字も保持し、管理 JSON の任意の `jev.object` 参照で表とともに保存・復元する。財政データの Parquet 参照とは分ける。`ingestion:verify` は scope とキャッシュから再計算し、API を呼ばない。キャッシュが欠けた候補は停止する。変換時には mise + age で注入した `TYPESAFE_API_KEY` によって不足分だけ問い合わせ、キーもない場合は理由を示して停止する。旧保存済み表には sidecar がないため、再変換・保存まで従来の木の検査だけを適用する。

回答の再生成にはネットワーク・費用・将来のモデル提供状況への依存が残る。毎回問い合わせる代案では、同じ入力から同じ検査結果を再現できない。モデルの版・質問・文字層の変更時は該当するキャッシュだけを更新し、閾値の変更だけでは問い合わせを増やさない。

2026-10-12 の45表・10,007質問では、0.9 の追加停止51件と0.95 の15件はすべて合計・頁番号の取り違えで、0.99 の追加停止は0件だった。この観測から共通閾値を0.99にした。本当の見落としはこの標本に無く、検出率の較正は保留する。低い確率の本当の見落としを止められなくなる代わりに、正常な表の再変換を繰り返し止める負担を抑える。W-3d の注記規則を取り込んだ後に再評価する。

閾値の実測結果と追加停止の原典照合はローカルの `.agent/report.md` に記録する。W-3d のルール変更後の全量再評価は別途行う。
