# ADR 0030: 所属（局）ごとに分かれた明細書は、所属を表の事実として宣言し、dbt で足して1つのノードにする

状態: 採用（2026-10-16）。[ADR 0025](0025-level-names-by-shared-rule.md) の科目の段の名前と、intermediate が款・項・目の番号で表をまたいでノードを1つにする規則（`int_fiscal__settlement_expenditure_rows` の `node_id`）を前提とする。

神戸市（281000）の2025年度決算は、目・節の粒度の明細が全市一括では公開されず、市会の決算特別委員会に局が出した「決算説明書」に**局の所管分**の事項別明細書として載る（[選定](../../pipeline/source_selection/281000.json)）。どの冊も款・項・目・節の番号と名称は市の科目体系のままで、金額だけがその局の分である。同じ「2款1項1目 一般管理費」が9冊に、それぞれ違う額で載る。

これまでの intermediate は、同じ団体・年度・会計・款・項・目のノードを表をまたいで1つにまとめ、名称か支出済額が食い違えば止めていた（同じ明細が別の冊に重ねて印字されるときの一致の確かめ）。局の冊はこの前提に合わない。款・項・目は金額の食い違いで止まり、目の下の節は別の局の同じ節が同じ `node_id` になって最初の行だけが残る。

## 決定

- 変換の options に `division`（その表が印字する所属。神戸市では局の名称）を書く。原典の表紙・見出しに印字された事実であり、判断ではない。変換の受領（管理 JSON の `tables[]`）に `division` として残り、`dbt/scripts/prepare.py` が `ingestion.tables.division` に入れる。組版の設定（`layout.json`）には置かない（冊ごとの事実で、組版の規則ではないため）。
- intermediate（`int_fiscal__settlement_expenditure_nodes`）は、所属を持つ表どうしが同じ `node_id` を持つとき、金額を**足して**1つのノードにする。2表以上を足した金額は1つの印字ではないので、金額の原典の位置（`amount_source_*`）を NULL にする。ノードの原典の位置（`origin_id`・`source_page`・`source_x0` 等）は、印字の1つ（原典・頁・位置の順で最初のもの）を代表として残す。どの冊にも印字が無い節は足さない（全部の冊で印字があるときだけ和を持つ）。
- 所属を持たない表（会計全体を印字する表）が同じノードを持つときは、その表の金額がノードを代表し、所属の表の和がそれに一致することを検査する（`tests/fiscal_rows_contract.sql` の `cross_table_subject_disagreement`）。所属を持たない表どうしは従来どおり金額が一致しなければ止める。
- 同じ会計で同じ所属の表が2つあれば、二重に数えるので止める（`duplicated_division`）。
- 木の検査（`tests/fiscal_tree_balances.sql`）は、所属の表を**表ごとに**当てる（その局の分の中で親＝子の和）。足した木は、所属を持たない表が代表するノードだけで当てる。局の冊の中の不整合は、取り込みと同じ `source_inconsistencies` の宣言で通す。
- 会計の合計の検査（`tests/fiscal_account_totals.sql`）では、所属の表が目を立てずに印字した項（神戸市 福祉局の冊の2款1項「総務費」170,000円）を、目の段ではその項の額として数える。局の分では目が無いので、足した木の目の和にはその局の分が入らないため。
- marts・API の列は変えない。所属は識別（`node_id`）に入れない。

## 検討した案

| 案 | 利点 | 採否 |
| --- | --- | --- |
| A. 所属を表の事実として宣言し、dbt で足す（採用） | marts・API・他団体の識別を変えない。印字はそのまま取り込める。足し合わせの正しさを決算書の款・項と照合できる | 足したノードの金額は1つの印字ではなく、原典の位置は代表になる |
| B. 所属を財政明細の追加区分として識別（`node_id`）に入れる | 局の分のまま配れる | 他団体と同じ物差しで目を比べるには集計が要り、marts・API・MCP に列が要る。後から A の上に足せる |
| C. 局を別の会計として取り込む | 既存の仕組みのまま通る | 会計の意味（一般会計・特別会計）を壊し、会計の合計が原典の決算書と合わなくなる |
| D. 全市一括の事項別明細書を待つ・請求する | 1冊で済む | 市HPに無く、いつ得られるか分からない |

## Consequences

- 所属を持たない表と所属の表が混ざらない限り、既存の団体の結果は変わらない（`division` が無い表は従来の規則のまま）。
- 足したノードの `amount_source_*` は NULL になる。原典で確かめるには、同じ款・項・目・節を各冊で引く。
- 局の冊が市全体を覆うことは、選定のときに決算書（決算第1〜12号）の款・会計の合計との一致で確かめる。所属を持たない決算書の表を一緒に取り込めば、dbt の検査が同じ一致を毎回確かめる。
- 所属ごとの金額は intermediate の手前（`int_fiscal__settlement_expenditure_rows`）に残る。B に進むときはそこから作る。
