# ADR 0034: Power BI の公開レポートでだけ出た評価資料は、レポートの API から取った表の CSV を出典にする

状態: 採用（2026-10-23）。八王子市の2024・2025年度で実装し、確かめた。[評価の検索の設計](../prd/evaluation-search/dd.md)の出典の保存・索引の登録・catalog・検索の操作を、PDF に加えて CSV の出典に広げる。[ADR 0031](0031-evaluation-text-items-for-unreadable-pdfs.md) の文字の item（`.md`）を前提とする。

八王子市は2024年度の事業の評価（令和7年度評価）から、事務事業評価を Microsoft Power BI の公開レポート（「Web に公開」）でだけ出している。PDF も CSV も無く、2024・2025年度は見送り（`selected_candidate_id: null`）になっていた。レポートにエクスポートのボタンは無い。ただし表示の元になる表は、レポートの頁が自分で使う公開 API から読める。

- `GET <cluster>/public/reports/<resource key>/modelsAndExploration`: データモデルの id と、頁・visual の一覧
- `POST <cluster>/public/reports/conceptualschema`: 表と列（列と measure の区別を持つ）
- `POST <cluster>/public/reports/querydata?synchronous=true`: 表の行（DSR という圧縮した形で返る）

`r` の値は base64 の JSON で、`k` が resource key、`t` が tenant である。cluster は固定せず、頁の HTML に埋め込まれた割り当て（`FixedClusterUri`）から頁の script と同じ規則（`-redirect`・`global-` を外して `-api` を足す）で決める。認証は resource key の header だけで、ログインは要らない。

2025年度のレポートの表「01 メイン（済）」は、事業ごとに事業目的・目標・課題・実績・評価・方向性の列を持ち、画面の総事業数（568）と行数が一致する。評価資料として足りる内容がある。

## 決定

- 出典は、公開レポートの API から取った表の CSV のスナップショットにする。市が公開したファイルではなく、風土記がレポートに問い合わせた結果である。選定の `reason` と検索の結果（`origin_format: csv` の注記）にこのことを書く。
- 選定のファイルに `format: csv` の形を足す。`download_url` はレポートの URL、`sha256` は取った CSV のバイト列のもの、`acquisition` に取得の宣言（`type: powerbi`・表の名前・列の一覧・並びの列）を持つ。列は measure を除く列から選んで列挙して固定する。並びの列は行を一意に決め、決まらなければ取得を止める（問い合わせは同じ値の行を1行にまとめて返すため）。PDF の形は変えない。
- 取得は `pipeline/source_selection/powerbi.ts` が行う。DSR の復元（直前の行と同じ列の `R`、null の列の `Ø`、値の辞書）は自前で書く。bitmask は列が32を超えるので BigInt で読む。結果が途中で終わっているときは行数が足りないまま使わず止める。CSV は UTF-8・LF・ヘッダ行あり・RFC 4180 で、同じデータからは同じバイト列になる。User-Agent は風土記と名乗る。
- 保存は `archive.ts` が、ダウンロードの代わりに取得で作ったバイト列を使う。sha256 の照合と key（`evaluation-settlement.csv`）は PDF と同じ流れにする。
- 索引は、データ行1行を1つの `.md` の item にする（key `<sha256>_p<行番号4桁>.md`、metadata の `page` は1始まりのデータ行の番号）。本文は「列名: 値」を列の順に行ごとに並べ、空の値は省く。登録の形は出典の形で決まり、`text_origins` の宣言は要らない。CSV は OCR を使わないので、OCR なしのインスタンスにだけ載せる。
- catalog の各出典に出典の形（`origin_format`）を持たせる。`csv` のときだけ書き、無ければ PDF とする（既存の出典の行を書き換えない）。検索の結果も同じで、CSV の候補だけ `origin_format: csv` を返し、`page` は取った表のデータ行の番号、`url` と `page_url` は公開レポートの URL（頁の指定は付けない）にする。PDF の候補の値と形は変えない。

## 検討した案

| 案 | 利点 | 採否 |
| --- | --- | --- |
| A. レポートの API から取った表を CSV にする（採用） | 全事業の本文を欠けなく、列の対応を保って取れる。同じ問い合わせから同じバイト列になり、画面の件数と突き合わせられる。PDF を作る工程が無い | 公開 API の形（DSR）に依存する。市のファイルではない |
| B. ブラウザで事業ごとのシートを開き、PDF に印刷する | 市が見せているままの見た目で残る。既存の PDF の流れに乗る | 事業が500超あり、事業ごとに画面を操作するので遅く壊れやすい。印刷の版面は画面の大きさに依存し、同じ入力から同じ PDF にならない。文字が長い欄は切れる |
| C. 見送りのままにする | 何もしなくてよい | 八王子市の2024・2025年度は引けないまま |

## Consequences

- 八王子市の2024・2025年度を収録できる。評価の欄（目標・課題・実績・評価・方向性）が事業ごとに1行で入り、検索の候補の1行が1事業に対応する。
- 出典は市のファイルではない。利用者が確かめる先は公開レポートの画面で、頁を指せない。検索の結果の注記と説明に書き、`page` は風土記が取った表の行の番号であって画面の番号ではないと明記する。
- 同じ問い合わせでも、市がレポートを差し替えると sha256 が変わる。保存した CSV は R2 に残るので、索引は保存したバイト列から作り直せる。差し替え後は取り直して選定を更新し、新しい sha256 を別の出典として登録する。
- 列名は年度で変わる（2025年度は「令和７年度評価」、2024年度は「令和６年度評価」で、2024年度に「取組区分」は無い）。取得は列を宣言した名前で探し、無ければ止める。年度ごとに列の宣言を持つ。
- 共同所管の事業は、レポートの表で所管の課ごとに複数の行になる。2025年度は部・課の列を除いて担当部課（所管を全部含む）だけを残して事業ごとに1行にした。2024年度は担当部課自体が行ごとに違う2事業があり、行を担当部課まで広げた（事業は560、行は562）。
- 公開 API は公式に文書化されたものではなく、レポートの頁の実装に依存する。形が変わったときは復元の検査（件数・列の存在・結果の完全さ）で止まり、気づかないまま欠けた表を保存しない。
- 動画や画像のような表以外の visual（指標・経済性などの別の表）は今回は入れない。必要になれば、同じ取得の宣言で表を足せる。
