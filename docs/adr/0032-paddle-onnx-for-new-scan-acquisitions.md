# ADR 0032: 新しい scan PDF の取得は Paddle small（ONNX Runtime）を既定にし、既存の冊は Vision のまま残す

状態: 採用（2026-10-20）。[ADR 0018](0018-paddle-small-for-scan-pdf.md) と [ADR 0019](0019-freeze-scan-ocr-observations.md) の 2026-10-11 改訂（既定エンジンを Apple Vision にする）を置き換える。ADR 0019 の「変換器の外で一度だけ OCR し、観測を固定して補助入力にする」方針と、`_vlm_identity()` に結び付いた VLM の答えの固定は変えない。[ADR 0017](0017-vision-for-coordinate-preserving-ocr.md) は比較の記録として残る。

新しい取得依頼（`ocr_inputs[].request.engine`）は `paddle` と書く。PaddleOCR PP-OCRv6 small を ONNX Runtime の CPU（intra_op 4）で動かし、頁を縦2分割（重なり60px）して分割片ごとに検出の長辺上限1920で読む。描画は pypdfium2 の300dpiである。管理 JSON に `engine: "vision"` で書かれた既存の依頼は、そのまま Apple Vision で取得し、観測も動かさない。

## Vision を既定にした前提が崩れた

Vision を既定にしたのは、実スキャンの金額で Paddle small より読めたからだった。ただし比較に使った Paddle は頁全体を一度に読む設定で、右罫線に接した桁や縮小による取りこぼしが多かった。頁を縦に分けて検出すると、この差は縮まる。132055 の 269 セル（読めた・誤り・読めなかった、の順）では、Vision の頁全体読みが 229/4/36、Vision の固定観測が 265/4/0、Paddle が 265/4/0 だった。固定観測は取得後に墨チェックと VLM で補った結果で、Paddle も同じ数になった。

縦に分ける効果は大きい。131181 荒川区の 1646 セルは、頁全体読みが 1595/5/46、縦 4 分割が 1640/6/0。132152 国立市の 2245 セルは、頁全体読みが 2161/20/64、縦 4 分割が 2233/8/4 だった。訂正前の Vision は数百件の金額の誤りを出したのに対し、縦 4 分割の Paddle は 6〜12 件にとどまる。残る主な誤りは、右罫線に接した最後の桁の落ちである。これは木の検査（階層別合計）が合わないセルとして止まるので、誤りが表に入ることはない。

Vision の弱みは精度だけでなく動く場所にもある。macOS でしか動かず、OS の更新で出力が変わりうる。ONNX Runtime の CPU 実行なら、同じ重みと同じ画素でどの環境でも同じ読みになる見込みが立つ。

## ONNX Runtime で動かす

Paddle の公式配布には、変換済みの ONNX（`PP-OCRv6_small_det_onnx_infer`・`PP-OCRv6_small_rec_onnx_infer`）がある。PaddleOCR 3.7.0 の `PaddleOCR(engine="onnxruntime")` が直接読む。2026-10-20 の実測で、宣言済みの Paddle 重みを Paddle 本体で動かした結果と ONNX Runtime の結果は、933 観測で文字・枠とも完全に一致した（枠差 0px）。10 頁の所要は、ONNX Runtime（intra_op 4 スレッド）が 28.8 秒、Paddle 本体（10 スレッド）が 84.7 秒。ONNX Runtime は 2〜6 スレッドで同等で、8 以上で遅くなる。既定のスレッド数は 4 にする。

ONNX の重みは `paddle_ocr_models.json` に、ファイル名・バイト数・sha256 付きで固定する。ここで Paddle 本体の重みも `runtime` で区別した。照合は従来どおりで、自動ダウンロードはせず、不足と不一致は停止する。`inference.yml` の sha256 は、宣言済みの Paddle 版と ONNX 版で一致した。

ONNX Runtime での実行は paddlepaddle を import しない。そこで `paddle-ocr` extra から paddlepaddle を外して `onnxruntime==1.31.0` を足し、paddlepaddle は `runtime="paddle"` のためだけの extra `paddle-native` に移した。

## 検出の既定は縦2分割・上限1920にする

検出の解像度の上限（`detection_limit_side_len`）と頁の縦分割数（`page_strips`、隣との重なり `strip_overlap_px`）は `PaddleConfig` の項目で、依頼の `config` で変えられる。上限は分割片ごとに効く。2026-10-20 の比較（132152 国立市の2245セル、131181 荒川区の1646セル。数字は読めた/誤り/読めなかった）で、既定を次にした。

| 設定（132152） | 結果 |
| --- | --- |
| 頁全体・1280（桁落ち17） | 2161/20/64 |
| 縦4分割・1280 | 2234/8/3 |
| 縦2分割・1920（採用） | 全件一致。桁落ち・連結は0 |
| 頁全体・2560（131181） | 連結6、RSS 2.3GB |
| 頁全体・3520 | RSS 2.8GB |

採用した設定は、132152・131181とも全件一致で、桁落ち・連結が0、木の検査で新たに合わなくなった親が0だった。頁あたり5.6〜7.6秒、RSSは1.3〜1.7GBである。検出箱の拡張（unclip の引き上げ）、箱の右への拡張、罫線際のROI再読は、いずれも結果を悪くした。

重なりの帯で同じ文字が二重に観測されることは、評価で確認した（縦4分割で同じ金額の重複が25件）。変換器に二重の観測が渡らないよう、取得時に除く。分割片をまたいで箱が重なる（小さい方の箱の半分以上）行のうち、同じ文字なら分割片の端から遠い側の読みを残し、片方がもう片方に含まれる短い読み（切れた読み）なら短い方を落とす。欄をまたぐ行は継ぎ目で2つに切れて読まれる（一方の箱が自分の帯の右端で、他方が次の帯の左端で終わる・始まる、同じ行の2つ）。切れた読みは信用せず、両方を落とす。残った墨は墨チェックで拾い、罫線を消した再読の範囲（`ink_areas`）にまとめる。範囲は、同じ行（墨の縦の中央の差が4pt未満）の墨を、横の隙間が14pt未満で、2つの墨の間にある縦の列罫がその行の高さを覆うときだけ2つの範囲に分け、それ以外は1つにする（隙間13ptで1つ・14ptで2つを、合成の墨でテストした）。1つのセルの中の行は、継ぎ目をまたいでいても1つの範囲になり、セルの罫の内側に収まる。列罫が行の高さを覆わない結合セルの見出しも1つの範囲になる。2つの墨の間に列罫が行の高さで通っていれば別のセルとして2つの範囲になり、字間が14pt以上空いた行も2つになる。範囲が1つでも、その読みが採られるかどうかは別で、採られなければ未読（`unread_ink`）のまま残る。

残る危険は名称である。再読の読みが採られない、または一部だけ採られると、名称は欠けるか途中で切れる。金額は木の検査で止まるが、名称には検査が無く、止まらない。132152/2025 で折り返した「使用料及び賃借料」12件が、墨の再読で読めず、名称が空か「使用料及び賃借」で終わったまま木の検査を通った（名称は宣言で直した）。継ぎ目で落ちた行がこうなるかは、132152/2025 では落ちた観測が0件で、確かめていない。132152/2025 の42頁では、保存済みの観測にこの規則を当てても落ちる観測が0件で、保存済みの観測と表は変わらない。列罫が継ぎ目付近を通って再読の範囲が2つに割れる場合は、この PR では規則を変えない（変えると全表の refresh が要る）。継ぎ目で落とした組の再読が1つの範囲にならない、または採った読みがその組の箱の和を覆わないときは、その和を未読として記録し、黙って一部を採らない。落とした組の箱の和は試行の `seam_dropped_boxes_px` に残し（組が無い試行には書かない。観測のバイトは変わらない）、墨の再読の後に `settle_seams`（`scan_ocr.py`）が確かめる。組の箱の和の左右の端を2pt以内で覆う読みが1つあれば採る。無ければ、再読と VLM が組の箱の中で採った読みを外し、箱の和を `unread_ink` と `unread_seams` に足す（頁全体の読みは触らない）。`unread_seams` の箱は、変換（`declared_unread`）が列を問わず `unowned` に積み、変換を止める。名称の列でも止めるのは、名称には木の検査が無く、名前が欠けた行が配布されるより、止まって宣言か取り直しで直すほうがよいと判断したためである（金額列の `unread_ink` は従来どおり金額列の帯に入るときだけ止める）。箱と縦に重なっても縦の中央を含まない読みは外さない。131181/2024 の取り直しでは、縦2分割の継ぎ目で落ちた組は0件だった（全67頁で `duplicate_observation_ids` が空）ので、この規則は単体のテストで確かめた。

残すと変換が重なる2箱を連結し、印字 `1,234,567` が `12,344,567`、名称が `負担金、補助及び及び交付金` のように静かに汚れる。そのほかの食い違いは両方残し、文字を選ばない。落とした行はその単語と一緒に外し、観測IDは試行の `duplicate_observation_ids` に残す。

### 比較の数え方を直した

最初の比較は、セルの期待値と観測の数字だけを比べ、非数字を捨てていた。そのため、単独の0の上の単位表示「円」が同じ箱に入った `円0` も一致に数えていた。空白以外の全文で数え直すと、最良設定は 132152 が全文一致2196/2245、131181 が1533/1646である。残りは、132152 の `円0` 28件と注記金額に「円」が付いた形21件、131181 の注記金額に注記の文言や「円」が付いた形113件で、131181 には `円0` 型がない。注記を含む形は注記の組み立てが分けるので失敗ではないが、`円0` は読み違いである。

### 比較に使った参照表と検査の限界

比較の正解を、比べるエンジンの出力から作らない。2026-10-19〜20 の Paddle と Vision の比較では repo に正解データが残っておらず、採用済みの取り込み表（Vision の固定観測から作った表）を参照表に使った。これは独立した正解ではない。名称は同じ読み同士の比較になるので一致数は精度の指標にならない（Vision 固定観測どうしで 128/128）。金額は木の検査を通っていることを根拠にした。参照表の対象頁・表と金額の分母は固定しておらず、独立した正解での再測定はしていない。

木の検査は、親と子が同じ桁落ちをすると通る（荒川区 2024 の型1、`12,828,111` を `12,828` と読む形）。照合の完全一致も、正解側の誤りを検出しない（`04,069,726,000` は誤った正解に偶然一致した）。名称の誤りは木の検査では止まらない。金額の正しさを言うときは、出典の画像と上位の行で検算した範囲と、一致数の分母がどの読みに由来するかを添える。

## 描画は pypdfium2 の300dpiにする

描画は pypdfium2（lock の版）の300dpiを既定にする。描画は読みの結果を左右する。同じ設定で132152は、poppler が2232/13/0で、「円」と0が `円〇` に連結した。CoreGraphics は最良設定で測っていない。CoreGraphics と poppler は `pdf_renderer` で明示すれば使える。描画方法とdpiは観測の `render` に、版は実行記録の `renderer` に残す。

## 墨チェックと VLM は Paddle の取得でも最後の段にする

墨チェックは残す。単独の0などの未検出は全件検知した（132152 A 64/64、B 3/3、131181 A 3/3）。桁落ち・連結は墨では検知できない（0/17）が、木の検査と金額の形の検査で止まる。最良設定では墨の領域は空振りのみで（132152で69件、131181で7件。見出しの字間の空いた漢字や「円」のラベルなど）、害は読み直しの時間だけである。

取得は、Paddle の頁読み、Paddle の ROI 再読、数字だけの認識（`_read_zeros`）、VLM の順に補う。ROI 再読は、罫線を白く消した頁から見落とした墨の範囲を切り出し、64px まで拡大して読む。Vision で使っていた白い余白は付けない。VLM は木の検査が合わないセルだけを対象に、期待値を渡さず 1 回だけ読ませて観測に固定する。採るかどうかは木の検査が決め、VLM の答えが合計に合うことを読みの正しさの根拠にはしない。

`column_tiles`（罫線で区切った列を小さく分ける読み）は Vision の取りこぼしへの対処なので、Paddle の依頼では使えない。

## 既存の冊は Vision のまま残す

（この節と下の「結果」の Vision に関する記述は導入時の判断である。その後、全冊を Paddle で取り直し、Vision の処理は消した。末尾の節を参照。）

観測 ID は、Paddle が `p{n}:{region}:a{k}:result{m}:r{i}`、Vision が `p{n}:{region}:r{i}` で、形が違う。`AmountRule` などの固定観測と訂正の宣言は Vision の ID に結び付くので、既存の冊を Paddle に切り替えると訂正がすべて無効になる。切り替えの利益は、訂正済みの冊では小さい。そのため既存の依頼は `engine: "vision"` のまま触らない。固定済みの VLM の答えを無効にしないよう、`_vlm_identity()` の値も変えない。

## 132152/2025 の試しの取り直し

2026-10-21、132152/2025 の42頁を Paddle の新しい既定で取得し（`vlm_fallback: false`）、旧宣言（`amount_corrections` 489件）を外して変換し、採用済みの表と比べた。取得と変換はローカルで行い、仕上がった後に `convert --remote` で R2 へ保存した（末尾の「保存の実態」）。3つの問題を直した。

1. **変換が Vision の単語を前提にしていた。** `scan.py` は観測の単語の子を使う。Vision の子は1語だが、Paddle の子は1文字や数字の断片（`4` `,` `505`）で、金額が `4,505,294,000` → `4,505` と欠けた。Paddle の行は、その行の文字から罫線で分ける。直す前は款の和と歳出合計が合わず変換が止まった。
2. **エンジンを頁ごとに作り直すとメモリが戻らない。** 閉じても ONNX Runtime のメモリが残り、4頁で RSS が1.4GBから2.9GBに増え、再読用のエンジンと合わせて42頁の最大が3.5GBになった。1設定1エンジンに共有すると、1.5〜1.7GBで頭打ちになり、42頁は433秒から310秒になった。観測のSHAは42頁とも変わらない。
3. **`円0`。** 各セルの右上に小さく印字された「円」と、その下の単独の0を、検出器が縦長の1つの箱にして `円0` と読む（93件）。円の単語箱の下端で分け、下の部分を認識器だけで読み直す（領域 `unit-<n>`）。分けた読みが金額の形でなければ、元の箱を残す。

直した後は、採用済みの表と比べて、ノード1069（採用済みは1068）、金額の同一6356、値が違うもの5、木の検査は一致1121・不一致4だった。値の違いのうち2つは Paddle の誤りである（頁53の `84,444,000` を `8,444,000`、頁72の `1,239,443,000` を `01,239,443,000`）。前者は木の検査で止まる。残りの3つは注記の位置のずれによる比較の見かけで、金額の集合は一致する。名称は、「負担金、補助及び交付金」などの読点を Paddle が拾う（85件）。逆に Paddle だけが誤るのは異体字（徵・產・涉・查など）と、2行目の「料」を落とす折り返しの名称（8件）である。

### 宣言と仕上がり

VLM を既定のまま（`vlm_fallback` なし）で取ると、12領域が埋まったが、どれも行全体の「使用料及び賃借料」で、折り返しの2行目の「料」だけではなかった。名称が重複し、木の検査の不一致が4件から73件に増えた。そこで取得は `vlm_fallback: false` にし、VLM は木の検査が合わないセルだけに使う。頁全体の読みの観測 ID は、VLM の有無で42頁とも変わらない。

折り返した名称の2行目の単独の「料」を、数字の墨と同じく認識器だけで読む案も試した。取りこぼした墨のうち数字以外の27件を、認識器だけで確信度つきで読んだところ、「料」は独立した1字の墨ではなかった。名称行と連なった幅約45pt・高さ13ptの墨で、認識器は1行目だけを読んだ。見出しの未読17件は「び」の点の断片で、確信度0.999で「び」と読み、拾うと見出しに余計な字が足される。採用せず、node 結びの名称訂正にした。

宣言の数は、採用済みの表が `amount_corrections` 489件だったのに対し、Paddle では `amount_corrections` 2件、`name_corrections` 16件（折り返した「使用料及び賃借料」12件、小さい ィ・ょ の3件、頁48の1件）、`dropped_readings` 5件（頁48）と、共通の見出し訂正2件（`scan_header_corrections.json` は37件から39件）、共通の字形の対応表19字（`ocr_variant_chars.json`）である。字形の対応表は engine paddle の観測だけに当たり、当たった観測は変換の記録に残る（132152 では 增→増 84件、查→査 12件、產→産 10件、徵→徴 6件、涉→渉 2件、·→・ 4件）。

この宣言を使った変換は、木の検査が1126件すべて一致し、款の和は歳出合計に一致した。採用済みの表との差は、金額が47セルの増加（採用表にない印字された0）、名称144件の差は表記の差または採用表側の誤りである（読点を拾う85件、注記の文言の誤読38件、採用表側の誤字21件）。注記金額98件は集合が一致する。

## 結果

- 新しい取得は `engine: "paddle"` と書く。`scan_ocr` の `backend` 既定は Paddle になった。`config` に `VisionConfig` を渡す呼び出しは、従来どおり Vision を選ぶ。
- Paddle の観測は native の出力（`attempts[].native`）を持たない。観測は `regions` にあり、native は大きく、同じ内容の重複になるためである。試行の設定・拡大条件・画素の sha256 は残す。
- `scan_ocr.py`・`paddle_ocr.py`・`paddle_ocr_models.json` の変更で、全保存済み表の `input_fingerprint` が古くなる（[ADR 0027](0027-refresh-fingerprints-by-table-content.md)）。`ingestion:refresh` で中身が同じことを確かめて指紋だけを書き換える。表の中身は、取り直した 2 冊（132152/2025 と 131181/2024）を除いて変わらない。132152/2025 は下の取り直しで中身が変わり、131181/2024 は観測を Paddle で取り直したので表が別物になった（nodes 1571 行、amounts 8337 → 8345 行。「131181/2024 の取り直し」の節）。Vision のままの冊は、全冊の `ingestion:refresh --remote` で内容が同じ（same）と確かめて指紋だけを更新した。
- ROI 再読が Paddle で十分に動くかは、実際の頁で測る。最良設定で桁落ちは見つかっていないが、起きれば木の検査で止まる。

## 描画の箱・時間の上限・Vision の数字の再読

- **CropBox と MediaBox。** Paddle の観測の座標は pypdfium2（CropBox）で、規則線と墨の再読の切り出しは poppler（MediaBox）の画像である。両者が違う頁（切り取った A3 の見開き）では別の墨を読むので、墨の再読の前に `require_one_page_box` で確かめ、違えば取得を止める。回転した頁は止めない。PDFium の `get_size` は `/Rotate` 90/270 で幅と高さを入れ替え、`pdftoppm` も `/Rotate` を適用するので、CropBox が MediaBox と同じなら表示寸法が同じになる。実際に 281000 の `/Rotate 90` の頁（物理23頁・75頁）で2つの画像は同じ大きさ・同じ位置（ずれ0px、直立の頁と同じ重なり）だった。132152 の出典は157頁すべてで CropBox と MediaBox が同じで回転も無く、保存済みの観測は変わらない。

## 132080/2024 の scan 5頁（146・147・382・383・413）を Paddle にする

2026-10-23、最後に残っていた Vision の依頼（`general-ocr-columns-1`、`column_tiles`）を `engine: "paddle"`（既定の設定、`{"pages":[146,147,382,383,413],"vlm_fallback":false}`）にして取り直した。文字層の無い5頁だけを読み、残りは文字層で読む文書である。取得は 75 秒、観測は 1,880,386 bytes。

- **結果。** 款の和 109,405,332,961 ＝ 印字の歳出合計、未読金額 0、親不明 0、木の検査は全件一致、網羅の検査は通った（Jev の聞き直しは新規0件）。採用済み（Vision）の表との金額差は 0（金額の多重集合が全頁で一致。印字された 0 も Paddle が読み、宣言は不要になった）。行数は nodes 8,155・amounts 15,428 で変わらない。
- **宣言（旧→新）。** 金額の訂正3・重なる読みの除去2・名称4・読み落とした0の補い2（箱7）の計11件を外し、名称の訂正3件にした（`amount_*`・`dropped_readings` は0）。3件は字の誤読（`コミュニテイ`→ィ、`センタ一`→ー、`O諸経費`→○）。組版設定に `note_kinds` を1つ足した（頁413 の折り返した注記「体育施設費・工事請負費から報償費へ／流用」。2行目の「流用」が別の読みになり、注記と読めず備考の項目になって木が 1,000,000 ずれたため）。
- **名称の差。** 採用表との差は37件。Paddle が印字に近い: `備品入費`→`備品購入費`・`一般需用費`・`報償費`・`検査`・`調査`・`負担金,補助及び交付金`（読点を保持。他頁と同じ）・`オリンピック・パラリンピック`・`指導者・協力者謝礼`・`部活動地域連携・地域移行関連`、および ○ の段の印を名称から外した16件（旧は ○ を ・ と読んで名称に残していた）。差が残るのは、(協働推進課)・(スポーツ振興課)・(社会教育課) の括弧書きが直前の項目の名称に付く3件（文字層の頁と同じ扱い。旧は読まずに落としていた）と、注記の名称が「…報償費へ」で止まる1件（種類は流用として読まれ、名称には「流用」が付かない）。
- **節の番号が名称に結ばれる（12件）は、混在文書の学習の出どころの誤りだった。** `tree.build` は 款・項・目と節の番号の欄の位置（`code_margins`）、番号の右端（`number_edges`）、行の幅（`line_limits`）を、文字層の頁だけから学び、OCR の頁にも当てていた。132080 の節の番号の欄の左端は、文字層の頁が {426, 430, 442}（±1）で、OCR の頁は 2 桁の番号が 423 前後（`14` は 423.4）に出る。許容の ±1 を割った `14`・`18` などが「数字で始まる名称」と読まれた。OCR の頁を含む文書では、OCR の頁を自分たちの頁から学んで読むようにした（`scanned`。文字層だけの文書と全頁 OCR の文書は従来どおり）。`corrected_code` の訂正12件は外し、名称の訂正は3件になった。金額・款の和・名称の差は変わらない。
- **頁の左上の款・項の番号の網羅（`coverage_checks.py`）。** 款・項・目の番号を Paddle が1つの語（`103510`）に読み、罫線で切った語が隙間なく接する。網羅の検査は接する語を1つの番号の字の破片と見て、2桁の番号を単独の候補から外していた。2桁以上の語は番号そのものなので、単独の候補にも残す（候補が増えるだけで、通っていた表は落ちない）。検査のコードで指紋の対象外。
- **検討して外した。** `detection_limit_side_len: 2560` は木の不一致が1件から12件に増えたため使わない。

## 全冊を Paddle へ移した後、Vision の処理を消した

2026-10-23、管理 JSON の `ocr_inputs[].request.engine` がすべて `paddle` になったので、Vision の処理を消した（`vision_ocr.py`・`vision_ocr.swift`・語彙 `ocr_vocabulary.json`、`scan_ocr` の `backend="vision"`・`column_tiles`、manifest schema の `engine: "vision"`・`column_tiles`）。測定用の plans のうち Vision の依頼だけで書かれた19件も外した（git の履歴に残る）。Vision の経緯と比較は ADR 0017・0018・0019 と `docs/vision-ocr-evaluation.md` に歴史として残す。
