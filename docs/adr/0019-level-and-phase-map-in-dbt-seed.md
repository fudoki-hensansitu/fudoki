# ADR 0019: 段の名前と金額の段階への対応は dbt の seed に置き、取り込みには原典の事実だけを求める

状態: 提案（2026-10-11）

取り込みのノードの表と金額の表（[ADR 0020](0020-ingestion-outputs-node-tables.md)）を、提供用データの段の名前（款・項・目・事業・節・細目）と金額の段階（支出済額など）へ対応づける宣言は、dbt の seed に置く。取り込み側（B）には、その宣言を原典に照らして検査できる事実（ノードの親子と分解の軸、原典に印字された段の見出し・番号・名称、金額欄の原典の見出しと単位、原典の頁）だけを求める。staging の前の入力準備が宣言と取り込みの表を照合し、宣言にない見出しや、宣言が当たらないノード・金額があれば構築を止める。

## 理由

対応づけは風土記の解釈であり、原典で確認した事実とは性質が違う。たとえば新宿区の決算書の目の欄にある「支出済額」を、提供用データの支出済額として採るのは風土記の判断である。この判断を取り込みに置くと、[保存設計](../prd/ingestion-storage/design-doc.md)が取り込みから除いた「共通分類への対応」が入り込み、判断を直すたびに取り込みの fingerprint と R2 の表が変わる。

一方で、宣言だけを根拠にすると、宣言どうしが一致しているだけで原典との対応は確かめられない。そのため、照合に使う事実を取り込みの責務として要求する。

宣言を seed にできるのは、取り込みの出力がノードの表と金額の表に揃い、staging が書式ごとの SQL を持たなくなるためである。宣言は書式ごとの列名ではなく、見出しの値への対応になり、構築中の結合で引ける。

## Considered Options

- **取り込みに段の名前・金額の段階を持たせる**: dbt の宣言は不要になる。判断の修正が取り込みの再実行を伴い、保存設計の境界にも反するため採用しない。
- **staging の yml（列の `meta`）に書式ごとの対応を書く**: 横持ちの表のように列名が書式ごとに違う場合には向く。ノードの表では列が共通で、対応は見出しの値に対して決まるため、表として検査できる seed にする。

## Consequences

- 団体・表を足すたびに seed に行が増える。行は（団体・表・軸・深さ）から段の名前への対応と、（団体・表・軸・深さ・金額の見出し）から金額の段階への対応で、根拠を書く。
- 金額欄に原典の見出しがない場合（説明欄の金額など）は、子の和が親の支出済額と一致することを根拠として seed に書く。
- 設計の全体は [dbt モデルの設計](../prd/fiscal-dbt-models/design-doc.md) を参照する。
