# 風土記 — マーケティング計画 v1

作成 2026-11-10。期間は 2026-11 〜 2027-10。marketing-plan skill（wwwyo/marketingskills）の 13 節の型に沿い、課金する SaaS 向けの項目（ARR・CAC・資金調達の段階）は風土記に合わせて読み替えた。位置づけ・相手・言葉の決まりは [.agents/product-marketing.md](../../.agents/product-marketing.md)。

## 1. 要約

**3つの賭け**
1. **自治体の頁を検索の入口にする。** 「◯◯区 予算」「◯◯市 決算書」で公式サイトの次に出る。全自治体で予算と決算を並べる前提で、title・説明文・年度ごとの頁を仕込む
2. **AI から引かれる。** ChatGPT・Claude に「◯◯市の予算」を聞いたとき、風土記が出典として使われる・勧められる状態にする
3. **よく使う人を季節で掴む。** 議員・記者は予算審査（一般に2〜3月）と決算審査（一般に9〜10月）に集中して調べる。その時期に合わせて使い方を届ける

**最初の90日（〜2027-02 初め）の優先**
- 自治体の頁の SEO の土台（title・説明文は PR #457、年度ごとの頁、OG 画像）
- 計測の型（週次レポート、目標の指標）
- 1〜2月の当初予算の発表に合わせた「今年新しく始まる事業」

**12か月後の姿:** 自治体の頁への検索流入が週ごとに積み上がり、議員・記者の中に「予算を調べるなら風土記」と使う人がいる。

## 2. 戦略の枠

**一文で:** 自治体が何にいくら使い、どう振り返ったかを、事業の単位まで出典つきで読める場所。

**取りにいく場所（カテゴリ）:** 「自治体の予算・決算を調べる場所」。新しいカテゴリを名乗らず、すでにある検索（自治体名＋予算・決算）に入る。

**相手:** 住民（特に引っ越し・子育ての節目）、議員・議会事務局、記者・研究者、開発者・AI 利用者。詳細は product-marketing の Personas。

**問題の大きさ×頻度（市場の質の門）**
| 相手 | 問題の大きさ | 頻度 | 打ち手への含意 |
| --- | --- | --- | --- |
| 住民 | 中（もやもやはあるが困ってはいない） | 低（年に数回、引っ越しや報道のとき） | 検索で出会い、一度で分かることが大事。戻ってくるのは期待しすぎない。こちらから届ける仕組み（SNS・動画）が要る |
| 議員・議会事務局 | 大（委員会の準備） | 季節で高い（予算・決算審査） | 季節に合わせて掴めば繰り返し使う。声もかけてよい |
| 記者 | 中〜大（記事の裏取り） | 中（予算発表・不祥事のとき） | 出典まで辿れることが決め手 |
| 開発者 | 中 | 中 | 一度 MCP を入れれば使い続ける |

住民は「大きくない・まれ」の象限で、検索だけでは戻ってこない。だから戻ってくる仕組みは議員・記者・開発者で先に作り、住民は検索と SNS で広く出会う形にする。

**ビジネスの筋:** 風土記は無料で、広告も出さない。マーケの目的は売上ではなく「使われて、データの価値が認められる」こと。API・MCP の商用利用は問い合わせ制（未定）。

**守る線（変えない）:** 評価を書かない・順位付けや良し悪しの色を付けない。数字には出典。自治体には打診しない（議員にはこちらから声をかけてよい）。選挙は別サイト。

## 4. 集める（Acquisition）

**今:** 検索（自治体名＋決算書）からわずかに来る。ほかの流入はほぼ無い。

**計画**
- **SEO（主力）**: 自治体の頁を検索の入口にする。予算と決算の両方を並べる前提で title・説明文・構造化データを作る（#457）。次に、年度ごとの URL（`/tokyo/shinagawa/2025` など）にして過去の年度も検索に載せる。新しく始まる事業の頁、自治体ごとの OG 画像
- **自治体×年度の頁を型で作る（programmatic SEO）**: 自治体と年度の組み合わせで頁が増える。薄い頁にならないよう、その自治体・年度だけの中身（新規事業・大きい事業・前年との差）を必ず載せる
- **AI 検索**: AI に引用されやすい形（数字と出典を1か所にまとめる、llms.txt の要否を検討）にする。MCP の公開レジストリ掲載は後回し（2026-11-10 決定）
- **X（@fudokijp）**: 「◯◯区が今年新しく始める事業」を週2〜3回。出典つき。下書きは agent、投稿は yuito
- **技術記事**: 予算書 PDF を事業の単位まで構造化する仕組み、認証なしの公開 MCP の守り、Claude に風土記を入れて自分のまちの予算を聞く手順。被リンクと開発者への入口
- **コンテスト・コミュニティ**: アーバンデータチャレンジ2026（作品概要エントリー 11/15 23:59、本応募 12/27 締切。概要エントリーをしないと本応募できない）
- **見送る**: 広告（使わない。選挙前後は公選法の線もある）

**90日の動き:** #457 の merge → 年度ごとの URL → UDC の概要エントリー（11/15）→ OG 画像 → UDC 本応募（12/27）→ 1〜2月の「新規事業まとめ」→ 技術記事1本目

**12か月:** 収録の自治体が増えるほど頁が増えるので、SEO は収録と一緒に積み上がる。2〜3月と9〜10月に議員・記者向けの告知を山として置く。

**skill:** seo-audit・programmatic-seo・ai-seo・schema・site-architecture・social・content-strategy・directory-submissions（MCP 掲載を始めるとき）・launch

## 5. 初めて使う（Activation）

**「使えた」の定義:** 自治体の頁で、自分のまちの金額か新しく始まる事業を一つ読んだ。開発者は MCP を追加して一回答えが返った。

**計画**
- 検索から来た人が最初の画面で「何にいくら」と「今年新しく始まること」を読めるか確かめる（品川区は済み。予算の無い自治体でも同じ体験にする）
- 自分のまちが未収録のときの行き止まりをなくす（近いまち・収録予定を出す）
- ホームから自治体の頁へ進んだかを、頁ごとの表示数の比（自治体の頁 ÷ ホーム）で見る（人ごとの遷移は Cloudflare Web Analytics では取れない）
- MCP は「AI に貼り付けて接続する」文が入口。追加後の最初の質問の例を整える

**skill:** cro・onboarding・copywriting（コピーは yuito が「これで」と言うまで repo に入れない）

## 6. また来る（Retention）

住民に頻繁に来てもらうことは狙わない（頻度が低い問題なので）。狙うのは「季節が来たら思い出す」こと。

**計画**
- 議員・記者: 予算・決算の時期に「今年の分が入った」を知らせる。手段（X・RSS・ニュースレター）は未決定
- 住民: 「うちのまち」を選んだ人に、そのまちの新しい年度が入ったことを頁の上で知らせる
- 開発者: MCP を入れた人は会話の中で使い続ける。データの更新履歴（最近の更新）を見える場所に置く

**skill:** emails（ニュースレターをやると決めたら）・churn-prevention は使わない

## 7. 人に教える（Referral）

**計画**
- 頁を共有しやすくする: 自治体の頁・事業ごとに、開いたときにその数字が見える OG 画像。X やチャットに貼ったときに中身が伝わることが一番効く
- 議員・記者が記事や委員会資料に出典として書けるよう、引用の書き方（「風土記（fudoki.dev）、出典: ◯◯区決算書 143頁」）を docs に置く
- 開発者が作ったものを紹介する場所（docs の事例）

**skill:** referrals（仕組みとしての紹介制度は持たない）・social

## 8. お金（Revenue）

風土記の頁からは収益を取らない。マーケの指標にも売上を置かない。API・MCP の商用利用は問い合わせ制で、問い合わせが来たら記録する（プランと価格は未定）。議員・会派向けに「予算・決算委員会の調査を AI で行う仕組みづくり」の相談を受ける話は、別事業として扱う。

**skill:** pricing は使わない（決めるときに使う）

## 13. 計測・決めること

**北極星:** 自治体の頁を読んだ人の数。人数は直接は取れないので、Cloudflare Web Analytics の本番の訪問のうち自治体の頁に入った訪問を代わりに数える（同じ人の別の日の訪問も数え、サイトの中の移動は数えない）。週次で見る。

**先行指標**
- 集める: Search Console の表示・クリック・平均順位、自治体の頁の表示数
- 初めて使う: 自治体の頁の表示数 ÷ ホームの表示数（Cloudflare Web Analytics は人を追わずイベントも取れないので、頁ごとの表示数の比で代える）
- また来る: 参照元が無い（ブックマーク・直接入力）自治体の頁の訪問数。同じ人の再訪そのものは取らない
- 教える: X・外部サイトからの流入

**最初の3か月の目標（案）:** 自治体の頁の月間訪問数を今の10倍。基準の数字は週次レポートの初回（11/16）で固める。

**決めること（yuito）**
1. ニュースレター・RSS をやるか
2. 3か月の目標の数字（初回レポートのあと）
3. 比較の頁を作るか、作るなら評価に見えない並べ方

**決めたこと**
- X は @fudokijp がある（2026-11-10）
- 年度ごとの URL は、最新の年度を `/tokyo/shinagawa` のまま残し、過去の年度を `/tokyo/shinagawa/2024` のように1段下げる（2026-11-10、PRD なしで実装）
