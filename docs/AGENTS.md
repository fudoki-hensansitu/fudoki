# docs

設計・調査文書。判断の記録はコードと同じ寿命を持ち、git 管理する。

- `survey/`: データ源の実測・調査記録。主張には実測日を添え、参照するときは該当スクリプトを回して観測を取り直す（観測は commit しない）
- `prd/<topic>/prd.md` + `prd/<topic>/dd.md`: 要件と設計書は同じ topic に併置し、その topic の作業記録（移行・回顧・生成一覧）も同じ dir に置く。データ源の実測・調査は `survey/`
- `adr/`: 決定の記録。番号はファイル名の `NNNN` を一意にし、`bun run pipeline/verify/docs.ts` で重複を検出する。並行する PR が同じ番号を取ったら main 側は動かさず、後から入れた PR の番号を main が使った番号の次へずらし、H1 と全参照（doc・SQL・ADR 相互参照）を更新して検査を通す。
